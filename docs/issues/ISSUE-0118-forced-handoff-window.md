# ISSUE-0118：手动强制完整转写时可能超过目标模型的整个窗口

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 中 |
| 发现于 | [1.6 阶段 6](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

点击“强制 H2 重新交接”对应的接口可以启动新会话，发送一份估算超过模型整个窗口的转写。

## 复现步骤

1. 新建临时项目，用离线演示适配器完成第一次交接。
2. 在已接收的会话中记录一条较长的助手回复和大小为 2048 token 的窗口报告。
3. 从当前交接记录调用重新交接接口，读取新交接记录，核对模拟 Agent 收到的文本和启动次数。

## 影响

本次完整转写估算为 10671 token。真实服务可能拒收或裁剪；是否计费取决于服务。真实服务在本例未验证。

## 根因

强制 H2 直接选完整转写。已有预算分支处理自动选级以及探针失败后的修补，手动重开会话前没有处理完整转写大于整个窗口的情况。

## 处理方式

等待产品决定。A 在本次操作内显示所需与可用容量，保留当前会话，用户可更换大窗口模型。B 将用户主动点击强制 H2 视为同意尝试一次，交给目标服务处理。详见验收记录。

## 验证

离线定向两例。正常重开通过，原用户消息只有一条。超窗用例期望保持一个接收会话，实测已启动第二个，模拟 Agent 收到完整原文。整个过程没有真实模型请求。

## 时间线

- 2026-11-18 开启，等待用户决定超窗时手动重开的行为。
- 2026-11-18 关闭。按用户决定在启动目标前校验窗口。超窗时返回所需容量与可用容量，模拟接收端没有再次启动。见 [阶段 6 全量验收](../acceptance/step-1.6.md)。
