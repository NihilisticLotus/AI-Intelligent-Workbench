# ISSUE-0014：实时事件只靠动画帧合并，窗口被遮挡时审批卡片不出现

| 关闭 | |

## 现象

浏览器验收时，用 Claude Code 新建任务后，页面一直停在“运行中”，看不到工具调用和审批卡片；Gateway 的事件表里其实已经有 `approval.requested`，任务状态是“等待审批”。点 [允许] 之后服务端已经处理完（文件生成、任务变为“待验收”），页面仍然不变。刷新页面后内容才完整出现。

## 复现步骤

1. 让浏览器窗口被遮挡或最小化，但页面的 `document.visibilityState` 仍为 `visible`（开发预览面板里就是这种状态：`requestAnimationFrame` 的回调 1.5 秒内没有执行）。
2. 新建一个会产生事件的任务。

## 影响

用户看不到审批请求，任务会卡到审批超时自动暂停；手机和桌面软件的 WebView 在后台时也可能出现。

## 根因

`apps/web/src/state/app.ts` 的 `enqueueEvent` 在页面可见时只用 `requestAnimationFrame` 合并刷新。浏览器在窗口被遮挡时可能停发动画帧，但不把页面标为隐藏，于是事件一直留在队列里。

## 处理方式

动画帧和 100ms 的 `setTimeout` 同时安排，谁先到用谁（只执行一次）。已在工作区修复，尚未提交；提交后把状态改为 fixed 并写上提交哈希。

## 验证

- 修复后重新构建，在同一个（动画帧不触发的）预览页面里换模型、发“只回复 OK”：切换提示和回复都实时出现，没有刷新页面。
- 未验证：修复后审批卡片的实时出现（没有为此再发一条会触发审批的消息）；没有补自动测试（`enqueueEvent` 未导出）。
