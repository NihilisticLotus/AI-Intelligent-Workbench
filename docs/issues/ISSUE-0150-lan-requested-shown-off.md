# ISSUE-0150：启动时未能恢复的局域网被显示为“已关闭”，开关无法真正关闭

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | [第 1.7 步代码审查](../acceptance/step-1.7.md) |
| 开启 | 2026-11-19 |
| 关闭 | 2026-11-19 |

## 现象

局域网开启后重启工作台，若启动时网络变成公用网络、网卡未连接，或端口顺延导致防火墙规则不匹配，Gateway 保留“要求开启”的设置但不启动第二监听。“设备与访问”只看 `enabled`，显示“已关闭，只有这台电脑能访问”，开关为关。

## 复现步骤

1. 在专用网络开启局域网。
2. 关闭工作台，把网络改成公用网络（或占用 17890 让端口顺延），再启动。
3. 打开“设置 → 设备与访问”：页面写“已关闭”。点开关会再次尝试开启，而不是关闭。
4. 网络恢复专用后再重启，局域网自动重新开放。

## 影响

用户以为局域网已关闭，实际下次满足条件时会自动对局域网开放。想彻底关闭只能先开再关。

## 根因

接口已返回 `requested`，网页的开关、状态文字和网卡选择都只用 `enabled` 判断。

## 处理方式

网页新增 `lanSwitchOn`、`lanStatusText`：`requested` 为真时开关显示为开，状态写“已开启，暂未生效”，网卡选择锁定；点开关提交关闭，清除设置并删除规则。局域网关闭但仍查到规则时，防火墙一栏改写“有残留规则，点‘更新规则’删除”。

## 验证

新增网页测试覆盖“要求开启但未生效”的渲染与开关可用。临时撤掉修复后该测试失败，恢复后通过。全量结果见验收记录。

- 2026-11-19 代码审查发现并修复。
