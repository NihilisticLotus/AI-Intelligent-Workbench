# ISSUE-0022：Claude 回合卡住两分钟以上没有任何输出，也没有超时

| 项 | 值 |
|---|---|
| 状态 | open |
| 类型 | bug |
| 严重程度 | 高 |
| 发现于 | [第 1.2 步补验](../acceptance/step-1.2.md)（2026-11-08） |
| 开启 | 2026-11-08 |
| 关闭 | |

## 现象

1.2 补验时 Claude 账号额度用完，两次表现不同：

- 第一次（新会话，haiku）：发出消息后 3 分 25 秒没有任何事件，之后才收到 429 文本和 `agent.quota_exceeded`，任务暂停。
- 第二次（Gateway 重启后，恢复同一个会话再发消息）：`session.started resumed=true`、`session.config` 之后 2 分钟以上没有任何事件，也没有错误。手动 [停止] 后任务变为“已暂停”。

这期间界面只显示“正在处理”，用户不知道是在等模型、在重试，还是已经卡死。

## 复现步骤

1. 用额度已经用完的 Claude 账号，在任务里发一条消息。
2. 观察事件：长时间没有 `message.delta`、`tool.*`、`error`。

## 影响

任务长时间占着 Agent 的并发名额；用户无从判断要不要等。额度用完之外的网络问题、上游重试大概也是同样表现。

## 根因

未查明。推测 claude.exe 遇到 429 后在内部重试（带退避），重试期间不发 ACP 更新；第二次可能是重试时间更长。Gateway 没有“回合内长时间没有任何事件”的检测。

## 处理方式

第 1.3 步：

- Gateway 给每个回合加“无事件计时”：60 秒没有任何事件时发 `session.notice`（“Agent 已经 1 分钟没有回应，可能在重试或网络不稳定，可以继续等，也可以停止”），界面在“正在处理”旁显示已等待时间和 [停止]；10 分钟仍没有事件时自动取消这一轮并暂停任务，错误码 `agent.no_response`（协议只增不改）。
- 查 claude-agent-acp 0.100.0 / claude.exe 是否有关闭或缩短重试的开关（环境变量或 `_meta` 选项），有的话设成较短的重试，让 429 尽快报出来。
- 测试：假 ACP Agent 加一个“长时间不发事件”的场景，用假时钟验证提醒和自动取消。
