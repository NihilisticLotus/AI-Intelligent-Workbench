# ISSUE-0120：保留原会话时模拟第三方 Agent 无法取得接收名额

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 中 |
| 发现于 | [1.6 阶段 6](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

接收端有空位仍出现“任务已经占用或等待名额”。

## 复现步骤

1. 在新建临时项目启用两个进程内模拟适配器的第三方会话计数，从不支持原生恢复的来源发送到另一个模拟 Agent。

## 影响

第三方会话接力及同 Agent 强制 H2 都可能在有容量时失败。

## 根因

队列原先把任务 ID 当作所有 Agent 的唯一运行名额。

## 处理方式

交接时按每个存活进程占一个名额，后续回合仍防止重复加入。保留来源时允许接收端独立占位，继续遵守目标 Agent 的并发上限。模拟回归证明修改前失败，修复后跨 Agent 成功，同 Agent 上限 1 保留原会话，上限 2 重开成功。

## 验证

阶段记录见 [1.6 验收](../acceptance/step-1.6.md)。

## 时间线

- 2026-11-18 开启，已定位并修复，等待阶段全量验收。
- 2026-11-18 关闭。两个模拟第三方会话分别计数，来源占位、并发上限和同 Agent 重新交接均通过。见 [阶段 6 全量验收](../acceptance/step-1.6.md)。
