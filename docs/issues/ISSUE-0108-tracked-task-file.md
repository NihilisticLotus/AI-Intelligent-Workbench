# ISSUE-0108：项目已跟踪同名任务说明时，副本文件与工作台目标不同

## 现象

新任务的数据库账本有本次目标，但其 git 工作副本中的 `.aic/TASK.md` 是项目原先提交的内容。若交接直接要求新 Agent 以这个文件为准，它会读到另一份说明。

## 复现步骤

1. 在新建的临时 git 项目提交一个 `.aic/TASK.md`，写入“项目自己的说明：保留图集源文件”。
2. 使用离线演示适配器新建草稿任务，任务描述为“工作台本轮目标：核对关卡存档”。
3. 等副本准备与说明写入结束，比较原项目文件、副本文件、事件和任务账本。

## 影响

在原项目已经跟踪同名文件的情况下影响新任务，与 ISSUE-0104 所涉旧任务撤销相互独立。原项目文件未被修改。

## 根因

git 创建工作副本时会检出项目的同名文件。工作台发现目标没有自己的写入收据，保留用户文件。第 12.3 节规定了工作副本的固定说明路径和 inplace 的内联例外，未规定这种同名冲突时 Agent 应读哪一份。

## 处理方式

建议保留项目同名文件，针对冲突的工作台材料改为内联账本原文，去掉对应文件引用。另一选择是在准备副本时报告名称冲突并停止该任务。详见验收记录中的选择说明。

## 验证

两个文件都仍含项目原文，副本文件不含工作台目标，数据库账本含正确目标，并收到说明未更新的提示。只在新建的临时项目复现，未启动真实 Agent。
