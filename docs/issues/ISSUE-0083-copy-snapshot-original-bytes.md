## 现象与影响

非 git 文件被复制后，普通 git add 仍会执行 autocrlf 或 .gitattributes 的换行规范化；直接用快照 blob 回滚可能把原来的 CRLF 改为 LF，无法保证原始文件摘要一致。

## 复现步骤

1. 临时非 git 项目放入 CRLF 文本以及 `*.txt text eol=lf` 属性。
2. 建副本、修改、快照、应用，再撤销应用。
3. 按字节检查恢复结果，应与初始 CRLF 内容完全一致。

## 根因与处理方式

影子快照是恢复材料，不应采用普通版本控制的内容规范化。copy 用 hash-object --no-filters 写原始对象，再显式更新私有索引；不改变 git worktree 的正常差异语义。回滚前再次核对基线 blob 与原始摘要，旧快照不一致时停止，不伪称恢复。
