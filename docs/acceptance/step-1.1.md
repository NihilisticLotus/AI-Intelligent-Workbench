## 实际操作（浏览器）

1. 带 `#pair=<配对码>` 打开 → 自动配对，地址栏的配对码被清掉。没有令牌时显示配对页，可以重新生成配对码。
2. 添加项目：通过文件夹浏览对话框选择，不用手打路径，能自动识别 git 仓库。
3. 新建分组、把任务移入分组；在项目和分组两种视图之间切换；组内按最近活动排序。
4. 用演示 Agent 新建任务，权限为“需审批”：先弹出“请求修改文件”的审批，允许后再弹出“请求执行命令”的审批，再次允许后任务变为“待验收”。
5. 拒绝审批并填写理由：Agent 引用这条理由换了一种做法；工具行显示“未执行（已拒绝）”，不显示“执行失败”。
6. 切换模型和思考强度；切换权限级别，图标随级别变化，选“全自动”时要二次确认，按钮变成琥珀色。
7. 刷新页面后对话完整恢复；Gateway 运行期间断开连接，侧栏显示“正在重新连接…”，发送按钮被禁用，恢复后事件补齐。
8. 窄屏（小于 768px）：侧栏收进抽屉，底部出现导航栏。

## 审查与修复

4 位审查员分别从安全、正确性、接口规则、和原型的一致性四个角度审查，共报告 26 条问题。逐条复核后确认 21 条，全部修复，并补上了对应的测试。主要修复：

- 安全：
  - 去掉固定的开发配对码，开发模式改为把启动时的随机码写进数据目录。
  - 浏览器登录同时要求 Cookie 和设备密钥；Cookie 名带上实例 ID，不同端口之间不再共用。
  - 配对失败按配对码计数；重新配对时吊销旧设备。
- 正确性：
  - 加单实例锁，第二次启动时打开已有实例，不再把第一个实例的任务改成“已中断”。
  - Gateway 重启后用 bootId 识别，避免重复执行。
  - 补发改为异步并带背压。
  - 会话启动期间也能取消。
- 接口规则：
  - 令牌交付方式由 Platform 决定，为桌面软件和手机应用预留了 Bearer 方式。
  - 文件夹浏览改为游标分页。
- 界面：
  - 窄屏加上底部导航；已处理的审批显示处理设备的名称。
  - 拒绝理由框加了“取消”按钮。
  - 第 1.1 步不提供“总是允许”（规则功能放在第 1.3 步）。

主 Agent 复核时又发现一处：“需审批”级别下修改文件没有走审批，和 design.md 9.1 不符。已修复：演示 Agent 修改文件前也会请求审批，测试已同步更新。

## 备注

- 启动脚本 `.bat` 只用 ASCII 字符：实测发现，cmd 在 UTF-8 代码页下调用 npm.cmd 后会读错文件位置，导致中文行被截断。所以中文提示放在 `scripts/start.mjs` 和 `scripts/no-node.txt` 里。
- 数据库迁移到 v2 时，会让已有的浏览器设备失效，需要重新配对一次（安全修复的一部分）。
