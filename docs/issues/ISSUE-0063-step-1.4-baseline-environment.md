## 现象

工作区干净、尚未修改业务代码时，typecheck 与 build 通过，但默认 npm test 无法复现历史的 789 通过 / 3 跳过基线。适配器 7 项失败涉及 taskkill、进程退出与超时；Gateway 另有独立命令、受控文件、附件和运行时测试失败。

## 复现步骤

1. 在当前受限执行环境运行项目默认三项检查。
2. 独立启动一个 2.5 秒后自行退出的 Node 子进程，只对该子进程执行 taskkill /T /F。
3. 观察退出码 1 和“错误: 拒绝访问”；子进程自行结束。

## 影响

阶段 0 无法判定通过；按 phase-1 第 10 节，不得进入阶段 1 或将历史基线记作本轮通过。未影响正式工作台，没有调用收费 Agent。

## 根因

最小复现确认当前环境拒绝进程树操作。文件宿主的 forbidden 与命令作业失败的全部根因尚未查明；当前不能据此认定产品本身回归。

## 处理方式

保留测试与安全约束，先收集完整结果；不增加跳过项、不缩减断言、不绕过宿主校验、不改系统设置。后续须在能够执行既有 Windows 生命周期测试的获准环境中复验，再判断是否需要产品修复。

## 验证

- typecheck、build 通过。
- 最小 Node 子进程 taskkill 检查两次均失败；第二次按 GBK 解码确认是“拒绝访问”。
- 默认 npm test 最终结果待追加。
- 未验证：其他获准环境中的同一提交是否恢复 789 通过 / 3 跳过。
