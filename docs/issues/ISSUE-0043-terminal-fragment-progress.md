## 现象

智谱第二回合产生一段文字后协议失败，任务标题已显示“失败”，请求记录也有失败终态，但过程仍显示“正在处理 · N 秒”，数字继续增长。

## 复现步骤

1. 产生 message.delta 或 thought.delta，未产生对应 message.done。
2. 接收任务 failed 状态；也可用离线事件回放重现。
3. 观察过程仍被当作未结束。真实现场来自 ISSUE-0042，不需要重新调用真实模型复现。

## 影响

误导用户认为任务仍在执行，影响失败后的核对。此显示缺陷不证明后台仍有请求，也不是 ISSUE-0042 的协议失败原因。

## 根因

buildTimeline 仅在后续消息、工具开始或 message.done 时关闭先前片段，没有在任务结束状态上关闭；严格传输检查失败不会提交助手记录，因而也没有 message.done。

## 处理方式

时间线收到 review / paused / interrupted / failed / merged / discarded 后关闭文字、思考的进度；保留片段与错误，不补造正式消息。queued / running / waiting 不关闭，失败后新回合照常进入进行状态。没有调整协议、传输、费用或服务路由。

## 验证

- 新增两项离线回归覆盖六种结束状态、三种忙状态与失败后新回合。
- 浏览器重新载入已有真实失败任务，显示固定“用时 4 秒”，失败提示与原片段保留；没有发送新消息或请求模型。
- 完整 typecheck / test / build 结果与提交哈希随后追加。
