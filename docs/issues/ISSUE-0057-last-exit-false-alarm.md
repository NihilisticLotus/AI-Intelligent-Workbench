# ISSUE-0057：旧格式日志下，启动时把本次的启动行当成上次运行，误报“上次没有正常退出”

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 低 |
| 发现于 | [第 1.3 步代码审查](../acceptance/step-1.3.md)（2026-11-11，范围 0e1a3b2..80ed883） |
| 开启 | 2026-11-11 |
| 关闭 | 2026-11-11 |

## 现象

日志里还没有“生命周期”记录的数据目录（旧版本升级后第一次启动），上一次明明是“正常退出”，本次仍记录 WARN“上次运行没有正常退出”，设置页“关于”也显示异常退出。正式数据目录 2026-11-10 23:12 那条来源不明的警告就是这样来的。

## 复现步骤

1. 日志依次写入旧格式的“启动 v…pid 1”“已启动”“正常退出”。
2. 再写入本进程的“启动 v…pid <本进程>”，调用 readLastExit。返回 clean=false。

## 影响

一次性误报，但会干扰 ISSUE-0015（意外退出）的排查。

## 根因

server.ts 的 main 先写“启动 v…”再创建 Gateway；readLastExit 的旧格式兜底找最后一条含“启动 / 退出”的行，匹配到的是本次自己的启动行。

## 处理方式

兜底时排除以本进程 pid 结尾的“启动 v”行。

## 验证

- crash-log.test.ts 新增 2 项：上次正常退出时不再误报；上次只有启动没有退出时仍判为没有正常退出。
