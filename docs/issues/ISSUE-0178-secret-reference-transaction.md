# ISSUE-0178：配置保存中断可能留下无归属的密文

| 项 | 值 |
|---|---|

| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | `6a163f5`，[第二轮审查](../acceptance/workbench-review-2026-11-21.md#第二轮审查) |
| 开启 / 关闭 | 2026-11-21 |

## 现象与影响

服务配置和加密条目分开提交，进程中断可能留下无归属的密文。兼容账号保存失败还可能只改了部分字段。

## 复现方法

在临时数据库创建、轮换服务，另开只读连接观察事务可见性。为兼容账号注入新建与默认账号写入失败。测试只使用合成值。

## 根因与处理

先异步加密，再在保存配置的同一事务写入密文和引用。轮换兼容账号时重新读取事务内的当前引用，连同默认项、审计与旧密文清理一起提交。

## 验证

旧版第二个连接在创建、轮换的中途各读到一个未关联条目。修复后两次均为零。兼容账号保存失败时，原字段和原密文引用保持一致。

## 时间线
