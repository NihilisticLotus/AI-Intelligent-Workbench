## 现象与影响

交接守卫等订阅者在处理工具事件时追加提示，网页可先收到序号较大的提示，随后跳过工具事件。正在观看任务的用户可能需要刷新才能看到完整记录。

## 复现方法

一个订阅者在首条事件触发时追加提示，另一个记录交付顺序，同时在事务中写两条原始事件。

## 根因与处理

提交后的通知逐个直接运行，订阅者重新进入发布流程后先完成了新事件的发送。按提交顺序排队，当前批次发布完再发送派生通知。独立请求账本直接检查事务状态，继续保证预算预留先写入磁盘。

## 验证

`packages/gateway/test/events.test.ts` 对比数据库序号与实时交付顺序。
