# ISSUE-0138：接收方首轮中途失败或被停止时交接被静默撤回

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 高 |
| 发现于 | [1.6 完成后的第二次代码审查](../acceptance/step-1.6.md)（审查范围 5dc0c9c..72adaf5） |
| 开启 | 2026-11-19 |
| 关闭 | 2026-11-19 |

## 现象

接收方首轮没有以 end_turn 结束（出错、被停止、拒绝、审批超时）时，runTurn 一律按交接失败处理：任务换回原 Agent、接回原会话。接收方在这一轮里可能已经改过文件，原 Agent 不知道这些改动。

## 复现步骤

1. 交接给另一 Agent，让接收方先调用编辑工具改文件，再让进程报错。
2. 任务回到原 Agent，交接记为失败，文件改动留在副本里。

## 影响

原 Agent 在不知情的情况下继续工作，可能覆盖或重复接收方的改动；用户主动停止也被显示为交接失败。

## 根因

sent 只在 handoffTurnCompleted() 时置位，finally 里 !sent 一律走 failedHandoff。

## 处理方式

接收方在本会话里已经发起过工具调用，或消息已送达后由用户停止（非无响应）时，保留交接：记为 sent、发 session.handoff、关闭原会话，并在对话里提示“首轮没有正常结束，交接已保留”。接收方没有动手就失败时仍回到原 Agent。

## 验证

`handoff-review.test.ts` 两例：接收方动手后崩溃 → 任务留在接收方、状态 sent；未动手即失败 → 回到原 Agent、状态 failed。临时还原修复后第一例失败。
