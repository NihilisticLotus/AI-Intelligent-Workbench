# ISSUE-0104：旧任务撤销应用时可能涉及项目自己的 .aic 文件

## 现象

1.5 的非 git 项目可以把根目录 `.aic/` 当作普通项目资产。若历史任务已经应用过该目录内的改动，升级后直接按 1.6 的新规则过滤文件，会让撤销误报原项目有后续修改。

## 复现步骤

1. 在新建的临时非 git 项目中写入 `.aic/rules.txt` 和 `notes.txt`，两个文件内容均为“修改前”。
2. 用 `bbddd2b` 中的工作区管理器创建副本，把两个文件内容改为“修改后”，打影子快照并应用。
3. 用阶段 1 排除根部 `.aic` 的工作区管理器打开同一临时数据库，撤销应用。随后用原管理器对照。

## 影响

只要 1.5 已应用任务的历史应用清单包含根部 `.aic` 路径，就需要区分项目原有文件和 1.6 新生成的工作台文件。未读取真实任务数据，实际受影响的任务数量未知。

## 根因

旧版将项目资产登记在应用清单中。新版枚举跳过该目录后，旧清单里的文件在核对时被视作缺失。直接过滤旧清单还会让部分撤销看起来像完整成功。

## 处理方式

待用户确定对历史撤销的处理范围。方案 A 保持 1.5 的既有撤销能力，只对升级时已经应用的旧清单沿用原校验与整批撤销。方案 B 遇到这种旧清单时整批停下并在界面说明，不写项目。两种方案均对新任务完全排除工作台文件。

## 验证

在上述临时项目实测，1.5 返回 `applied` 并列出两个文件。阶段 1 的初步排除实现返回 `source_changed`，两个文件仍是“修改后”。同一份数据随后交给 1.5 撤销，返回 `rolled_back`，两个文件恢复“修改前”。未操作用户项目。
