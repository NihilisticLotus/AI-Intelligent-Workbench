# ISSUE-0078：并行长工具测试依赖固定延时造成时序误判

| 项 | 值 |

| 类型 | 测试稳定性 |
| 严重程度 | 中 |
| 发现于 | 第 1.5 步阶段 1 全量测试 |
| 开启 | 2026-11-15 |
| 关闭 | |

## 现象

新增 git 进程测试参与全量运行时，既有 real-agent.test 的长时间静默并行工具用例在“第一个工具已结束”断言失败；任务仍然运行，没有证据表明产品看门狗误停。

## 复现步骤

1. 执行包含工作区测试的 npm test。
2. 夹具进程在 500ms 后发送 A 结束，测试进程固定等 750ms 后检查事件；本次并发负载下结束事件尚未到达。

## 影响

默认全量测试可能因进程调度延迟误报失败。

## 根因

两个进程各自的定时器无法保证事件传输先后；固定等待不等于确认收到事件。

## 处理方式

先明确等到 A 结束事件，再跨过普通无回应上限检查 B 仍在运行。B 等待本测试临时目录的释放信号，完成检查后才发结束。保留全部原断言，不增加产品或既有测试超时，不连接网络、不启动真实 Agent。

## 验证

首次全量失败已记录；修复后的专项与全量结果待追加到 step-1.5 和本问题时间线。
