# ISSUE-0047：新任务选择第三方时无法保留软件默认模型

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | [step-1.3](../acceptance/step-1.3.md) 原生 Luna 补验准备 |
| 开启 | 2026-11-08 |
| 关闭 | 2026-11-08 |

## 现象

新建任务默认处于演示 Agent，展开 Codex 只有九个具体模型。一级只展开、二级只能点实际模型，无法改用 Codex 自己的默认模型；已选择具体模型也无法在此处清空。

## 复现步骤

1. 打开新建任务，不改变项目或软件设置。
2. 展开 Codex，观察模型列表没有“Agent 自己的默认模型”。
3. 取消对话框；没有创建任务或发送消息。

## 影响

用户不能从该入口选择“不下发模型 ID”的原生配置，新补验的默认基线也无法按原方案用界面准备。

## 根因

pickerItems 只映射实际目录，AgentPicker 只在目录空时生成默认选项；因此有模型的第三方无法显式选择空值。后端和新任务提交本已支持 model=null，不是第三方认证或 API 覆盖。

## 处理方式

仅在新建任务、usesNativeConfig 时追加默认模型选项，选择空值沿用现有 model=null 提交；保留真实模型顺序，已有会话和独立 Agent 不加入虚构 ID。null 的可见勾选与 aria-checked 对齐，设计与原型同步。修复哈希和验证结果随后追加。

## 验证

- 修复前正式浏览器实际展开 Codex，缺少入口；[截图](../acceptance/assets/step-1.3-native-default-before.jpg)。
- 定向选择器测试通过，完整检查与修复后界面尚待本轮完成，真实调用仍为零。
