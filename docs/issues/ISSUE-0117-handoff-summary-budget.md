# ISSUE-0117：交接摘要模型与任务执行模型使用不同的请求预算绑定

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 待办 |
| 严重程度 | 中 |
| 发现于 | [1.6 阶段 5](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

只使用第三方 Agent 的任务通常没有独立请求预算。已配置独立执行模型的任务有预算，但换成另一个摘要模型后，请求不能占用该预算。

## 复现步骤

1. 在内存数据库创建演示任务，使用现有请求账本读取任务预算。
2. 设置三次请求的执行预算，保留任务和服务，只将模型换成另一个测试模型，尝试预留一次请求。
3. 查看原预算已占用的次数。

## 影响

全局可以选择任意已配置的摘要模型。如果采用单独额度，摘要可能产生任务执行上限以外的费用。如果共用任务额度，摘要和探针会减少剩余执行次数。

## 根因

独立请求账本按任务保存唯一执行预算，并核对服务、模型和配置修订。计划第 12.3 节规定了请求用途和记账机制，未规定摘要购买应消耗哪一笔额度。

## 处理方式

等待用户决定。验收记录列出了单独的摘要总额度和共用任务额度两种方案。两种均在请求发送前检查预算，保留原任务的模型绑定，摘要不足时使用确定性内容继续交接。

## 验证

内存数据实测，第一步返回“任务尚未设置独立请求预算”，第二步返回“请求与任务预算绑定不一致”，最终已请求条数为 0。没有发出网络请求。

## 时间线

- 2026-11-18 开启，已核实现有预算限制并将费用归属列为待决定事项。
- 2026-11-18 用户选择 A，设置独立的全局摘要额度，请求记录关联实际任务。
- 2026-11-18 修复。摘要和探针逐次占用单独总额度，关闭重开和进程中断都保留已占用额度。全仓 1111 通过、3 跳过；智谱两次摘要用途请求成功，实际任务执行请求为零。
