## 现象

下一轮仍显示同一 Agent，但模拟原生连接收到的会话编号从原会话变成了失败接收段的编号。

## 复现步骤

在临时项目完成一次交接，再对同一 Agent 强制 H2；让新接收段拒绝首轮，随后发一条普通消息。另在启动恢复用例中模拟接收段已登记、收据尚未回填。

## 影响

会话上下文、后续预览里的交出方以及恢复后的历史查询可能与用户选择不同。

## 根因

恢复和预览原先各自选择最近会话，没有识别失败的交接。启动恢复只检查收据上的接收会话编号。原生恢复也没有重新登记历史服务。

## 处理方式

统一来源选择。按任务和 Agent 排除失败接收段，优先取活动会话，再看最近一次启动或恢复。不同 Agent 间保留活跃的来源连接到目标首轮成功。原生恢复已交接会话时重新发放只读授权，原授权随旧连接结束失效。启动恢复同时核对会话表，保留尚未发送的预览。

## 验证

同一 Agent 的三个回合分别进入原连接、失败的新连接、恢复的原连接。旧令牌和失败接收令牌均失效，新授权仍限原任务和原交接。模拟启动恢复只标记已建立接收段的收据。
