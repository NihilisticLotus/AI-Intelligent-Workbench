## 2026-11-19 阶段 3：局域网配对与设备来源

- 本机已配对设备可查看独立的六位局域网配对码。回环启动码继续走原流程，局域网提交正确码后只返回待确认状态。通知只发给本机连接，本机没有已订阅的网页时拒绝请求。等待中最后一张本机网页掉线、两分钟超时或点拒绝后均不发凭据。
- 本机允许后，只有原请求 IP 能凭同一个请求编号领取一次 Cookie 和设备密钥。Cookie 带 `HttpOnly`、`SameSite=Strict`，HTTP 下没有 `Secure`。配对每 IP 每分钟最多五次，连续十次失败锁十五分钟。回环和局域网分开计数，错误返回可重试时间。
- 数据库迁移 v26 为原配对保留本机来源。关闭再开启第二监听后，局域网设备能用原凭据重新连接。吊销全部局域网设备会立即使这些凭据失效并断开其 WebSocket，保留本机设备。阶段 4 完成操作保护前，已配对的局域网连接只开放读取。
- 通过回环别名、假网络执行器和临时数据库验证。临时移除两处检查后，测试分别观察到电脑未允许就发放凭据、没有本机网页也能进入待确认。恢复后四项新增测试全部通过。
- `npm run typecheck`、`npm test` 与 `npm run build` 均通过。默认离线测试 1165 通过、3 跳过（适配器 104 通过 / 3 跳过，Gateway 826、协议 67、网页 168）。构建保留已有的体积提示，本阶段没有界面改动。

## 2026-11-19 阶段 7：真机复核步骤

本轮用户无法使用手机或另一台电脑，以下步骤留作现场验收。离线替身使用的是本机回环地址和模拟防火墙。设备、系统和真实网络结果登记在 [ISSUE-0149](../issues/ISSUE-0149-lan-phone-acceptance.md)。

1. 在电脑打开 AI Console，进入“设置 → 设备与访问”。选当前 WiFi 的专用网络网卡，打开局域网开关，在 Windows 的 UAC 窗口点“是”。等网页显示“防火墙规则正常”。如果 Windows 另弹“允许访问网络”，记下弹窗内容和当时的操作。
2. 让手机连同一 WiFi，在手机浏览器打开电脑显示的地址。电脑点“配对新设备”，把六位码输到手机。电脑弹出“有新设备请求连接”后，核对设备和 IP，点“允许”。扫码入口暂缓，本次使用地址和配对码。
3. 用手机新建演示 Agent 任务。看到“演示 Agent 请求修改文件”时点“允许一次”，观察任务继续。演示 Agent 有第二次审批时也可允许。这个过程无需电脑再确认。
4. 在手机打开验收项目的“项目设置 → 权限规则”，添加一条规则并点“保存规则”。确认电脑弹出“确认远程操作”，点“拒绝”以免保存验收规则，并查看审计记录。
5. 手机先竖屏、再横屏，各试一次新建任务、发消息、审批、查看“改动”、停止任务和打开设置。演示 Agent 不写真实文件，改动为空时核对空状态可读。打开软键盘时确认输入框和发送按钮可见，点“添加图片”试相册和拍照。条件允许时换另一种系统的手机复测。
6. 回电脑的“设备与访问”，按名称和 IP 找到本次手机并点“吊销”。确认手机回到配对页。关闭局域网，出现 UAC 时确认删除。检查设置显示“只有这台电脑能访问”和“未安装规则”，手机刷新原地址失败。可在 Windows“高级安全 Windows Defender 防火墙”的入站规则中核对本实例的 `AI Console LAN` 规则已删除，其他实例的规则无需操作。
