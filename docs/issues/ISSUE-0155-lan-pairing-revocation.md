# ISSUE-0155：设备吊销和一次性配对领取的状态不一致

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 高 |
| 发现于 | `16e0c4b`，[1.7 审查记录](../acceptance/step-1.7.md) |
| 开启 / 关闭 | 2026-11-21 |

## 现象与影响

已有设备的换配在电脑允许后仍可能等到吊销后才领取。批量吊销也遗漏尚未领取的配对和已发出的六位码。换配中途写库失败时，可能同时留下新旧设备。

## 复现步骤

用临时设备在等待、已允许未领取、换配写入失败三个阶段核对设备列表与领取状态。同时检查只读取响应头的请求。

## 根因与处理方式

单设备吊销同步撤回对应的换配。批量吊销同时作废全部在途配对和当前码。换配在一个事务内写入新设备并撤销旧设备。一次性领取接口只用 GET 领取，HEAD 返回 405。电脑收到配对请求后收起已用的六位码，重新生成也清除旧的手动复制文本。

## 验证

离线覆盖单设备吊销、批量吊销、换配失败重试及只读响应头。正常换配后只留一台有效设备，只读响应头不会领取凭据。
