# ISSUE-0019：回复的结构和格式与常见 Agent 软件差别大（参照 Codex）

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | 用户人工验证（2026-11-07，对比 Codex 截图） |
| 开启 | 2026-11-07 |
| 关闭 | 2026-11-07 |

## 现象

1. 思考的折叠仍然不对：每段思考各自折叠、各自显示，过程散落在整条回复里。
2. Codex 把一轮的思考、中途说明、搜索收进一个“已处理 N 秒”的折叠里，网页搜索合成一组“已搜索网页”，展开可逐项查看；工作台没有。
3. 回答是原样贴出来的，`##`、`**…**` 直接显示，链接显示成网址文本。
4. 选中对话文字后，Codex 有“添加到对话 / 在侧边聊天中提问”菜单，工作台没有。

## 根因

- ISSUE-0018 只合并了头像和名称，时间线仍按片段逐条渲染，没有“一轮”的概念。
- 回答文本只做了换行处理，没有 Markdown 渲染。

## 处理方式

- 新增 `groupTurns`：两条用户消息之间 Agent 的输出合成一轮。最后一段并且之后没有工具调用的输出作为最终回答；其余（思考、中途说明、工具、审批）收进“用时 N 秒”折叠。进行中显示“正在处理 · N 秒”并展开，有待审批时强制展开，结束后收起，用户手动开合后以用户为准。
- 连续的网页搜索合成一组“已搜索网页 N 次”，展开后列出每次的内容。
- 回答和思考用 react-markdown 10.1.0 + remark-gfm 4.0.1 渲染（不渲染原始 HTML）；链接只显示文字，点击后经 `platform.openExternal` 在系统浏览器打开。
- 选中文字菜单：[添加到对话] 在第 1.2 步提供，把选中的内容作为引用插入输入框；[在侧边聊天中提问] 依赖侧边聊天（design.md 第 26 节，后续阶段），由功能开关 `chat.side` 控制，目前关闭、不显示。

## 验证

- `timeline-grouping.test.ts` 新增 groupTurns 3 项（共 6 项）。
- 浏览器实测（演示 Agent）：整轮只有 1 个头像，显示“用时 59 秒”，展开后能看到思考、中途说明、工具行和已处理的审批；回答里的有序列表正常渲染；选中回答文字弹出“添加到对话”，点击后输入框里是 `> 完成了。总结一下：`；控制台没有报错。
- 未验证：用真实 Codex 的网页搜索会话在工作台里对照显示（演示 Agent 不发网页搜索事件，搜索分组只有单元测试）。

## 时间线

- 2026-11-07 开启并修复。
- 2026-11-07 用户纠正：[添加到对话] 不是往输入框里插“> 引用”，而是 Codex 的注释流程。改为：评论框“添加可选评论…” → 原文旁编号圆点（悬停看评论，点击修改 / 删除，原文高亮）→ 输入框上方“N 条注释”（列表可删除，× 清空）→ 发送时附在消息后面，发出后清空。新增 `lib/annotations.ts` 及 4 项测试；浏览器实测正式网页和原型的完整流程，控制台无报错。
