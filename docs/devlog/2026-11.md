## 2026-11-05 确定总体方向：本地 Gateway + ACP + 多端共用接口

- 背景：用户希望用一个工作台整合本机的 Claude Code、Codex、CodeBuddy、WorkBuddy、ZCode，随时切换模型不丢上下文，以后还要能从外网和手机操作。
- 决定：做一个常驻的本地 Gateway，对下用 ACP 接入各家 Agent，对上提供 REST + WebSocket 接口；网页、桌面软件、手机应用都只是客户端。上下文由工作台自己持有（事件库 + 工作区 + 任务说明文件），不依赖各家的私有会话格式。
- 放弃的方案：直接控制各家的图形界面（不稳定）；把各家的原始会话互相迁移（格式私有，做不到）。
- 影响：design.md 第 2、6、7 节。

## 2026-11-05 用户偏好：全程图形界面

- 背景：用户说“我不喜欢用命令行”。
- 决定（用户决定）：安装、登录、配置、排错全部做成界面操作；底层的命令行 Agent 由工作台在后台托管。
- 影响：design.md 第 3 节（安装包、托盘）、第 6.2 节（适配器提供 install / login）。

## 2026-11-05 本机实测各 Agent 的接入方式

- 发现：WorkBuddy 内置了 CodeBuddy Code 引擎（`codebuddy.js`），原生支持 `--acp`；ZCode 内置 `zcode.cjs` v0.17.1，有 `app-server`，但用的是自有协议，需要写桥接；CodeBuddy 编辑器本体是 VS Code 改版，没有 Agent 命令行。
- 影响：design.md 6.1 节。ZCode 放到较后的里程碑。

## 2026-11-05 范围调整：外网和手机优先级降低

- 决定（用户决定）：先做好本机和局域网直连；外网访问（VPS 中转，浏览器直接访问）和手机应用后做，但接口要预留。
- 影响：design.md 第 16、18 节。

## 2026-11-05 界面方向：轻量工作台，不做编辑器式的停靠面板

- 背景：第一版原型参照游戏编辑器做了可停靠面板，用户反馈“不需要像游戏编辑器这么重”。
- 决定（用户决定）：固定为侧栏 + 主区 + 按需出现的右侧面板；三维预览是右侧面板里的一种预览，可以全屏查看。
- 放弃的方案：dockview 可停靠面板和三套预设布局。
- 影响：ui-design.md v0.2。

## 2026-11-06 自动交接：默认全自动，不弹窗

- 背景：用户不希望每次交接都人工查看交接内容，也觉得交接包太简单。
- 调研：research/handoff.md。同一工具里换模型，主流产品都是转写完整历史；跨 Agent 时，没有产品能注入原生的工具消息。
- 决定：交接分 H0–H4 五级；交接内容扩展为 13 项；发送前在后台自动做覆盖校验、一致性校验和探针问答；只有 4 种情况会打扰用户；事后可以查看、切回、重新交接。
- 影响：design.md 7.5 节。

## 2026-11-06 快速判断层和按会话的开关

- 决定（用户决定）：快速判断默认用已有账号或 API 的便宜模型（不用下载，但消耗额度）；“低风险审批自动允许”按会话提供开关，默认打开；“测试通过后自动合并”按会话提供开关，默认关闭，开启时要二次确认。
- 影响：design.md 24.3、24.5 节。

## 2026-11-06 模型资料：自动联网调研，以可信度最高的来源为准

- 决定（用户决定）：新模型不在资料表里时自动联网调研；多个来源说法冲突时，以可信度最高的来源（官网）为准，而不是取最保守的值。

## 2026-11-06 第 1.2 步联调与真实冒烟

- 背景：后端和网页分别完成后做联调、真实 Agent 冒烟和浏览器验收（验收记录 docs/acceptance/step-1.2.md）。
- 发现并修复（工作区，未提交）：
  - 后端报告的“Claude 未登录”是误报：从 Git Bash 启动时 `HOME=/c/Users/...` 传给了 Windows 原生的 claude.exe，它找不到登录信息。`buildChildEnv` 在 Windows 上删掉以 `/` 开头的 HOME；同时预防性删掉宿主 Claude Code / 桌面端注入的变量（`CLAUDECODE`、`CLAUDE_CODE_OAUTH_TOKEN`、`CLAUDE_CODE_HOST_*` 等），保留用户自己的 Claude Code 设置。Node 写的 CodeBuddy 不受 HOME 影响（Windows 上 `os.homedir()` 读 USERPROFILE）。
  - CodeBuddy 版本 0.0.0：真实版本改从 `codebuddy.js` 嵌入的包信息读取。
  - [重新检测] 对已登录的 Agent 都做一次探测会话，和计划 6.3 一致（之前只有 Claude 会探测，Codex 卡片一直没有模型）。
  - 网页实时事件只靠 `requestAnimationFrame` 合并，窗口被遮挡时审批卡片不出现（ISSUE-0014）：加 100ms 定时器兜底。
- 决定：冒烟测试为控制费用改为每个 Agent 最多 3 条极短消息（OK → 审批一次 → 换模型和强度 → OK），resume 不再发消息，不再让模型调用 `aic-echo`；计划 6.8 同步修改。这是联调任务里约定的预算，不是用户的原话。
- 实测：Claude Code、Codex 冒烟全部通过（审批、换模型和强度、resume 都成功；resume 后配置回到默认，靠 Gateway 重新下发，ISSUE-0012）。CodeBuddy 未登录，没有替用户登录（ISSUE-0010）。浏览器里用 Claude Code 完成了新建任务、审批、换模型和继续对话。
- 关联：ISSUE-0001、ISSUE-0007、ISSUE-0008（时间线已追加）；新开 ISSUE-0010 至 ISSUE-0014。

## 2026-11-07 第 1.2 步完成：接入真实的 Claude Code、Codex、CodeBuddy

- 背景：按 plans/phase-1.md 第 1.2 步开发。过程中后台模型账号额度多次用尽（429），流程从中断处续跑了 3 次，已完成的部分全部复用，没有重复花费。
