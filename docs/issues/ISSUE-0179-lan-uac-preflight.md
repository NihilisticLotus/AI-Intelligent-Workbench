# ISSUE-0179：局域网开关缺少 Windows 无法弹出 UAC 时的处理约定

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 高 |
| 发现于 | `680e3aa`，[1.7 现场预检](../acceptance/step-1.7.md#阶段-7-现场预检) |
| 开启 | 2026-11-21 |
| 关闭 | 2026-11-22 |

## 现象与影响

在一次性演示实例打开电脑设置页，Windows 报告有专用网络，工作台报告本实例未安装规则。本机管理员批准模式已关闭，Gateway 进程已提升。这台机器当前无法提供阶段 7 要求用户亲眼确认的 UAC 授权。

## 核对方法

只读查看运行进程权限和 Windows 的 UAC 策略。检查工作台防火墙适配器，其写操作通过 `Start-Process -Verb RunAs` 请求提升，以子进程结果判断是否成功。代码没有区分交互确认与系统已授予的权限。本次没有点击开关，也没有执行规则写操作。[Microsoft UAC 策略说明](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/settings-and-configuration/)

## 待决定

建议在工作台能确定 Windows 无法交互确认时，保持本机访问，在执行规则写操作前说明原因。需要同时约定关闭时先断开访问后怎样提示清理既有规则。另一种呈现方式是在设置页直接禁用开启入口并显示原因。两种方式都保留专用网络、UAC 和真机验收要求。

## 验证

待决定后用可注入的权限状态和规则执行器补离线测试，再在能显示 UAC 的 Windows 设备上由用户操作。真机结果由 [ISSUE-0149](ISSUE-0149-lan-phone-acceptance.md) 汇总。

## 时间线

- 2026-11-21 阶段 7 预检发现，登记待选处理方式。
- 2026-11-22 用户选择“点击开启时说明原因”。工作台写规则前只读检查 UAC、当前进程所在桌面、权限和账户对应的提升策略；权限状态读取失败也会阻止写入。删除受阻时保留关闭状态和“更新规则”入口。实际 Windows 配合手机的验收继续记在 ISSUE-0149。
- 2026-11-22 窄屏复验发现错误栏和网卡状态会重复报告同一原因。设置页改为保留错误栏的提醒，状态刷新后仍可查看原因。网卡有其他独立问题时继续同时显示。
