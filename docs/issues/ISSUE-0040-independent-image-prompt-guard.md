# ISSUE-0040：独立任务图片校验未使用自有模型能力

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | step-1.3 正式独立任务接入审查 |
| 开启 | 2026-11-08 |
| 关闭 | 2026-11-08 |

## 现象

正式任务发送路径只从原生适配器注册表取 AgentInfo；独立运行时不在该表内，已知不支持图片的模型未在发布用户消息前返回 415。底层 driver 仍会阻止不支持的图片，没有据此发现外发。

## 复现步骤

1. 创建独立任务，把所选模型的图片能力明确设为 false。
2. 给该任务上传图片并调用正式 prompt；检查是否在记录用户消息、请求模型前拒绝。

## 影响

网页预检之外的调用方不能得到一致的附件拒绝行为。拒绝提示中的“换模型”还需打开独立配置，而非原生模型菜单。

## 根因

TaskService 的附件判断只查询第三方 / 演示适配器，没有查询独立目录的有效能力；输入框的外部切换请求也只驱动原生选择器。

## 处理方式

独立任务从自有运行时生成 AgentInfo，按同一 visionOf 规则提前拒绝；保留 false / null / true、冲突和过期语义。独立输入框接到换模型请求时打开自有配置。新回归使用正式任务、实际上传和本机 HTTP：false 时零请求 / 零原始消息；true 时受限读取图片和文本、请求含编码而事件与原始消息仅留附件身份。

## 验证

定向与最终完整结果追加到 [1.3 验收](../acceptance/step-1.3.md)。真实供应商视觉和当前新增错误按钮的浏览器点击未验证。
