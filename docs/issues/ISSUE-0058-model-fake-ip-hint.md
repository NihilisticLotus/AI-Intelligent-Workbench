# ISSUE-0058：独立 Agent 对话被 fake-ip 规则拦下时没有对应提示

## 现象

开着 fake-ip 代理但没打开开关时，独立任务发消息只显示“模型请求未能可靠完成”，请求记录写“连接失败”。设置页文案却说对话会提示“解析到本机代理的 fake-ip 网段”。

## 根因

model-http.ts 的地址校验失败一律报通用的 network，没有像元数据读取那样区分 fake-ip。

## 处理方式

- protocol 只增 `IndependentNetworkDetail`（目前只有 fake_ip_proxy）和结算记录的可选 `networkDetail`，只能配 network 失败。
- 模型请求的地址校验在“全部地址是 fake-ip 或本来就允许、且开关未开”时带上这个细分，写进请求账本；不记录解析出的地址。
- 网页请求记录显示“连接失败：域名解析到本机代理的 fake-ip 网段（198.18.x），可在‘设置 → 网络’里允许”；设置页文案改为说明提示出现的位置。

## 验证

- protocol、gateway（postModel 关闭 / 混合结果）、web 文案各有用例；设置页新文案在 17890 开发预览里核对。真实任务里的显示未实操（两个工作台的开关都已打开）。
- 顺带发现并修正：原先两条“打开开关后越过地址校验”的用例会真的连接 198.18.0.9。本机开着 fake-ip 代理时，这个连接被代理接走并访问了 example.com（本次全量测试因此失败一次，拿到上游响应）。默认测试必须离线，已改为只在纯函数用例里核对放行，不再实际连接。
