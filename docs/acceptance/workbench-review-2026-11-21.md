## 浏览器实操

- 使用开发预览配置的 Gateway 和浏览器，默认端口 17890，在隔离目录配对临时设备。目录浏览以父、子两个合成目录复现延迟并注入一次 503。原构建可以在等待时确认上一级，修复后读失败时确认按钮禁用，重试成功后添加项目框显示“子目录”。[目录选择截图](assets/workbench-review-20261121-folder.png)
- 在演示任务输入草稿并等到服务端保存，离开后注入一次读取失败。等过自动保存间隔后核对服务端仍有原文，点击“重新载入草稿”恢复。另一个标签页修改并保存后，再进入原页面可继续编辑新内容。[草稿恢复截图](assets/workbench-review-20261121-draft.png)
- 深浅主题分别在 375×812、390×844、412×915、768×1024 打开设置、Agent、新建任务、任务对话、项目设置及看板。逐页检查页面宽度，未出现整页横向滚动。另在桌面浏览器验证目录选择与草稿恢复。
- 回环替身复验包含上述四种尺寸及 812×375 横屏。通过网页配对临时设备、新建任务、发消息、允许演示审批、查看文件差异、停止和打开设置，验证远程改权限时电脑收到二次确认，最后吊销测试设备并关闭替身。桌面本机入口继续可用。

## 回归与反向验证

- 在 Windows 上让六个独立 Node 进程同时接手同一临时数据目录，连续三轮各有一个取得所有权、五个被拒。第一轮直接结束本次实验的持有进程后，下一轮正常接手。实验结束后再次获取并释放成功。

- 残留锁、启动失败、重叠关闭、排队登记失败、事务派生事件、项目多字段写入、工具改动行数、长分页和草稿的回归用例先复现对应错误。
- 在临时源码副本分别撤掉入队失败清理、提交后事件排队、启动器资源检查。三条对应断言均失败，逐一恢复后均通过。文件夹选择另在原构建与修复构建执行同一浏览器操作。
- 同机使用合成的 25,000 条已排序消息，每页 500 条。网页状态的内存归并从 1,274 毫秒降到 5 毫秒。另用 100,500 条复核得到 64 毫秒。这组数字只测内存归并，未计入网络与绘制。
- 已知草稿读取失败时输入新文字，切到设置再回来。旧构建会丢失未保存的文字。离线单测另核对未读回原稿时离开页面不写入空字段、恢复后保留原附件，以及设备会话结束时清理暂存内容。
- 使用固定种子生成 500 组存在实时重叠的历史页，与逐事件归并的结果对照，状态全部一致。另用 500 组多行文本对照独立的完整公共子序列计算，增删数一致。1,600 行完全替换给出精确行数，含公共行且超出比较上限的复杂替换报告未知。
