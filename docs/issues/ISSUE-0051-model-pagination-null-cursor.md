# ISSUE-0051：Messages 模型分页的空游标被当作列表结束

## 现象

模型目录返回 has_more=true / last_id=null 时，原代码先把该 null 视为无需校验，再把它当成没有下一页。可能以不完整列表结束发现。

## 复现步骤

1. 仅使用合成 Messages 响应：data=[]、has_more=true、last_id=null。
2. 经正式 parseEndpointPage 解析。
3. 预期应拒绝分页游标，不能当作完整列表，不为本单调用真实服务。

## 影响

坏分页响应可能被误当正常结束。本次只有源码与离线反例，未确认真实服务曾返回该组合。

## 根因

原校验条件是 next !== null，而 next 同时承担“没有下一页”和“上游明确返回 null”的含义，未依据 has_more 的声明决定是否必须校验。

## 处理方式

当 Messages 明确 has_more=true 时要求合法非空字符串游标，否则拒绝，并使用 ISSUE-0050 的固定 pagination_cursor 分类；has_more=false 仍正常结束。其余分页请求、原地址、上限和快照规则不变。

## 验证

新增针对明确空游标的回归通过，Gateway 定向 36 项通过；类型与构建通过，源码变化后的最终全量结果随后追加。没有 UI 新变化或真实服务请求；合法分页继续由已有跨页集成覆盖。
