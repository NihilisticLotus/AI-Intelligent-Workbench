## 现象

tasks.ts 的无回应看门狗只把事件和待审批算作活动。工具开始后 10 分钟没有任何事件，整轮就以“Agent 10 分钟没有回应”取消。独立命令工具的最大时限也是 600 秒，一条不产生输出、跑满时限的命令会先被看门狗取消，得不到命令自己的超时结果。

## 影响

长时间无输出的构建、打包一类操作会被误判为 Agent 卡死。是否常见取决于各 Agent 是否在工具执行期间持续发事件，尚未实测。

## 处理方式

未改，9.6 的规格就是“10 分钟没有事件自动停止”。建议：有工具处于执行中（已开始未结束）时不计入无回应时间，或单独给一个更长的上限。需要先确认三家 Agent 在长命令期间的事件行为。
