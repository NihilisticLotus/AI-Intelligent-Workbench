## 现象

在网页创建自定义 Responses 账号并发“只回复 OK”，任务在建会话时返回 agent.auth_required，未得到回复。

## 复现步骤

1. 创建 Codex 自定义地址账号，提供有效密钥与手填模型。
2. 在空项目中创建任务并派发极短消息。
3. 建会话失败，网页提示需要登录。

## 影响

仅注入 provider 的 env_key 无法通过锁定版本的前置认证检查。

## 根因

codex-acp 2.5.0 的 CODEX_CONFIG 只作为会话配置传入；readAuthRequirement 在创建会话前检查 app-server 的默认登录，尚未使用会话 provider。独立 CODEX_HOME 没有订阅登录，因此被拒绝。

## 处理方式

按 phase-1 §6.4.2 的后备方案，通过不含密钥的 DEFAULT_AUTH_REQUEST 指定 api-key，密钥另经 CODEX_API_KEY 环境变量传入。由 Codex 自己写入本账号独立目录，不读取或复制已有凭据。界面说明独立目录中的 Agent 凭据与删除行为。清理宿主继承的默认认证和 provider 变量。

## 验证

环境变量回归测试通过；修复后的真实对话尚未验证。用户提供的 Responses 地址为 `/api/v1`，与智谱官方文档一致；根地址 GET 404 不能证明接口地址错误。

## 时间线

- 2026-11-08 开启：真实 Codex 第 3 次消息尝试在建会话时失败，未自动重发。完成后备认证修复，待真实复测。
- 2026-11-08 复测：第 4 次人工消息尝试由 glm-5.3-flash 回复 OK；随后账号“测试”握手、新建会话、读取目录与关闭均通过，没有发送额外测试消息。认证问题已修复，待提交后追记哈希；删除清理另见 ISSUE-0028。
