# ISSUE-0137：切回原 Agent 或强制重新交接丢失模型选择或思考强度

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 高 |
| 发现于 | [1.6 完成后的代码审查](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

在原会话换过模型后，切回可能拿到启动时的旧模型，思考强度也会清空。当前会话强制 H2 同样会清空强度。

## 复现步骤

在离线任务中换模型与思考强度，再发送交接并切回；分别让假适配器支持或不支持 H1。另外在当前会话改强度后强制 H2。

## 影响

下一轮可能实际使用另一模型或费用档位。

## 根因

切回只查询会话启动时的模型；重新交接只传模型。两者均漏用了已保存的强度。

## 处理方式

优先读取交出时记录的模型和强度，保留旧收据的会话模型回退；原生恢复后按适配器报告回写。强制 H2 从当前任务同时取得两个选项。

## 验证

旧实现两种切回都从所选深思模型与高强度回到快模型与空强度；强制 H2 同样清空强度。三项修复后均通过。

## 时间线

- 2026-11-18 代码审查发现，离线回归先失败、修复后通过。
- 2026-11-18 临时库另行验证缺少来源配置快照的旧收据，H1 切回成功，目标仍为原会话记录的模型。
