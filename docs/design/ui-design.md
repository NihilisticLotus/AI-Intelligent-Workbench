## 1. 调研结论摘要

### 1.1 通用原则

- 可用性：按 Nielsen 十条启发式检查，本产品最相关的是“系统状态可见”（任务在跑、在等你、卡住了，一眼能看到）、“用户可控与撤销”（合并前看 diff、可回滚）、“用用户的话说”（“等你审批”而不是“pending”）。[NN/g 启发式摘要](https://media.nngroup.com/media/articles/attachments/Heuristic_Summary1_A4_compressed.pdf)
- 间距：统一 4px 基础单位，常用档位取 8 的倍数，所有内外边距只从刻度里取。[Atlassian 间距](https://atlassian.design/foundations/spacing)、[Designary 间距体系](https://blog.designary.com/p/spacing-systems-and-scales-ui-design)
- 深色主题：用深灰而不是纯黑；层级越高表面越亮，而不是靠阴影；强调色降饱和；正文对比度 ≥4.5:1。[Material 深色主题](https://material.io/design/color/dark-theme.html)、[Material 3 色调表面](https://m3.material.io/blog/tone-based-surface-color-m3)、[深色令牌示例](https://superdesign.dev/styles/dark-mode)
- 色彩生成：在 OKLCH 等感知均匀色彩空间里推色阶，深浅两套共用同一套语义令牌。[色彩体系文章](https://medium.com/@deepikameena315/design-system-color-foundations-why-most-palettes-fail-how-to-fix-them-5b47034cc9d7)
- 可访问性：WCAG 2.2 AA。文字 4.5:1，图标、输入框边框、焦点框等非文字元素 3:1；焦点不能被遮挡（2.4.11）；焦点框做到 2px（2.4.13 为 AAA，成本低）。[W3C WCAG 2.2 新增项](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)、[焦点外观](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance-minimum.html)、[对比度检查](https://blog.openreplay.com/check-color-contrast-wcag/)

### 1.2 Agent 工作台类产品

- Codex 桌面版：线程按项目归组，单窗口内并行多个线程；diff 面板可以对代码块加评论让 Agent 处理，可按块暂存或还原。[Codex app 功能](https://developers.openai.com/codex/app/features)、[worktree](https://developers.openai.com/codex/app/worktrees)、[发布介绍](https://openai.com/index/introducing-the-codex-app/)。用户反馈要求在线程里显著显示项目、目录和分支。[issue #28977](https://github.com/openai/codex/issues/28977)
- Cursor：Agent 回复结束后提供“Review changes”看完整 diff；社区反复抱怨“自动写盘、没有逐处接受/拒绝”，说明审查环节不能省。[Cursor Diffs & Review](https://docs.cursor.com/en/agent/review)、[论坛反馈](https://forum.cursor.com/t/regression-ai-edits-applying-automatically-without-diff-approval-ui/154887/1)
- Zed：工具权限分“允许一次 / 总是允许 / 拒绝”。两个教训：“总是允许”必须只作用于这一类操作；连续消息会把审批提示滚出视野、任务静默卡住。[Zed 工具权限](https://zed.dev/docs/ai/tool-permissions)、[#30313](https://github.com/zed-industries/zed/issues/30313)、[#57679](https://github.com/zed-industries/zed/issues/57679)
- vibe-kanban、Conductor、Crystal 一类：把 Agent 当作“异步工人”管理，看板按状态排列，注意力转向“准备好了要审查”的任务。[vibe-kanban](https://vibekanban.com/)、[VirtusLab 评述](https://virtuslab.com/blog/ai/vibe-kanban/)、[多 Agent 工具对比](https://nimbalyst.com/blog/best-multi-agent-coding-tools-2026/)、[worktree 工具对比](https://nimbalyst.com/blog/best-git-worktree-tools-ai-coding-2026/)、[桌面 Agent 环境对比](https://developertoolkit.ai/en/ecosystem/agent-tools/agent-shells/)（这类工具 2026 年内改名、停更频繁，只借鉴模式）
- Linear：基于 Radix，深浅色可手动切换；侧栏 + 主区的轻量结构是本版布局的主要参照。[LogRocket 文章](https://blog.logrocket.com/how-do-you-implement-accessible-linear-design-across-light-and-dark-modes)

### 1.3 游戏引擎与 DCC 编辑器

调研过 Blender、Unreal、Godot 的停靠面板体系。[Blender HIG](https://developer.blender.org/docs/features/interface/human_interface_guidelines/paradigms/)、[Unreal Content Browser](https://dev.epicgames.com/documentation/en-us/unreal-engine/content-browser-in-unreal-engine)、[Godot 界面](https://docs.godotengine.org/en/latest/getting_started/introduction/first_look_at_the_editor.html)。结论是这套体系适合长时间编辑场景，对“派活、审查、验收”的工作台太重，本版不采用。只保留三点：

- 预览背景用中性灰，不带色偏，方便判断材质颜色。
- 三维查看的操作习惯：拖动旋转、右键平移、滚轮缩放，`F` 对准对象，可选 Blender / Unity / Unreal 导航习惯。
- 不弹阻塞对话框：预览、对比都在面板或查看器里完成，随时可关。

### 1.4 实现选型

- 可调分栏：react-resizable-panels 当前活跃维护，2026-11-05 刚发布 4.18.1，10 月下旬以来几乎每天一个版本，MIT 许可；v4 支持像素、rem、vw 等单位，面板可折叠，自带布局持久化钩子，拖动条支持键盘；shadcn/ui 的 Resizable 组件就是基于它。[npm](https://www.npmjs.com/package/react-resizable-panels)、[Releases](https://github.com/bvaughn/react-resizable-panels/releases)、[CHANGELOG](https://github.com/bvaughn/react-resizable-panels/blob/main/CHANGELOG.md)、[shadcn Resizable](https://ui.shadcn.com/docs/components/resizable)、[键盘调整说明](https://www.shadcn.io/ui/resizable)
- 调研过但不再采用的停靠库：dockview（零依赖，支持浮动、弹出窗口）、FlexLayout、rc-dock。[dockview](https://dockview.dev/)、[FlexLayout](https://github.com/caplin/FlexLayout/blob/master/README.md)、[rc-dock](https://github.com/ticlo/rc-dock)
- 三维：three.js 最新为 r186（2026-09）；`WebGPURenderer` 可自动回退 WebGL 2。[three.js 2026 变化](https://www.utsubo.com/blog/threejs-2026-what-changed)、[WebGPURenderer](https://threejs.org/manual/pages/webgpurenderer)、[迁移清单](https://www.utsubo.com/blog/webgpu-threejs-migration-guide)。Tauri 早期答复是 WebView2 的 WebGPU 只在非稳定通道可用。[tauri #6381](https://github.com/tauri-apps/tauri/issues/6381)（结论偏旧，需在目标机器实测）。react-three-fiber + drei 提供 glTF 加载等组件。[R3F 加载模型](https://github.com/pmndrs/react-three-fiber/blob/master/docs/tutorials/loading-models.mdx)、[drei](https://github.com/pmndrs/drei)、[R3F 与 three 对比](https://www.creativedevjobs.com/blog/react-three-fiber-vs-threejs)
- 组件库：shadcn/ui 是复制进项目、可自己改的组件集，底层是无样式可访问原语；2026 年 7 月起默认原语从 Radix 换成 Base UI。[shadcn 与 Radix](https://designrevision.com/compare/radix-ui-vs-shadcn)、[Base UI 对比](https://www.untitledui.com/blog/untitled-ui-vs-base-ui)、[Base UI vs React Aria](https://www.untitledui.com/blog/base-ui-vs-react-aria)、[Base UI vs Radix](https://bestsky.tools/blog/base-ui-vs-radix-ui)

### 1.5 设计方法

- 按 `frontend-design` 技能的流程：先定令牌和布局草图，对照“生成式界面的常见套路”自查（奶油底配陶土色、纯黑底配荧光绿、一律同圆角同阴影的卡片、全大写小标签、“A · B · C”元信息串），再动手。
- 本版的“减法”自查：每条分割线、每个边框都问一句“去掉会不会看不清分组”，能用间距或底色区分的就不用线。

## 2. 设计原则

1. 轻量为先。默认只有侧栏和主区；右侧面板在需要看改动、计划、预览时才出现，用完收起。不出现多层工具栏和成排的标签页。
2. 等你的事最显眼。只有“需要你处理”的东西用琥珀色：待审批、登录过期、未验证版本。其他状态都安静。
3. 审批永远看得见。审批卡片在对话里出现，同时固定在输入框上方，侧栏顶部常驻“等你处理”入口（侧栏折叠后保留徽标），一键跳过去；超时倒计时写明。审批不抢焦点，避免打字时按回车误放行。
4. 看清楚再合并。所有改动先进右侧“改动”；模型等资产的改动用三维对比查看。合并、丢弃、回滚前都能看到改了什么。
5. 中性灰给美术资产让路。界面底色不带色偏，预览背景为严格中性灰，界面色彩不干扰对模型和贴图颜色的判断。
6. 点一下就能做，不需要命令行。工作台安装、配置、排错都有按钮；第三方登录和 API 配置引导到该软件自己的界面，工作台提供返回后重新检测的入口。错误统一写成“发生了什么 + 怎么处理 + 按钮”。命令只作为详情展示，不要求用户复制执行。
7. 说清楚切换的代价。换模型、换账号、换 Agent 前，切换器写明“会话内切换（无损）/ 恢复会话（无损）/ 交接（有损）”，与 design.md 第 7.4 节切换算法、15.2 节的提示文字一致。
8. 状态不只靠颜色。每种状态同时有形状（圆点、菱形、方块、空心圈）和文字。

## 3. 设计令牌

### 3.1 色彩

深色为默认，浅色是完整的第二套，不是反相。所有颜色以 CSS 变量提供，Tailwind 引用变量。本版色值不变，只改了用法：分区靠底色深浅，少用线。

| 令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| `bg-0` | `#1e1f22` | `#dcdddf` | 侧栏、输入框、代码底等凹陷区域 |
| `bg-1` | `#26272b` | `#f4f4f3` | 主区、右侧面板 |
| `bg-2` | `#2e3035` | `#ffffff` | 卡片、弹出层、用户消息 |
| `bg-3` | `#383a40` | `#e9e9ea` | 悬停、选中、次要按钮 |
| `bg-viewport` | `#333333` | `#8c8c8c` | 三维预览，严格中性灰 |
| `line` / `line-strong` | `#3e4047` / `#565961` | `#d2d3d6` / `#a9abb0` | 少量分割线 / 输入框边框（≥3:1） |
| `fg-1` / `fg-2` / `fg-3` | `#ecece9` / `#bcbdc0` / `#9c9ea3` | `#1c1d20` / `#45474d` / `#5f6168` | 正文 / 次要 / 最弱（仍 ≥4.5:1） |
| `accent` 靛 | `#8b95ff`（配深色字） | `#4a55d6`（配白字） | 焦点、选中、主操作 |
| `attn` 琥珀 | `#f2b646` | `#9a6200` | 只用于“需要你处理” |
| `ok` / `err` / `info` | `#62c98e` / `#f27676` / `#6cb6e8` | `#1f8a52` / `#c43838` / `#22709f` | 成功 / 失败 / 运行中 |
| diff 增删 | 绿 / 红 13% 透明底，词级 32% | 10% / 26% | diff 行与词高亮 |

Agent 身份色（用户可改，必须和字母徽标同时出现）：Claude Code `#e8a07c`（C），Codex `#56c2c8`（X），CodeBuddy `#b896f6`（B），ZCode `#a2cf63`（Z）。刻意不用各家官方品牌色。

线的使用只剩三处：拖动条（平时 1px，悬停加粗为靛色）、输入框边框（可访问性要求）、交接分隔条。面板、卡片、列表都不画边框。

### 3.2 字体

| 角色 | 字体 | 说明 |
|---|---|---|
| 界面 | Microsoft YaHei UI → PingFang SC → system-ui | 用系统字体，不打包中文字体（体积 10MB 以上） |
| 代码、路径、命令 | JetBrains Mono（随应用打包，OFL 许可）→ Cascadia Mono → Consolas | 只用于真正的代码和路径 |

字号刻度：12（辅助信息）、13（列表、工具调用、代码）、14（正文，基准）、16（标题）、20（页面大标题）、26（入口页）。正文行高 1.6；代码行高固定 20px。字重只用 400 和 600。对话列随主区变宽，最宽 1200px，两侧留 16～40px 边距，居中；正文不再单独限宽（用户反馈宽屏两侧留白太多、内容挤，2026-11-06）。

### 3.3 间距、圆角、阴影、动效

- 间距：4、8、12、16、24、32、48。主区左右留 24；消息之间 16；卡片内边距 12～16；页面类内容（Agent 管理、设置）最宽 1040px 居中。
- 圆角：控件 6；卡片 8；弹出层、对话框、输入框 12；徽标、筛选标签全圆角。
- 阴影：深色下靠表面亮度表达层级；只有弹出层、抽屉、提示有阴影（`0 12px 32px` + 1px 淡描边）。卡片没有阴影。
- 动效：120ms（悬停、按下）、180ms（展开、提示）、260ms（侧栏折叠、抽屉滑出）。缓动统一 `cubic-bezier(0.2, 0, 0, 1)`。持续动画只有运行中状态点的脉冲、生成中的三点和预览的自动旋转。遵守 `prefers-reduced-motion`，此时预览不自动旋转。

## 4. 整体布局

### 4.1 三块区域

```
┌──────────┬──────────────────────────────┬┬─────────────────┐
│ 侧栏      │ 主区头部：标题 状态 分支  [对话|看板] ▣ ││ 右侧面板（按需）  │
│ 新建任务  │                              ││ [改动][详细][预览] ×│
│ 等你处理 1│   对话（最宽 1200，居中）       ││                 │
│ 搜索      │   或 看板                     ││                 │
│ 任务      │                              ││                 │
│ 资产      │                              ││                 │
│ Agent    │   [待审批条]                  ││                 │
│ 项目/任务 │   [输入框 + 切换器]            ││                 │
│ 服务状态  │                              ││                 │
└──────────┴──────────────────────────────┴┴─────────────────┘
  252px，可折叠为 60px 图标栏     自适应          ↑拖动条  320px～62vw，默认 440
```

- 侧栏：顶部是新建任务、“等你处理”、搜索；中间是页面入口（任务、资产、自动化、监控、能力、Agent，设置在底部）；下面是“项目”区（见下）。折叠后变成图标栏，“等你处理”保留徽标数字。`Ctrl+B` 切换，状态按设备记住。
- 任务列表有两种归类方式，用标题行的 [项目 | 分组] 切换，选择按设备记住，侧栏和看板共用同一个设置：
  - 按项目：一个项目对应本机的一个文件夹，任务归在所属项目下面。
  - 按分组：分组是用户自建的标签，和项目无关，不同项目的任务可以放进同一个分组，一个任务最多属于一个分组。没有分组的任务统一放在最下面的“未分类”。分组可以新建、重命名、删除（删除后任务回到未分类，任务本身不删除）。
  - 移动任务到分组：任务行悬停出现 [… 更多]（也可右键），菜单里列出“移到分组 X”“新建分组并移入”“移出分组”；分组视图下也可以直接把任务拖到另一个分组上。
  - 排序：无论哪种归类，组内任务都按最近活动排序（你发消息、Agent 有新输出都算活动），最近的在最上面。项目和分组本身保持用户的顺序，不随活动跳动。
  - 任务行第二行：按项目时显示“状态 · Agent · 时间”，按分组时显示“状态 · 所属项目 · 时间”。
- 看板顶部同样有 [按项目 | 按分组] 切换，下面的筛选按钮随之变成项目列表或分组列表（含“未分类”）。看板各列按最近活动排序；“排队中”一列例外，保持执行顺序，可拖动调整。
- 项目区细节：
  - 标题行右侧有 [全部折叠/展开] 和 [+]：按项目时是“添加项目”，按分组时是“新建分组”。添加项目时用系统文件夹对话框选目录，自动检测是否 git 仓库、是什么引擎的工程。
  - 项目行：展开箭头、文件夹图标、项目名、任务数。点整行折叠或展开，折叠状态按设备记住；悬停时任务数换成 [+ 在此项目新建任务] 和 [… 更多]。鼠标悬停项目名显示文件夹路径。
  - 更多菜单：在此项目新建任务、在资源管理器中打开、在 IDE 中打开、项目设置、只看这个项目（折叠其他）、重命名（只改显示名）、从列表移除（不删除文件，二次确认）。
  - 任务行缩进在项目下：Agent 徽标（悬停显示全名）+ 标题；第二行是状态、Agent 名称、最近活动时间。项目超过 8 个任务时只显示最近 8 个，末尾一行“显示其余 N 个”。
- 主区：对话或看板二选一，用头部的“对话 / 看板”切换。头部只放标题、状态、分支、视图切换和右侧面板开关。
- 右侧面板：固定四个标签“改动 / 详细 / 预览 / 侧聊”（侧聊见 5.15）。“详细”（原“计划”，2026-11-07 改名）依次是环境、计划、上下文、会话 token 用量、连接、输出，对应 design.md 15.1 的“上下文”，规格见 6.13。宽度可拖动，拖动条聚焦后可用方向键调整；`Ctrl+J` 或右上角 × 收起。
- 不做多窗口、浮动面板和布局预设。宽度和开合状态只存在本机，不需要服务端接口。

### 4.2 右侧面板什么时候出现

| 场景 | 行为 |
|---|---|
| 打开一个有改动的任务 | 自动打开，停在“改动” |
| 点工具调用里的 [在改动面板中查看] | 打开并跳到对应文件 |
| Agent 修改了资产文件 | 对话里出现资产卡片；点卡片打开“预览”。如果预览已经开着同一文件，自动刷新 |
| 看板里点任务卡片 | 打开显示任务摘要，[打开对话] 进入对话视图 |
| 用户手动收起 | 记住这个选择，同一任务不再自动打开，直到用户再次打开 |

### 4.3 看板是主区的一个视图

看板和对话共用同一个外壳：同一个侧栏、同一个右侧面板。切换视图不改变侧栏和右侧面板的状态，也不是单独的“模式”。

### 5.1 工作台：对话视图（原型：`workbench.html`）

- 右侧“详细”：环境、计划、上下文、会话 token 用量、连接、输出（6.13）。
- 右侧“改动”：文件列表、diff、底部“测试通过后自动合并”开关（默认关，见 5.13）和 [丢弃任务…] [在 IDE 中打开] [合并到 main…]。

### 5.2 工作台：看板视图（原型：`kanban.html`）

- 列：排队中、运行中、等待审批、待验收、失败或中断、已完成（近 7 天，紧凑列表）。列之间用间距分开，不画线。

- “等待审批”卡片可直接 [允许]；“失败”卡片内嵌错误提示和恢复按钮。点卡片在右侧看摘要。

### 5.5 Agent 管理（原型：`agents.html`）

当前实现范围（2026-11-08）：正式页在第三方卡片上方单列“工作台独立 Agent”。可添加 / 编辑 / 停用 / 删除服务与模型，配置三种协议，密码框只写 Key，默认值单独设置或清空；目录刷新只读本地已保存资料。能力面板覆盖全部 16 字段，显示逐字段值、来源、日期、范围、冲突、过期及旧配置记录；只提交编辑的字段，人工 false / 零 / 空列表与未知分别保留。高级信息折叠；改为无认证会删除旧 Key，需先勾选确认。并发冲突时保留草稿并禁止覆盖，点击“放弃输入并载入最新版本”后重新编辑；能力写入同时核对模型与服务配置修订。在线获取 / 搜索 / 批量加入和运行时仍属下列待实现规格，不能把手填目录算作自动识别完成。原型只演示当前配置流程，不收集 Key、不联网，刷新后恢复示例。原因与验证见 [当日开发笔记](../devlog/2026-11.md) 和 [1.3 验收](../acceptance/step-1.3.md)。

- 启用开关（2026-11-07 用户要求：不一下子全部接进来）：
  - 每个 Agent 一个开关。默认 Claude Code、Codex 打开，CodeBuddy、WorkBuddy、ZCode 关闭。用户的选择保存在 Gateway，所有设备一致。
  - 页面分两块：“已启用 N 个”是状态卡片；“其他 Agent”是本机检测到但关着的，一行一个：徽标、名称、来源和版本、“已关闭”、开关。
  - 关闭的 Agent 不检测登录、不做探测会话、不出现在新建任务和切换器里，也不占并发。只做一次很轻的“装没装”检查，用来在“其他 Agent”里列出来。
  - 打开后立刻检测；ZCode 这类需要桥接的，打开后直接跑一次连接测试，结果写在详情区的“测试连接”里。
  - 关闭正在运行会话的 Agent 先确认：运行中的会话照常做完，不再接新任务；已有任务的记录保留，随时可以再打开。
  - 全部关闭时卡片区显示“还没有启用任何 Agent”，并隐藏详情区。
- 上方每个已启用的 Agent 一张状态卡片：徽标、名称、来源、状态、版本、自身登录状态，右上角是启用开关。第三方 Agent 未登录时显示“请在该软件中登录”与配置指引、[重新检测]；工作台不代为切换其登录或 API。安装、更新和连接测试保留各自入口。
- ZCode（本机已装 0.17.1）：来源写“应用内置引擎”。ZCode 没有 ACP 模式，接入 zcode-acp 桥接之前（ISSUE-0020、docs/research/zcode-acp.md）状态为“暂不支持”，说明还不能对话。测试连接逐步显示：找到引擎 → 读取版本 → 启动 app-server → 开始对话（目前不通过，写明原因）。接入桥接后按其他 Agent 一样检测和测试。
- 第三方 Agent 详情展示“沿用该软件自身设置”、模型来源、当前会话可选模型、并发上限、引擎位置、[测试连接] 的逐步结果；不提供替换其认证的“官方 API Key / 自定义地址 / 第二个订阅账号”表单。
- 增加单独的“AI Console 独立 Agent”卡片与详情。其“API 服务与模型”区域提供 [添加服务]、[添加模型]；服务表单填写名称、协议、地址、密钥，模型可以获取或手填。密钥只显示是否已保存和末四位，说明“已加密保存在工作台”。添加时保留现有服务和模型，设为默认是单独的明确操作。
- 多个 API 服务分别列为可展开的服务项，每项有自己的模型列表；相同远端模型名可在不同服务下共存。获取列表后搜索 / 勾选 / 批量加入，只追加所选模型；刷新展示新增、信息变化与冲突，不静默删除现有模型、覆盖手动字段或切换默认服务。
- 模型行显示上下文、图片、工具和思考的摘要，未知明确写“未知”；展开“能力详情”查看总窗口 / 最大输入 / 最大输出、模态、推理选项、流式和用量支持。每字段显示“接口声明 / 官方文档 / 公共目录 / 手动设置”、日期和冲突，不能把资料补全写成“实测通过”。提供手动修订与 [恢复自动]，明示只作用于当前服务与模型。
- 获取模型列表、地址可达和真实模型验证分别显示结果；验证模型单独提示将向哪个服务发送什么，以及调用上限和预计费用。自动识别不暗中发图片、遍历推理参数或试填长上下文。目录失败保留旧资料与过期状态，仍可手动添加。
- 测试服务连接不发模型消息；付费测试消息单独操作并提示。服务失败留在该服务显示原因，不回退使用第三方 Agent 的账号。独立执行器未就绪时显示“尚未实现”，不把演示回复或第三方代理调用包装为独立 Agent 成功。
- CodeBuddy 和 WorkBuddy 是两张独立的卡片（2026-11-07 用户决定，design.md 6.1）：
  - CodeBuddy：来源写“工作台自带的官方独立版引擎”，版本 2.181.0（已验证）。使用该引擎自身的配置与认证；工作台提供配置指引和重新检测，不替换认证。不能将 CodeBuddy 卡片当作 AI Console 独立 Agent 的 API 设置入口。
  - WorkBuddy：来源写“WorkBuddy 内置引擎”，账号写“在 WorkBuddy 里登录”，工作台不提供登录按钮。只带精简引擎（2.165.0 起）时状态为“暂不支持”（红方块 + 文字），卡片里写明原因：这个版本只带给 WorkBuddy 自己用的精简引擎，工作台暂时无法驱动；附 [重新检测]。
- 安装与连接过程在卡片内显示进度，脱敏日志折叠在“查看详情”里。已有工作台代登录流程需要退出并保留真实结果；此次整改后不在第三方 Agent 卡片新建工作台管理的认证。

### 5.6 项目记忆、插件

- 项目记忆：列表 + 筛选（固定、失效），每条可编辑、固定、标记失效；任务合并后弹出候选条目让用户勾选（design.md 7.3、15.1）。

### 5.7 项目设置

单列表单页，分区：基本（名称、路径、是否 git、[在资源管理器中打开]）、默认 Agent/账号/模型、忽略目录（标签式输入，Unity/Unreal 项目自动推荐 Library、Temp 等）、权限规则（表格，可拖动排序，每条注明来源，如“审批时点了总是允许”；全局“始终禁止”清单只读置顶）、资产（资产目录、资产备份开关及预计占用空间，design.md 11.5）。

### 5.8 设备与访问

局域网开关（关闭时写明“只有这台电脑能访问”）；打开后选网卡，显示地址和二维码；公用网络时开关禁用并说明原因。[配对新设备] 显示 6 位配对码和二维码、倒计时。已连接设备列表带 [吊销]，审计日志单独一节。

### 5.9 诊断

顶部一句总体结论（“一切正常”或“2 个问题”）。下面是检查项：服务进程、数据库、端口、各 Agent 引擎与登录、磁盘空间。每个问题给修复按钮：端口被占用 → [换一个端口]；引擎位置变化 → [重新定位] [手动选择]；服务多次重启失败 → [查看日志] [重启服务]。右上角 [导出诊断包]，完成后显示文件位置和 [在资源管理器中显示]。

分组：外观（深色 / 浅色 / 跟随系统，界面缩放 90%～125%）、通知、任务（并发上限、审批超时、清理策略）、三维预览（导航习惯 Blender / Unity / Unreal、背景灰度）、快速判断（见 5.13）、快捷键、关于与更新。

### 5.11 自动化（原型：`automations.html`）

侧栏导航“资产”之后；窄屏底部导航同样有入口。复用侧栏的项目数据，不另设项目列表。

- 列表：表格语义，行只用底色区分。列：启用开关（`role="switch"`，旁边写“启用 / 暂停”）、名称 + 所属项目、触发方式的中文描述（“每天 02:00”“工作日 09:30”“Assets/Art 有新 FBX 时”“‘每晚全量构建’成功后”）、Agent 徽标 + 模型、下次运行、最近结果（成功 / 失败 / 跳过，形状 + 文字）、[… 更多]。上方按项目筛选。Agent 登录过期时“下次运行”一格改为琥珀菱形 + 原因。主区变窄时先收起“Agent 与模型”列，窄屏改成卡片。
- 点一行，右侧面板显示详情与运行历史。详情：[立即运行一次] [编辑] [暂停 / 启用] [更多]、要做什么（变量显示为胶囊）、触发、接下来 3 次时间、Agent / 账号 / 模型 / 思考强度、权限、运行规则、完成后。运行历史每条是一个普通任务：状态、时间、耗时、一句结果、[打开对话]；跳过的写明原因（“上次还没跑完，已跳过”“电脑在休眠，已错过”），不生成任务；失败的附快速判断的严重程度。
- 行操作：立即运行一次（Agent 不可用时给出配置指引与 [编辑自动化]；第三方登录在其自身软件中完成后重新检测，上次未结束时按运行规则跳过或排队）、暂停 / 启用、复制（副本默认暂停）、删除（二次确认，写明运行记录保留、依赖它的“完成后运行”会失效）。
- 新建 / 编辑对话框，分四节，全部用表单控件，不出现 cron：
  - 做什么：名称、项目、要做什么 + [插入变量] 按钮（日期、变化的文件、上次运行结果、项目名）。
  - 什么时候运行：一次性（日期时间）/ 重复（每天、工作日、每周几（多选胶囊）、每月几号或最后一天、每隔 N 小时，加时间点）/ 文件变化（选文件夹 + 文件类型多选，同一批改动合并的等待时间）/ 任务完成后（选另一条自动化，“成功后”或“无论成败”）。下方实时显示“接下来 3 次运行”，文件触发显示“没有固定时间”。
  - 谁来做：Agent、账号、模型、思考强度（Agent 不支持时禁用并说明）、权限，默认“工作区内自动”；选“全自动”二次确认。
  - 运行规则：上次没结束跳过 / 排队；休眠错过醒来补跑 / 跳过；单次最长时间；单次额度上限（订阅账号按周额度百分比，API Key 按美元）。
  - 完成后：每次通知（默认）/ 只在失败时 / 按快速判断的严重程度（“中”及以上才通知；“自动化结果分级”关闭时禁用）。“生成的任务默认测试通过后自动合并”是每次运行生成任务的初始值，默认关，开启二次确认。

### 5.12 监控（原型：`monitor.html`）

侧栏导航“自动化”之后。单列页面，最宽 1120px，从上到下：

- 概览数字：运行中任务、等你处理（琥珀描边 + [去处理]）、今日失败（[看失败记录] 跳到事件并筛选）、今日用量（各账号额度占比条，≥80% 变琥珀并写“超过 80%”）、今日预估费用（只算 API Key 账号）。

- Agent 健康：表格列出进程状态、内存、会话数（已用 / 上限）、额度剩余、最近错误，行内按钮随状态变化：[查看配置指引] [重新检测]、[查看日志] [重启进程]、[去 Agent 管理]。第三方不提供工作台重新登录按钮。
- 任务表现（近 7 天）：每个 Agent 的成功率、平均耗时、卡住次数（10 分钟没输出）、被你拒绝的审批次数。
- 判断准确度：每类快速判断近 7 天被纠正的比例（计数 + 百分比 + 条形），任何地方点 [不同意] 都实时计入。
- 可能卡住或在原地打转：快速判断的检测结果，每条有 [打开对话] [继续等待] [中断…]。
- 告警规则：列表，每条有启用开关、条件、范围、通知方式，正在触发的规则显示琥珀菱形 + 现值；[更多] 里有编辑、发测试通知、删除。新建对话框：条件下拉（额度超过 N%、任务卡住超过 N 分钟、自动化连续失败 N 次、工作副本占用磁盘超过 N GB、Agent 进程崩溃、今日预估费用超过 $N）→ 阈值 → 范围 → 通知方式多选（系统通知、侧栏“等你处理”、已配对的手机、提示音）→ 启用；底部实时预览这条规则的一句话说明。
- 最近事件：时间线，筛选 [全部 | 只看失败 | 告警 | 崩溃恢复 | 自动化]，每条有状态形状、时间、类型、一句说明和相关按钮。
- 右上 [刷新]：刷新时保留旧画面并降低不透明度，不闪骨架屏。

标题旁两个标签：[概览]（上面这些内容）和 [调用统计]（对应 design.md 23.4，地址带 `#stats` 时直接打开）。调用统计从上到下：

- 筛选条（滚动时吸顶，窄屏不吸顶）：时间范围 [今天 | 7 天 | 30 天 | 自定义]（自定义显示两个日期框，只能选最近 90 天，开始晚于结束时提示并还原）、分组维度下拉（Agent / 模型 / 账号 / 项目 / 分组 / 来源）、[导出 CSV]（当前时间范围的逐任务明细，UTF-8 带 BOM，以 `= + - @` 开头的值加单引号防公式注入）。筛选作用于下面所有区块；下方一行写明统计范围和样本量。
- 概览数字一行：任务数、成功率、轮次数、工具调用数、MCP 调用数、总 token、预估费用。
- 每日调用量（占满宽度）：平滑曲线（单调三次插值，不冲过数据点、不低于 0），横轴按天，“今天”按小时，30 天时刻度按宽度稀疏；指标 [任务数 | 轮次数 | 工具调用数 | MCP 调用数 | token]。按分组维度每个实体一条线，超过 6 条时取当前指标前 5 名 + 灰色“其他”；“合计”是 3px 粗虚线 + 空心圆。线 2px，每个色位配固定标记形状（只画在线尾和读数处），颜色沿用 8 色图表色板。图例是按钮，可隐藏 / 显示线；悬停显示竖向参考线和提示框，读数区可 Tab 聚焦，左右键逐日（逐小时）移动、回车下钻；[图表 | 表格] 的表格行是日期、列是各条线。某个 Agent 当天掉为 0 且原因已知时（示例：Codex 登录过期）在点上加引线标注。
- 四层统计，每块右上 [图表 | 表格]：任务（按维度横向堆叠条形，成功 / 失败 / 丢弃 / 中断）、轮次（按时间堆叠柱：今天按 2 小时、45 天以内按天、更长按周；表格里分输入 / 输出 / 缓存命中 / 思考 token）、工具调用（按维度堆叠读取 / 搜索 / 修改 / 新建 / 执行；表格另附按类型的失败率和耗时）、MCP / Skill（调用次数前 10 名，按维度堆叠，可切 [按工具 | 按服务器]；下方单列“装了 30 天没用过”，每条 [去能力页]）。
- 不报告的 token 写斜体“未报告”，不写 0；分组里只有部分 Agent 报告时，数值下加“部分未报告”。
- 模型对比：只有表格，上方写“只展示数据，不做推荐”；可按同类任务（项目 · 分组）筛选；样本少于 10 的行在样本数下加琥珀菱形 + “样本少，仅供参考”；按 Agent 固定顺序排列，不按成功率排序。
- 切换与交接：一行小数字（换模型、换账号、换 Agent、探针平均分、守卫告警），图表是每行归一到 100% 的 H0–H4 占比条（第一行“全部”）。快速判断的开销：调用次数、token、费用，以及按判断类型的表格。
- 下钻：表格任意一行（行首是按钮，键盘可达）、图表任意一行或一根柱子（Tab 聚焦，回车）都会打开右侧面板，按任务汇总列出示例任务，标题链接到 `workbench.html?title=…`；Esc 或 [×] 关闭，焦点回到触发处。
- 图表规格同“用量”：8 色图表色板按实体固定顺序分配，图例常驻，悬停或聚焦显示提示框，每张图的数据都能在表格里看到。

### 5.13 快速判断

参照 Jev 一类模型：只返回结构化的“结论 + 概率 + 一句依据”，不生成文字。

- 统一组件：一行浅底条，依次是“快速判断”标签（悬停显示所用引擎）、状态形状 + 结论、概率、“依据：…”、[不同意]。[不同意] 是切换按钮（`aria-pressed`），点了结论加删除线，提示“已记录，会用于调整阈值”，计入监控页的判断准确度；再点撤销。
- 出现位置：
  - 审批卡片：事实表下方“风险评估：低 · 87%”+ 依据；事实表多一行“自动允许”，写明这条为什么没有自动放行（把握度不足 90%、本任务已关闭、判断已关闭）。
  - 新建任务：写了描述后显示“推荐 Agent：CodeBuddy 81%”+ 依据和 [采用推荐]，采用后按钮变为“已采用推荐”。
  - 任务完成：对话里“完成度判断：已满足验收标准 3/3 · 88%”。
  - 自动化运行历史：失败或有问题的运行附“严重程度：高 / 中 / 低”，用于决定是否通知。
  - 监控页：卡住或原地打转的检测结果。
- 低风险自动允许（按任务）：输入框下方工具条、权限级别按钮旁边，一个“低风险自动允许 ✓”芯片，默认开（取设置里的默认值）。点开是说明对话框，可关闭或重新开启。规则：只放行判断为低风险、把握度 ≥90%、且只作用于工作副本内的操作，永远不会越过“始终禁止”清单。每次自动放行在对话里留一行“已自动允许（低风险 · 96%）：执行 …”+ [撤销此类自动允许]（撤销后同类操作在本任务里重新询问，并计为一次纠正）。“审批风险”判断关闭时芯片显示“不可用”。
- 测试通过后自动合并（按任务）：放在右侧“改动”面板的合并区，[丢弃] [合并] 上方一个开关，默认关，开启要二次确认，说明合并前仍检查冲突、有问题改为通知。放在合并区而不是输入框工具条，是因为它和合并按钮是同一件事，开关在旁边看得到后果；工具条只留和“下一步怎么执行”有关的控制。
- 设置“快速判断”一节：
  - 判断引擎三选一：已有账号或 API 的便宜模型（默认，结构化输出，不用下载但消耗额度，可选具体账号和模型）/ 本机小模型（不出网，需先下载模型文件，未下载时不能保存）/ Jev API（需要 API Key；显著的琥珀提示“判断的内容会发到 TypeSafe AI 的服务器”，并可按项目关闭，关闭的项目改用已有账号的模型）。
  - 每类判断单独开关：审批风险、Agent 推荐、完成度、卡住检测、自动化结果分级。关闭后对应位置不显示判断，依赖它的功能（低风险自动允许、按严重程度通知）一并禁用并说明。
  - 新任务的默认值：是否开启“低风险自动允许”（默认开）。

### 5.14 能力页（原型：`capabilities.html`）

侧栏导航“监控”之后、“Agent”之前；窄屏底部导航同样有入口。依据 design.md 第 25 节，示例数据用本机盘点到的 MCP 和 Skill 名称。

- 顶部：一句说明“把各 Agent 的 MCP 和 Skill 收拢到一处，所有 Agent 都能用”+ 上次整合时间，右侧 [扫描本机 Agent]。下方是“发现新的 MCP”提示条（[整合] 先确认来源、命令、变量名；[忽略]）。再下面是 [MCP | Skill] 两个标签。
- MCP 列表：名称（出错时下面写原因）、类型 stdio / http、状态（运行中 / 已停止 / 出错 / 启动中，形状 + 文字）、提供给（5 个 Agent 字母徽标，已分配实心、未分配空心描边）、并发（共享 / 锁形图标 + 独占）、最近调用（时间 + 带前缀的工具名）、启用开关（旁边写“启用 / 停用”）、[… 更多]。blender、houdini、renderdoc 默认独占，悬停和详情里说明“连着正在运行的桌面软件”。上方 [新建 MCP]：名称、类型、命令或地址、环境变量（变量名 + 密码框，提示“保存到 Windows 凭据管理器”）、提供给。
- MCP 详情（右侧）：[测试连接]（对话框里逐行显示启动、握手、列出工具，失败写原因）[重启] [编辑] [停用 / 启用] [更多]；来源（“Codex · ~/.codex/config.toml”，另列其他同名配置的位置）、启动命令（只显示命令和参数）、环境变量（只显示变量名 +“已存入凭据管理器”）、工具列表（`服务器__工具` 前缀）、最近调用、每个 Agent 的提供方式（ACP 注入 / 已写入 Agent 配置 / 原样同步，各附一句说明）。编辑：分配给（勾选框）、并发方式、命令和参数。移除二次确认，写明不会改动各 Agent 自己的配置文件。
- Skill 列表：名称（有待确认脚本时加琥珀菱形“脚本待确认”）、描述、来源（视频类注明“已合并 3 处副本”）、版本、分配给、分发方式（链接 / 复制）、启用开关、[… 更多]（查看、更新、分配给、停用、移除）。上方 [导入 Skill]：选文件夹后读出名称、描述、文件和脚本清单，脚本可勾选“允许运行”，不勾则导入为待确认。
- Skill 详情：`SKILL.md` 预览、包含的文件（脚本单独标“已确认 / 待确认”+ [查看并确认]）、在各 Agent 里的路径（“~/.codex/skills/pacing → 统一库”）；不支持原生 Skill 的 Agent 写“通过 skills_list / skills_read 工具提供”。
- 扫描与整合：宽对话框，4 步，顶部步骤条。
  1. 扫描：逐个 Agent 列出读取的位置和结果，写明“只读取名称、命令和变量名，不读取密钥的值”；扫完才能下一步。
  2. 对比矩阵：行是 MCP / Skill，列是 5 个 Agent，格子是“✓ 有 / — 没有 / ⚠ 配置不同”。“配置不同”是按钮，点开并排显示两份配置（差异高亮），单选采用哪一份。重复的 Skill 在行名下注明“3 处重复副本，整合后统一成 1 份”。
  3. 选择：分 MCP、Skill 两组勾选（默认全选，组标题旁 [全选 / 全不选]）；分发方式 MCP 默认“经工作台提供”，Skill 默认“链接”；“同时写回各 Agent 的原生配置”默认不勾，勾上或选“原样同步”时出现琥珀提示：先备份，并列出要修改的文件。
  4. 结果：“整合了 12 个 MCP、13 个 Skill，去掉了 18 份重复副本”+ 明细，[撤销本次整合]（二次确认）[完成]。
- 工作台联动：输入框工具条上“MCP 12”芯片，点开弹出层列出已启用的 MCP（勾选框），取消勾选即本任务临时停用，芯片变成“MCP 10/12”，对话里留一行系统提示；[全部恢复]、[打开能力页]。只对当前任务生效。

### 5.15 侧边聊天（原型：`workbench.html`、`asset-mode.html`）

依据 design.md 第 26 节。临时问个问题，主 Agent 照常干活，问答不进主对话。

- 选中文字的小菜单（分阶段，2026-11-07 决定）：在对话里选中文字后，选区上方弹出小菜单。
  - [添加到对话]：第 1.2 步已提供，作为“注释”附到下一条消息上（对照 Codex，2026-11-07 用户纠正：不是往输入框里插引用）。顺序：
    1. 点 [添加到对话]：选区上方出现圆角评论框“添加可选评论…”+ [↑]，原文旁出现蓝色编号圆点 ①，输入框上方出现“1 条注释”。评论可以不填，Enter 或 [↑] 完成，点别处也会保留已输入的评论。
    2. 悬停圆点显示评论；点圆点重新打开评论框，原文高亮，框里有 [删除]、[取消]、[保存]。
    3. 悬停或点“N 条注释”列出每条“所选文本 / 用户评论”，可以修改、删除；[×] 清空全部。
    4. 发送时注释按顺序附在消息后面（“所选文本”引用 + “用户评论”）一起发给 Agent，只有注释没有文字也能发送；发出后圆点和“N 条注释”清空。
    5. 注释按任务保存，和输入框里没发出去的草稿一起：刷新页面、切到别的任务再回来、换一台设备打开都还在。保存的是原文、它在对话里的位置和评论；恢复时按原文在对话里重新定位，找不到（例如那段内容被折叠或删掉）就只在“N 条注释”里保留，不画圆点。
  - [在侧边聊天中提问]：随侧边聊天上线，由功能开关 `chat.side` 控制，开关关着时不显示。
  - 理由：侧边聊天整体是后续功能，要等交接内容、便宜模型调用、只读调查这些前提就绪；“添加到对话”只在网页里记下选区和评论、发送时拼进消息，Gateway 和协议都不用改，成本很低、不依赖侧聊，所以先做。原型里两项都画出来，正式版现在只显示第一项。
- 入口：输入框工具条“MCP 12”旁的 [侧聊 Ctrl /]；快捷键 `Ctrl+/`（焦点在侧聊输入框时再按一次回到主输入框）；在对话里选中文字后右键“在侧聊中问”，键盘用菜单键或 `Shift+F10`，选中后直接按 `Ctrl+/` 也行。选中的文字作为引用带进侧聊，输入框上方显示“引用：…”+ [×]。
- 位置：右侧面板第四个标签“侧聊”，和改动、计划、预览并列；标签上显示侧聊个数，侧边调查进行中时加“● 调查中”（脉动圆点 + 文字）。
- 标签内从上到下：
  - 侧聊列表：每行图标 + 标题（第一个问题）+ 模式标签，右侧 [删除]（二次确认，已带回的内容不受影响）；右上角 [新建侧聊]。没有侧聊时是空状态。
  - 说明块：模式（快速提问 / 侧边调查，附一句能做什么）、模型（下拉，默认当前 Agent 同一家的便宜模型，切换后在记录里留一行；连续切换、中间没有新问答时只保留一行，显示最终结果）、上下文来源（“基于交接内容 H3 · 约 8k token”）、用量（计入调用统计，来源“侧聊”）。固定一句“主 Agent 看不到这里的内容，主对话照常进行”。
  - 记录：复用对话消息和思考过程的样式，回答逐字显示；空的侧聊先列 2～3 个贴合当前任务的示例问题。
  - 输入框：Enter 发送，回答中按钮显示“回答中”。
- 两种模式：
  - 快速提问（默认）：只回答，不读文件。说明块里有 [改为侧边调查]；回答发现需要看代码时，回答里也给这个按钮。切换后保留已有问答，记录里留一行“已改为侧边调查，已有的 N 轮问答一并带过去”。
  - 侧边调查：回答前逐条显示只读工具调用（搜索、读取、查询 `aic_history`，复用 6.2 的工具调用行，详情尾注“只读”），再给结论。说明块多一行绿色锁形图标的“只读：不会修改文件”，并写明读取都在工作副本内，不会触发审批。
- 带回主对话：每条回答下面三个轻按钮，用过后变成“✓ 已…”（文字 + 图标，`aria-disabled`），再点只提示已带回。
  - [发给主 Agent]：对话框里可改写，[加入排队] 后主对话末尾出现一条用户消息，头部标“来自侧聊”和“○ 排队中：等当前步骤结束后发送”，消息块用描边而不是底色；当前步骤结束后变成“● 已发送”。
  - [记为约束]：提示“已写进任务说明的约束”，计划标签的上下文信息里“约束”一项多一条，标“来自侧聊”；任务说明（`.aic/TASK.md`）同步出现。
  - [新建任务]：打开新建任务起始页，描述预填问题和结论，Agent 推荐照常给出。
- 可访问性：所有按钮有可读标签；侧聊记录不逐字播报，回答完成时由隐藏的播报区说一次“侧聊回答完成”；模式、运行中、已带回都有文字，不只靠颜色。
- 窄屏：沿用右侧面板的全宽覆盖（design.md 26.5 的底部弹出面板留到正式实现）。

### 5.16 生成页（原型：`generate.html`）

依据 design.md 第 27 节。侧栏导航“资产”之后；窄屏底部导航同样有入口。具体用哪些生成工具等调研结论，原型里的生成器、模型、价格都标“示例”，不绑定特定厂商。

- 顶部：标题右侧是预算按钮“今日已用 $1.20 / 上限 $10 · 示例”+ 进度条，点开改每日上限；达到上限时付费生成暂停，本机生成不受影响。
- 生成器卡片（单选组，方向键切换）：名称、接入位置、状态（已连接 / 未连接 / 需要 API Key / 未安装，形状 + 文字）、本机写“独占排队”、云端写示例单价。默认选中云端图片服务。本机工具（ComfyUI）的卡片独有 [一键安装 ComfyUI]（对话框里逐步显示检测显卡、下载、安装、下载入门模型、连接，可关掉在后台继续）和 [我已安装，自动检测]；装好后是 [入门模板] [更多]（打开界面、测试连接、停止 / 启动服务、卸载）。
- 左栏参数：按所选生成器的 schema 自动生成。选 ComfyUI 时先列内置入门模板（文生图、图生图、无缝贴图、图标 / UI 元素、角色立绘、短视频），每个模板列出需要的模型和“已下载 / 未下载”，未下载的给 [下载模型 · 大小]；[导入工作流 JSON…] 是次要入口，导入后列出识别到的输入节点，勾选的才变成表单。参考图 [从资产库选…]，从资产页 [用它生成变体] 跳过来时用 `?ref=` 预选。底部写预计费用或预计显卡占用秒数；不能生成时在按钮上方写原因（未安装、缺模型、超预算），按钮带 `aria-disabled`，点了提示原因。`Ctrl+Enter` 提交。
- 右栏队列：每行缩略预览 + 标题 + 状态 + 进度条 + 百分比。本机独占时后来的任务写“排队中：显卡被占用（独占）”。按钮随状态变：[取消] → [查看结果] 或 [移除]。
- 结果网格：按批次分组，批次头写生成器、数量、用时、费用。每项：预览（图片可放大；音效是波形 + [播放 / 停止]；视频是画面 + [播放 / 暂停] + 可用方向键拖的播放条）、文件名和 seed、[采用]（选项目、目标文件夹、文件名，采用后绿色描边 +“已采用：路径”）、1～5 分评分（单选组）、[用相同参数再生成]、[只换 seed 再来 4 张]、[发给 Agent]（新建任务起始页里预填描述并附上结果和生成记录）、[查看生成记录]（生成器、工作流版本、提示词、seed、参数、耗时、费用，对应 `.aic/generations/<id>.json`）。
- Agent 调用（`asset-mode.html`）：`gen__image` 的审批卡片沿用 6.3，事实区写生成器、预计费用、本任务预算，以及“付费生成需要审批，不适用低风险自动允许”。允许后对话里出现进度卡片（进度条、缩略图逐步清晰、可取消），完成后文件出现在“改动”面板，标“新增 · 生成”，点开看生成记录。
- 能力页“生成器”标签：和 MCP、Skill 并列。[添加生成器] 先选类型（本机工具 / 云端 API / MCP），再选服务商（中性示例 +“更多服务商：调研后提供”）；本机地址收在“高级”里，默认 `http://127.0.0.1:8188`；云端填 API Key，提示存进凭据管理器；可测试连接、设并发方式（独占 / 共享）。
- 监控页调用统计：分组维度加“生成器”，另有“媒体生成”区块（生成次数、时长、费用、显卡占用时长）。

## 6. 关键组件规格

### 6.1 对话消息

- 用户消息：`bg-2` 底色块；助手消息：无底色，左侧 Agent 徽标，头部“名称 + 模型 + 时间”。
- 按“轮”显示（参照 Codex，2026-11-07，ISSUE-0018）：一轮回复是两条用户消息之间 Agent 的全部输出，头像和名称只出现一次。Agent 在工具调用之间分段输出，也不再拆成多条消息。
  - 过程：头部下方一行灰字“用时 N 秒 >”，点开看思考、中途说明（`fg-2`，比最终回答淡一档）、工具调用和审批。进行中显示“正在处理 · N 秒”（脉动）并展开；有待处理的审批时强制展开，审批卡片不能藏起来；结束后自动收起；用户手动开合后以用户为准。展开后标题下有一条细线把过程和回答分开。
  - 最终回答：最后一段、并且之后没有工具调用的输出，显示在过程下面，`fg-1` 正文颜色。
  - 计划更新放在这一轮后面，不插进过程里。
- Markdown 渲染：标题、粗体、列表、引用、表格（可横向滚动）、行内代码、代码块（带复制按钮和语言名）。链接只显示文字，悬停显示地址，点击后在系统浏览器里打开（经 `Platform.openExternal`，只接受 http/https）；不渲染原始 HTML。用户消息和思考内容用同一套渲染。
- 生成中：消息末尾三点动画；超过 10 分钟没输出时换成“可能卡住了”+ [继续等待] [中断]。
- 思考过程：放在消息头部和正文之间。Agent 思考时实时逐字显示，标题为“正在思考…”；思考结束后自动折叠成一行“思考了 N 秒”，点开查看；箭头朝右表示折叠，展开后朝下。展开后是左侧细竖线 + `fg-3` 的较淡文字，和正文明显区分。
  - 设置里可选“默认折叠（推荐）/ 默认展开 / 不显示”。
  - Agent 或模型不提供思考内容时（取决于各家通过 ACP 发不发 `agent_thought_chunk`），不显示这一块，不画空占位。
  - 交接时，原 Agent 的思考过程不进交接包，只保留在原会话的记录里。

### 6.2 工具调用

- 默认折叠成一行灰字：展开箭头、动词（读取 / 搜索 / 修改 / 新建 / 执行）、目标（等宽，过长省略）、右侧结果（“+22 −4”“4 处匹配”“成功 8.9 秒”）。没有边框和底色，悬停才出现浅底。
- 连续的工具调用合成一组，与消息正文缩进对齐。
- 连续的网页搜索再合成一行“已搜索网页 N 次 >”（搜索图标 + 次数），展开后每次搜索一行，写搜索的内容，过长省略；进行中写“正在搜索网页”。
- 失败：动词变红为“执行失败”，自动展开最后几行输出。命令输出默认显示最后 200 行，可展开全部。
- 修改文件：展开后显示内联 diff 片段，[在改动面板中查看] 打开右侧面板并定位。
- 用原生 `<details>` 或等价语义实现，键盘可展开。

### 6.3 审批卡片（规则与 v0.1 相同）

- 结构：标题（“Claude Code 请求执行命令”）+ 已等待时长和自动暂停倒计时 → Agent 给出的理由 → 命令或文件路径（等宽，完整显示）→ 事实表（运行位置、为什么要审批）→ 按钮。
- 按钮：[允许] [总是允许此类命令] ……[拒绝…]。“总是允许”预览将生成的规则，只作用于这一类。[拒绝…] 展开理由输入框，理由会发给 Agent。
- 视觉：琥珀描边 + 左侧 4px 粗条，全界面唯一用这种样式的组件。处理后变成一行“已允许，由 本机 处理”。
- 键盘：卡片获得焦点时 `Enter` 允许、`Esc` 打开拒绝；全局 `Ctrl+Shift+A` 跳到下一个待审批。新审批到来不抢焦点。
- 同一审批在对话、待审批条、侧栏“等你处理”、看板卡片、系统通知中同步；任一处处理后其他位置立即显示结果。

### 6.4 diff 视图

- 头部一行：比较基准（“相对 main 的全部改动”）、总增删、[左右对比]。
- 文件列表：类型字母（M 蓝 / A 绿 / D 红，M 不用琥珀）、路径（目录灰、文件名亮）、增删数。
- 内容放在 `bg-0` 的圆角块里：双行号 + 符号列 + 代码；行底色表示增删，词级高亮标出具体改动；hunk 头显示所在函数。文件头吸顶，带 [还原文件] [评论]（评论发给 Agent）。
- 二进制资产：显示“模型文件已修改（412 KB → 486 KB）”和 [前后对比]，打开全屏查看器的对比模式。
- 底部固定合并区。合并按钮打开确认：合并方式（默认压缩成一个提交）、提交说明（Agent 生成，可编辑）、主目录有未提交改动时的提示。

### 6.5 Agent / 账号 / 模型切换器

- 每个任务的输入框下方都有切换器（工作台、资产页等所有带对话的页面）。2026-11-07 起和新建任务用同一个选择器：一个按钮“徽标 Agent 模型 · 思考 X ▾”；第三方悬停显示“沿用软件自身配置”，独立 Agent 显示所选工作台服务。
- 配置归属（2026-11-08）：第三方 Agent 只列自身报告的模型和会话强度，提示“沿用该软件设置”；AI Console 独立 Agent 单独列出工作台 API 服务及其模型。工作台自定义模型不混入 Claude / Codex / CodeBuddy 等目录，选择它不切换任何第三方登录。下文“账号”切换仅在该执行者明确支持且不改变第三方认证时提供；旧的代登录账号方案停止沿用。
- 点开后第一级只列 Agent：徽标、名称，右侧写当前的“模型 · 思考 X ✓”，或者状态（“登录已过期”“未连接”，琥珀色）、“N 个模型”。鼠标移到某个 Agent 上（或按 →），旁边展开二级：第三方是模型列表 → 思考强度（分段，Agent 支持时；不支持写“由模型自己决定”），不列认证；独立 Agent 按工作台服务分组列出模型。打开时自动展开当前 Agent，思考强度一眼可见。当前 Agent 的思考强度点了立即生效，菜单不关；别的 Agent 要选了模型才算数。再点一次按钮、Esc、点外面都会收起。底部说明会话内模型与强度切换保留上下文，换 Agent 发送时才交接。
- 思考强度：分段选择（例如 低 / 中 / 高 / 最高），只有 Agent 通过 ACP 配置项暴露了这个选项时才可调；不支持的 Agent 显示“思考强度由模型自己决定”。调整后从下一条消息生效，上下文不受影响。
- 独立 Agent 的思考控件取当前服务 / 协议 / 模型已知可用的选项，可能是强度、预算或服务默认，不能固定套用第三方的 ACP 列表。不支持调节就不提供档位，未知显示“使用服务默认”；强制思考的模型不提供“关闭”。换模型后更新并校验选择，模型摘要同时提示图片与工具能力，无法运行工具的路径不显示为可完整执行任务。
- 连续切换模型或思考强度、中间没有新消息时，对话里只保留一行提示，显示最终结果（例如“已切换为模型 Sonnet 5，思考强度 高（会话内切换），从下一条消息生效”）。
- 弹出层底部说明随所选内容变化：已支持的会话内模型与思考强度切换保留上下文；独立 Agent 换服务时按接口兼容性说明历史如何继续，不承诺一律无损；换 Agent 走交接。失败只显示原因，不自动换服务或认证。
- 换 Agent 只是选定“下一条消息交给谁”，**发送消息时才交接**（2026-11-07 用户反馈：没输入就交接不对）。选完后对话末尾出现一行虚线提示“下一条消息交给 X：发送时才自动交接，不发就不交接 [撤销]”；连续换只保留这一行；切回原 Agent 或点 [撤销] 等于没换。还没发送时换模型、换账号只改这一行，不进对话记录。发送后先出现交接分隔条，新 Agent 接着回复这条消息。
- Agent 正在执行时切换，先问“等当前步骤完成 / 立即中断”。

### 6.6 任务卡片（看板）

标题（最多两行）→ Agent 徽标、名称、耗时 → 进度条 → 当前在做什么（一行）→ 快捷操作。卡片只有底色没有边框；等待审批的卡片有琥珀描边和左侧色条。排队卡片右上角有拖动手柄，写明排第几位、在等哪个 Agent 的空位。

见 5.5。状态五种：就绪（绿圆点）、运行中（蓝脉冲）、需要登录 / 未验证版本（琥珀菱形）、出错（红方块）、未连接或未安装（灰空心圈）。

### 6.12 上下文用量与 token 统计（2026-11-07，同日第二版）

数据来源（design.md 15.5）：ACP 的 `usage_update`（当前上下文 token、窗口大小、累计费用），以及每轮 `usage`（输入、输出、思考、缓存）。Agent 没报告的写“未报告”，不用 0 冒充，也不编造分母（没有窗口大小就不显示百分比）。

- **圆环**（参照 Claude Desktop）：输入框工具条最右、发送按钮左边，一个 18px 小圆环，不带文字。70% 以上琥珀，90% 以上红。悬停或聚焦只显示一行“上下文 76.2k / 200k（38%）”，快满时补一句“Agent 会自动压缩较早的对话”。点圆环打开右侧“详细”并滚到“上下文”。
  - 第一版的“输入框上方信息行”和弹出明细取消：项目、分支移到“详细 → 环境”，明细移到“详细 → 上下文”。
- **每轮用量**：每轮回复下面一行小字“N token · 输入 · 输出”，悬停看完整数字；Agent 没报告时写“用量：X 未报告”。
- 不在首页做 OpenBitFun 那样的“累计 token、连续使用天数”卡片；全局用量在监控页（5.12、design.md 23.4）。

### 6.13 右侧面板“详细”（2026-11-07）

原来的“计划”标签改名“详细”，一列分节，节之间一条细线。除计划外参照 Claude Desktop 的右侧栏。

每节都能折叠展开：点标题行（左侧小箭头）切换，默认只展开“计划”和“上下文”，状态按设备记住。收起时标题行右侧仍有一句摘要（计划“3 / 6”、上下文“38% · Agent · 模型”、token 用量“220k · 6 轮”、连接“10 个可用”、输出“6 个文件”）。点输入框的上下文圆环会自动展开“上下文”。

1. **环境**：运行在哪（本机 / 局域网设备名）、项目名 · 文件夹路径、分支（工作副本，基于哪个分支）。[存为常用] 把这组组合存起来，新建任务时一键选用。
2. **计划**：Agent 的计划步骤，标题右侧“已完成 / 总数”。
3. **上下文**：直接显示明细，不再要点“查看明细”。样式参照 Claude 的 Context 面板：
   - “已用 N%”和“X / 窗口”，标题右侧是 Agent · 模型；
   - 8px 细分段横条：每个分类一段，段间 2px 空隙，最后是剩余空间。悬停或键盘聚焦某段显示名称、数量、占比；
   - 图例：色块、名称、数量、占比。分类：对话消息、MCP 工具、内置工具、系统提示、技能、记忆文件、MCP 服务说明、自动压缩预留、剩余空间。前 4 类用图表色板（和监控页同一套，已校验），其余用灰色；
   - 可展开：MCP 工具（按服务）、记忆文件（逐个文件）。
4. **会话 token 用量**：**整个会话**从开始到现在所有轮次的累计，不是某一轮。
   - 大字合计，旁边写“N 轮 · N 段会话 · 从几点开始”；
   - 输入（其中读缓存及比例、写缓存）、输出（其中思考）；
   - 按会话段列出（交接前后各一段），没报告的段写“未报告”，并在底部说明合计里不含它；
   - 费用（API Key 账号显示预估费用，订阅账号写“不单独计费”）、账号额度细条（如本周已用 46%），拿不到写“额度未知”。
5. **连接**：本任务可用的 MCP 服务（和输入框“MCP 12”同一份数据），标题右侧“N 个可用”。默认显示 4 个，[再显示 N 个] / [收起]。断开的服务行尾 [重新连接]（悬停看原因）；本任务停用的变灰并写“已停用”。
6. **输出**：这个会话新建或修改的文件，最近的在前；文件名 + 所在目录，行尾 +N −N 或“新建”。默认显示 5 个，[再显示 N 个]。点文件在“改动”里打开。

### 6.14 对话导航条（2026-11-07）

参照 Codex 对话区左侧的刻度条，长对话里快速跳转。

- 对话区左边一列细刻度，垂直居中：你的消息是长刻度，Agent 每轮回复是短刻度，交接是灰色短刻度，有待审批的回复是琥珀色。
- 当前看到的那条刻度高亮（可视区上方 1/3 处所在的消息；滚到底就是最后一条）。
- 悬停或键盘聚焦刻度：右侧浮出一张小卡片，写谁、时间和开头一句。点击平滑滚到那条消息，并短暂闪一下底色（减少动态效果时不滚动动画、不闪）。
- 键盘：Tab 进入后上下方向键在刻度间移动，Home / End 到首尾，Enter 跳转。
- 少于 3 条消息时不显示。新消息、流式输出、审批出现或处理后自动更新。

### 6.15 新建任务起始页（2026-11-07）

替代原来的“新建任务”对话框，参照 ZCode 的起始页。侧栏 [新建任务]、`Ctrl+N`、项目 / 分组的“+”、侧聊的“新建任务”、生成结果的“交给 Agent”都打开它。

- 占满主区域，右侧面板临时隐藏；左上 [返回]，`Esc` 返回原页面，不丢页面状态。
- 中间：问候语（按时间“早上好 / 下午好…”，“今天让 Agent 做什么？”）。
- 大输入框：
  - 顶部一排胶囊：项目 ▾、基于分支 ▾、分组 ▾（不分组时弱化显示）；选了闲时运行时多一个“闲时运行 ×”；
  - 中间是描述，提示写“描述要做的事…@ 引用文件”；附件显示在描述上面（粘贴、拖入、点“+”，见 6.16）；
  - 所有下拉胶囊再点一次就收起，Esc 也能收起；当前选中项打勾。
  - 底部：+（附件）、权限 ▾（只读 / 需审批 / 工作区内自动 / 完全访问，选完全访问时琥珀色并提示）；右侧 Agent · 模型 · 思考强度 ▾（只列已启用的；和对话输入框同一个选择器，见 6.5）、圆形派发按钮（没写描述时不可点）。`Ctrl+Enter` 派发。
- 写了描述后，输入框下面出现 Agent 推荐（快速判断，规则同 5.13），可以 [采用推荐]。
- 快捷入口一排：报错修复、周报总结、资产处理、PPT 制作、闲时任务。点了填好模板并选好合适的 Agent，光标停在要补充的地方；“闲时任务”只是给这个任务加上闲时运行。
- 底部一句：派发后会建立独立的工作副本，不影响你正在用的代码。
- 派发后回到原页面，侧栏出现新任务，提示“有空位后自动开始”。

### 6.16 附件与图片（2026-11-07）

对话输入框和新建任务起始页共用。

- 三种加法：`Ctrl+V` 粘贴截图或复制的图片（剪贴板里同时有文字时文字照常粘贴）；把文件拖进输入框（拖入时输入框高亮）；点“+”选择文件。最多 10 个，单个不超过 20 MB，超出的提示原因。
- 输入框里显示附件：图片是缩略图 + 文件名 + 大小，点缩略图看大图；其他文件是图标 + 文件名 + 大小。每个都有 × 删除。粘贴的截图没有文件名，按时间命名“截图-时分秒.png”。
- 发送后图片显示在你的消息里，点开看大图。只有附件、没写文字也可以发送。
- **模型看不了图片时立即警告**：
  - 加图片时，或者有图片时换到看不了图的模型，输入框上方出现一条琥珀提示“X · 模型 看不了图片，这 N 张图片发过去它收不到”，图片缩略图描琥珀边，同时弹一条提示。
  - 提示里给出 [换成 Y]（优先同一个 Agent 里能看图的模型，会话内切换；没有就推荐别的 Agent，写“发送时交接”）和 [去掉图片]。
  - 不处理就点发送会被拦下，提示条晃一下并聚焦第一个按钮，不会悄悄把图片丢掉。
  - Agent 没报告能不能看图时写“没有报告能不能看图片，可能收不到”，多一个 [仍然发送]。
  - Agent · 模型选择器（6.5）里看不了图的模型后面标“不能看图”，选之前就能看到。
- 数据来源：ACP `initialize` 返回的 `promptCapabilities.image`（Agent 级）；同一 Agent 不同模型的差别来自 Agent 报告的模型信息，拿不到时按“未确认”处理（design.md 15.2）。

### 6.8 交接分隔条

交接默认全自动，不弹窗（design.md 7.5）。

- 进行中：对话里出现一条胶囊“正在自动交接到 X”，后面逐项打勾：生成交接内容、覆盖校验（自动补齐 N 项）、一致性校验、探针问答、发送。
- 完成后：一条细线，中间胶囊“已自动交接：A（模型）→ B（模型）”，后面跟两个小徽标，分别写级别（如“H3 结构化交接”）和校验结果（如“校验 7/8”）。箭头朝右表示折叠，展开后朝下。
- 展开内容：为什么选这一级、自动补齐了什么、原样带过去了什么、新 Agent 的复述，以及复述是否和交接内容一致。按钮：[查看交接内容]（三个标签：发给新 Agent 的内容 / handoff.json / 自动校验记录，含每道探针题的对错）、[切回 A]（可选同时恢复工作区到交接时的检查点）、[重新交接…]（强制完整转写，或修改后重发）。
- 新 Agent 的第一条回复里，有一块可折叠的“交接确认（我的理解）”。
- 设置里开启“交接前让我确认”后，切换时先弹出可编辑的交接内容，确认后才发送。默认关闭。

### 6.9 资产卡片

Agent 修改资产后在对话流里出现（design.md 15.2）：缩略图 + 文件名 + “已修改，点击预览”或“第 3 版，刚刚更新”。点击在右侧“预览”打开。

### 6.10 空状态与错误提示

- 空状态告诉下一步做什么：任务列表为空 →“还没有任务。描述你想完成的事，选一个 Agent 派发出去。”+ [新建任务]；预览为空 →“这个任务没有可预览的资产”+ [去资产页]。
- 错误统一三段：标题写发生了什么（“Codex 登录已过期”），说明写影响和怎么办，再给按钮。不道歉、不笼统。技术细节折叠在“查看详情”。
- 三种强度：页面内提示块（`alert`，只用底色不用描边）、卡片内嵌提示、底部居中的短提示（只用于操作结果，如“已合并到 main”，动词与按钮一致）。

## 7. 三维预览

### 7.1 形态：预览的一种类型

预览是右侧面板的一个标签，按文件类型选择预览器（design.md 12 节的预览器插件）：图片、音频波形、三维模型。三维模型预览分两档：

- 面板内预览：4:3 中性灰画布，左上角 [材质] [线框]，右上角 [全屏查看]，左下角面数。下方是文件信息（路径、三角面与任务前对比、材质、尺寸、版本）和三个按钮 [和任务前对比] [截图发给 Agent]。原型另有一个“模拟 Agent 写入”按钮，只用于演示。
- 全屏查看器：覆盖整个窗口的对话框，顶部浮层工具条：文件名、着色（材质 / 实体 / 线框）、[和任务前对比]、[重置视角]、[截图发给 Agent]、[×]。`Esc` 或 × 关闭，焦点回到打开它的按钮；打开期间焦点留在查看器内。

### 7.2 与对话和任务联动

1. 自动刷新：收到 `asset.changed`（design.md 11.6），路径命中正在预览的资产，按新 `version` 重新加载，保持相机位置，底部提示“CodeBuddy 更新了 chest.glb（第 3 版），预览已刷新，视角保持不变”。对话里的资产卡片同步显示新版本号。
2. 任务前后对比：全屏查看器左右分屏，左边“任务前（第 1 版）”，右边“现在”，两边共用同一个相机，转一边另一边跟着转。数据来自 `GET /tasks/:id/files/*path?ref=base|head`（design.md 11.5）。diff 面板里的模型文件直接提供 [前后对比]。
3. 截图发给 Agent：把当前画面作为图片附件放进输入框，Agent 支持图片输入时直接发送。
4. 从任务打开：看板卡片、对话资产卡片都可以一键打开预览。
5. 验收：待验收任务若含资产改动，合并确认里列出资产缩略图，提醒“1 个模型尚未预览过”。

### 7.3 技术选型

- three.js + react-three-fiber + drei。生态最大，glTF 支持最好。Babylon.js 功能更全但包更大、React 集成弱，作为备选。
- 预览器按 design.md 12.1 运行在沙箱 iframe 里。全屏查看时不移动 iframe（在 DOM 里移动会让它重新加载），而是把 iframe 所在的容器用 CSS 放大到整个窗口，同一个渲染器继续工作，不重复加载模型、不占两份显存。工具条由外壳绘制，通过消息通知预览器切换着色、对比、重置视角、截图。
- 对比模式用视口裁剪（scissor）在同一画布上画“任务前”和“现在”两个场景，共用相机。原型（没有 iframe）用移动画布的方式演示同样的效果。
- iframe 获得焦点时，按键不会传到外壳，预览器要把 `Esc` 转发出来，否则全屏查看器关不掉。
- 渲染后端：先用 WebGL 2，`WebGPURenderer` 在 WebView2 上实测通过后再作为可选项开启，运行时用 `navigator.gpu` 探测、失败回退。
- 格式：glTF/GLB 为一等格式（配 Draco、Meshopt、KTX2 解码）；OBJ 直接读；FBX 由转换器插件转成 GLB 再预览（design.md 11.1）；引擎私有格式先显示“不支持预览”。
- 性能：右侧面板收起或不在“预览”标签时停止渲染（R3F `frameloop="demand"`）；大文件在 Web Worker 里解析。
- 原型说明：`asset-mode.html` 从 jsDelivr 按版本号引入 three.js 0.170.0，只为免构建打开，文件里已注明。正式工程打包进应用，不访问 CDN。

## 8. 响应式、键盘、可访问性

### 8.1 断点

| 宽度 | 布局 |
|---|---|
| ≥1280px | 侧栏 + 主区 + 右侧面板并排，右侧可拖动宽度 |
| 768～1279px | 侧栏默认折叠为图标栏；右侧面板变成从右滑出的覆盖抽屉，默认收起，`Esc` 关闭 |
| <768px | 侧栏隐藏，底部导航（任务、资产、自动化、监控、能力、Agent、设置，任务上带待处理徽标）；右侧面板全宽覆盖 |

触控目标 ≥44px（底部导航 48px）；所有功能不依赖悬停。

### 8.2 键盘

| 快捷键 | 作用 |
|---|---|
| `Ctrl+K` | 命令面板（搜索任务、文件、命令、设置项） |
| `Ctrl+N` | 新建任务（网页端浏览器会拦截，改用 `Alt+N`） |
| `Ctrl+B` | 折叠 / 展开侧栏 |
| `Ctrl+J` | 显示 / 收起右侧面板 |
| `Ctrl+/` | 打开侧聊（有选中文字时带上引用）；在侧聊输入框里再按一次回到主输入框 |
| `Ctrl+Shift+A` | 跳到下一个待审批 |
| `Enter` / `Shift+Enter` | 发送 / 换行 |
| `Enter` / `Esc`（审批卡片聚焦时） | 允许 / 打开拒绝理由 |
| `Alt+↑/↓` | 看板排队顺序 |
| `←` / `→`（拖动条聚焦时） | 调整右侧面板宽度 |
| `Esc` | 关闭弹出层、全屏查看器、中屏下的右侧抽屉 |

`Ctrl+B`、`Ctrl+J` 等组合在部分浏览器里有默认功能，M1 阶段在 Edge、Chrome 里实测，有冲突的在网页端换成 `Alt` 组合。界面上显示的快捷键按当前平台自动替换。

### 8.3 可访问性要点

- 对比度见 3.1，深浅两套都按 AA 校验；预览上的浮层文字放在半透明深色底上。
- 焦点框 2px 靛色，偏移 2px；吸底的输入区、待审批条不能遮住获得焦点的元素（WCAG 2.4.11）。
- 拖动条是 `role="separator"`，可聚焦，方向键调整，报告当前宽度。
- 全屏查看器是 `role="dialog"` + `aria-modal`，打开时焦点进入、关闭时还原。
- 对话流只播报“消息完成”和“新审批”，不逐字播报流式输出。
- 状态都有文字；Agent 身份同时用颜色和字母；进度条带 `role="progressbar"` 和数值；三维预览有文字替代，文件信息提供全部数值。
- 完整合规需要用读屏软件（NVDA、讲述人）实测并请无障碍专家审查，本设计只做到规范层面。

## 9. 技术选型结论

| 部分 | 选择 | 理由 |
|---|---|---|
| 组件 | shadcn/ui（跟随其当前默认原语，Base UI 或 Radix）+ Tailwind | 代码在自己仓库里，可完全按本文令牌改；原语负责焦点管理和 ARIA。其 Sidebar（可折叠为图标栏）和 Resizable 组件正好对应本版布局。Mantine、Ant Design 自带强烈视觉风格，改造成本高 |
| 分栏 | react-resizable-panels | 活跃维护（见 1.4）；可折叠、最小/最大宽度、键盘调整、布局持久化都内置；shadcn Resizable 基于它，样式与组件库一致。本版只有“主区 + 右侧面板”一处可调分栏，不需要停靠库 |
| 三维 | three.js + react-three-fiber + drei | 见 7.3 |
| diff | CodeMirror 6 + `@codemirror/merge` | 比 Monaco 轻，支持逐行和左右对比、词级高亮 |
| Markdown 与高亮 | react-markdown + Shiki | 高亮质量好，可与 diff 共用主题 |
| 长列表 | TanStack Virtual | 对话、日志、长列表需要虚拟滚动 |
| 拖放 | dnd-kit | 只用于看板排队排序，自带键盘拖动 |
| 命令面板 / 提示 | cmdk / sonner | 与 shadcn 生态一致 |
| 图标 | Lucide | 与 shadcn 默认一致 |

依赖在实施时锁定精确版本。

## 10. 对架构文档的建议

以下是对 `docs/design/design.md` v0.3 的修改建议，供维护者决定：

1. 第 4 节技术选型表补充：react-resizable-panels（可调分栏）、three.js + react-three-fiber、CodeMirror merge、dnd-kit、cmdk。
2. 第 15.1 节“工作台”：说明主区有“对话 / 看板”两个视图，看板不再单列为页面；右侧面板为“改动 / 计划 / 预览”三个标签，“上下文”并入“计划”标签下方，按需出现、可收起、可调宽度；“新建任务”是抽屉而不是独立页面。
3. 第 15.3 节响应式：中屏侧栏折叠为图标栏，右侧面板变覆盖抽屉、默认收起；窄屏改为底部导航。
4. 第 15.2 节“资产卡片”：补充点击后在右侧“预览”打开，可放大成全屏查看器，支持任务前后对比。
5. 第 11.6 节 `asset.changed`：建议增加 `taskId` 和 `sessionId`（`origin=agent` 时），界面要显示“由哪个任务、哪个 Agent 修改”。
6. 第 11.5 节：前后对比需要“任务前”的版本号用于标注（“第 1 版”）；建议 `GET /tasks/:id/files/*path?ref=base|head` 的响应头带上对应的资产 `version`。
7. 第 14.1 节 `GET /tasks/:id/diff`：对二进制文件标出 MIME 类型、前后大小和 `assetId`，界面据此显示 [前后对比] 而不是文本 diff。
8. 第 14.2 节 `approval.requested`：载荷带上 Agent 给出的理由、运行目录、到期时间 `expiresAt`、“总是允许”将生成的规则预览。
9. 第 9.3 节审批流转：补充“审批不自动获取焦点”，避免用户打字时按回车误放行。
10. 第 6.2 节 Agent 配置：增加界面用的身份色和字母，允许用户修改。
11. 截图发给 Agent 依赖第 6.2 节能力里的 `prompt.image`；Agent 不支持时，建议通过第 11.4 节上传接口存为任务附件，在消息里给出路径。
12. 第 20 节风险表：增加“WebView2 上 WebGPU 可用性”（应对：默认 WebGL 2，探测后开启）。
13. 布局偏好（侧栏折叠、右侧宽度、面板开合）只存在客户端本地，不需要新增接口。
14. 第 12.3 节预览器消息协议：除 `ready`、`thumbnail`、`error` 外，建议增加界面 → 预览器的 `setShading`、`setCompare`（附任务前版本的 url）、`resetView`、`capture`，预览器 → 界面的 `capture.result`（图片 blob）和 `key`（转发 `Esc` 等按键）；`asset.changed` 刷新时由预览器自行保持相机位置。
