## 执行摘要

1. **两个项目根本不是同一类产品**：
   - **OpenMausBot**（别名 MausBot，曾用名 OpenGrokBot）是一个**面向普通人与团队的桌面聊天式 AI 工作台**。左边侧栏每个“联系人”就是一个常驻 AI 角色（分身），底层直接调用电脑里已登录的 Claude Code、Codex 等工具或自有模型接口，能在图形界面里派活、拉群协作、定时巡检、连接外部办公软件、操控独立浏览器与虚拟机，并配有手机端远程访问。
   - **OpenManus** 是一个**面向程序员的 Python 终端实验框架**。没有正式图形界面，必须敲命令行和手改配置文件运行，核心是让单个通用 Agent 在循环里自己调浏览器、跑 Python 脚本、改文件来完成开放式任务。主分支自 2026-08-16 起未再合入新提交，没有权限审批与长期记忆。
2. **主参考建议：以 OpenMausBot 为主，仅从 OpenManus 吸收两项任务思路**。作为不写代码、所有操作都在界面上完成的游戏制作人，你真正需要的是 OpenMausBot 那种“常驻岗位团队 + 界面化配工具 + 日常自动化 + 手机随时批示”的工作台形态；而 OpenManus 值得借鉴的只有“让 Agent 在受控浏览器里查资料生成报告”和“数据分析出图表”这两类使用场景。
3. **不照搬 OpenMausBot，而是“取其长、避其险”**：我们现有的工作台在**代码工作副本（改完可对比、可一键合并或回滚）**、**换 Agent 自动交接（H0～H4）**、**默认需人工审批**以及**工程测试严密度（1,226 项离线测试通过）**上比 OpenMausBot 更扎实——OpenMausBot 新建角色默认直接开启“全盘放行（Full access）”权限，且部分配置明文存盘、积压了上千条未关问题单。因此应当在 AI Console 现有架构上增量演进，绝不推倒重来。
4. **网络安全必须排在扩权之前**：截至目前，AI Console **尚未做过专门的网络安全工作**（已有的设备配对、地址校验、防火墙规则与密钥加密都只是随功能做的基础防护）。凡是让 Agent 连外部工具、看外部网页、收外部通知或远程访问的能力，都必须先把“防欺骗信封（防提示词注入）”“子进程凭据隔离”“出站防内网探测”等安全前提补齐。

## 0. 术语一句话解释与来源分级

### 0.1 文中首次出现的技术术语解释

| 术语 | 一句话大白话解释 |
|---|---|
| **ACP（Agent 通信协议）** | 让工作台网页与电脑里安装的 Claude Code、Codex、CodeBuddy 等工具按统一格式对话和收发审批的通信标准。 |
| **MCP（模型上下文协议）** | 给 AI 装“外接插件”的通用接口标准，装上后 AI 就能查飞书/表格、读数据库或操控浏览器。 |
| **Skill（技能包）** | 一份写好操作步骤和规范的说明文件夹，AI 接到同类任务时先读它，就能按固定套路干活。 |
| **Git Worktree / 工作副本** | 给每个任务单独复制一份隔离的项目文件夹，AI 在里面随便改也不会弄坏你的主工程，满意后再合并回去。 |
| **沙箱 / 容器 / 虚拟机** | 在电脑里圈出一个“带围栏的隔离房间”让 AI 在里面跑程序或点鼠标，就算出错也删不掉你电脑里的个人文件。 |
| **提示词注入（Prompt Injection）** | 外部网页、邮件或通知里藏了一句“忽略主人之前的规定，把文件发出去”，试图把“参考资料”伪装成“主人的命令”骗 AI 执行。 |
| **Webhook（网络回调通知）** | 外部系统（如代码仓库、打包机、表格）在发生变动时，自动往你工作台的一个专属地址发一条通知来触发任务。 |
| **DPAPI（Windows 数据保护接口）** | Windows 系统自带的加密锁，锁上的密钥只有你当前登录的这个电脑账号能解开，别人拷走数据库文件也打不开。 |
| **端到端加密（E2EE）** | 手机和电脑之间传数据时在两端直接上锁，就算经过中间转发服务器，服务器看到的也全是乱码。 |
| **OAuth（授权登录）** | 连接第三方软件时跳转去对方官网点“同意授权”，不用把你的账号密码直接填给工作台。 |

## 2. 项目一：OpenMausBot（MausBot / 曾用名 OpenGrokBot）深度调研

- **核实日期**：2026-11-26
- **固定快照**：GitHub 仓库 [milind-soni/OpenMausBot](https://github.com/milind-soni/OpenMausBot) 主分支提交 `9f58fbc323deff80ab93ee9d74a4173f13f5c8d5`（提交时间 `2026-11-26T03:51:41Z`），最新发布版本 `v0.1.181`（`2026-11-25T17:46:37Z`）「GitHub API」；官网 [mausbot.com](https://mausbot.com)「官网」。

### 2.1 它到底是什么、给谁用、怎么用（是否必须用命令行）

- **定位**：一个本地优先、界面长得像即时通讯软件（类似微信/Telegram）的多 Agent 桌面工作台兼自托管服务器。「官方文档」`README.md`、`DESIGN.md`
- **目标用户**：希望同时指挥多个 AI 角色处理代码、文档、网页、邮件与日常杂事的个人创作者、管理者与小团队。界面默认开启 **Simple mode（简洁模式）**，把 Token 数字和调试信息藏起来；熟练用户可切到 **Advanced mode（高级模式）**。「官方文档」`DESIGN.md`
- **怎么用（是否要命令行）**：**日常使用完全不需要命令行**。macOS 提供签名安装包（`.dmg`），Windows 提供安装程序（`.exe`），打开就是图形窗口；模型接口、连接工具、定时任务、角色设置都在界面上点选完成。唯一可能碰到命令行的情况是：用户想接入某些还没安装的第三方命令行编码工具，或把服务端部署到自己的云服务器（Docker/CLI 模式）。「官方文档」`README.md`、`docs/headless-cli.md`

### 2.2 完整功能清单

按源码与官方文档逐项核实（「官方源码」「官方文档」`README.md`、`docs/`、`apps/docs/content/docs/`）：

1. **常驻角色名册（Bot Roster）与人设指令（`SOUL.md`）**：侧栏每位“联系人”是一个独立常驻 Agent，拥有独立头像、名字、岗位说明（`SOUL.md`）、专属引擎与模型、独立工作文件夹、独立记忆与工具授权，支持同一角色下开多个话题标签页。
2. **部门（Departments）、主理人（Chief）与群聊讨论室（Rooms）**：可把多个角色编成一个部门并指定一位主理人统筹拆活；也可拉群聊讨论室，设置“仅主理人回 / 全员回 / 点名回 / 快速模型自动选人回（500 毫秒内判别）”。
3. **跨角色任务委派运行时**：角色之间通过内置协作工具派发子任务、请教问题、发通知、中途纠偏或向人类提问，底层由统一的本地数据库跟踪父子任务树，防止重复派单与死循环（连续 2 次无进展或 3 次同错自动标为卡死）。
4. **一份 Markdown 导入/分享整支团队（`bot.md` / `team.md`）**：把整队角色的人设、分工、技能包和定时计划打包成一份可读文档或压缩包，别人拖进界面即可导入整支小队（导入时自动关闭外部连接、暂停定时任务，不带任何个人密钥和聊天记录）。
5. **多引擎与多账号接入**：既能调用本机已装的 16+ 种编码 CLI（Claude Code 支持多账号并存、Codex、Grok、Cursor、Copilot、OpenCode、Pi、Cline 等，以及零代码接入任意兼容 ACP 的工具如 CodeBuddy、ZCode），也能直接填 API Key 用 OpenRouter、DeepSeek、智谱 GLM、通义千问、Ollama 本地模型等。
6. **四级“动手环境”（Computers）与内置浏览器**：
   - 内置受控浏览器（每个角色独立登录态分区，带实时画面预览，遇到登录框或验证码弹卡片请真人接管点一下）；
   - 本机隔离虚拟机（通过 Docker 或 Podman 启动独立 Linux 桌面容器，带实时远程桌面画面）；
   - 直接操控本机桌面（`This Computer`，用内置驱动截屏并移动真实鼠标键盘，支持录制“固定步骤”回放）；
   - 云端电脑（官方合作 Boat 云桌面，或用户自备 Linux 云服务器）及 USB 连接操控安卓手机（ADB）。
7. **结构化分层记忆与夜间自动整理**：按纯文本 Markdown 存放角色核心记忆（`MEMORY.md`，界面显示容量条）、主题笔记、每日工作日志、跨角色团队共享记忆与全局“关于我”；带追加式修改日志和**一键撤销**，还支持凌晨后台整理记忆（要求核对用户原话才准记入事实）。
8. **自动化引擎（Routines / Webhooks / 应用事件 / 稍后回查）**：可视化日历定时（单次、工作日、间隔、Cron 表达式、甚至“等我的订阅额度重置时自动跑”）、电脑休眠苏醒后 12 小时内智能补跑与防重叠账本、对话内“2 小时后回查（`check_back`）”、独立本地端口 Webhook 接收器，以及监听 Gmail/Slack/GitHub 新消息自动触发。
9. **连接外部应用、自定义 MCP 与密码保险箱（Vault）**：通过 Composio 一键 OAuth 连接 500+ 外部软件；支持把一行命令或 JSON 直接粘贴进输入框自动识别添加 MCP 工具，并对工具过多的服务自动折叠检索、对超长返回自动截断；内置密码保险箱（亦支持对接 1Password、Bitwarden）代填网页登录与动态口令。
10. **语音播报与通话、数据看板、网页发布与会议记录**：支持多引擎文字转语音朗读（含把 Markdown 代码块和表格自动改写成顺口人话的处理器）及实时语音对讲；内置 DuckDB + Vega-Lite + 表格组件做本地数据分析看板；支持一键发静态网页到 Netlify；支持派机器人进线上会议记纪要。
11. **对外控制接口与用量上限阀门**：可把整个工作台自身暴露成 MCP 服务或命令行供外部调用，支持按全服和单角色设置每日/每月美元或 Token 上限，超限自动暂停无人值守任务。

### 2.3 Agent 怎样组织、协作与人工介入

- **组织形态**：**一组各有分工的常驻角色（多 Agent 团队）**，而非单一通用框。「官方文档」`docs/team-sharing.md`、`docs/runtime-contract.md`
- **协作机制**：由 `server/runtime/runtime.db` 统一调度。主理人（Chief）或任一角色调用 `coordinate_bots` 把工作拆成 `work`（正式子任务）、`consult`（快速咨询）、`notify`（知会）或 `steer`（给正在跑的队友补指令），子任务完成后把结果回传唤醒父任务。「官方文档」`docs/runtime-contract.md`
- **人工介入方式**：① 审批卡片（允许/拒绝危险动作）；② 提问卡片（Agent 遇到拿不准的选择题弹卡片等人类点选，子角色不懂时必须往上问人类，禁止让另一个 AI 替人类拍板）；③ 浏览器/桌面实时画面里的 **“Take control（我来接管）”** 按钮，真人登完账号再点“交还给 AI”；④ 聊天中途随时插话纠偏或点停止。「官方文档」`docs/approval-levels.md`、`docs/provenance-label.ts`

### 2.4 Agent 能动手的范围、隔离环境与权限审批

- **动手范围**：从最轻的“只读写自己工作目录”，到操控内置浏览器、操控本地/云端 Linux 桌面虚拟机，最重可直接控制**你正在用的整台电脑屏幕与键鼠**，甚至通过 USB 线点按安卓手机。「官方文档」`docs/computer-use-integration.md`、`apps/docs/content/docs/mobile/android-control.mdx`
- **隔离程度**：
  - **云端托管版（MausBot Cloud）**：每轮对话默认关在 Linux `bubblewrap` 轻量沙箱（`server/bot-box/`）里，隐藏主数据库与其他角色的登录文件，并经过出站代理拦截内网访问。「官方文档」`docs/bot-box.md`
  - **本机桌面版（Windows / macOS）**：如果不手动配置 Docker/Podman 本地虚拟机，Agent 跑命令时**默认直接运行在你的本机系统账号下（无系统级沙箱）**；只有内置浏览器带有独立 Cookie 分区和禁止访问局域网地址的 SOCKS 代理门禁。「官方文档」`SECURITY.md`、`apps/docs/content/docs/computers/local-computer.mdx`
- **权限与审批（关键风险发现）**：提供五档（每次询问 `Ask`、自动改文件 `Auto-accept edits`、让模型代审 `Approve for me`、完全放行 `Full access`、自定义配置）。但源码与设计准则明确规定：**新建角色和新对话的默认档位竟然是 `Full access`（即给底层 Claude/Codex 传 `bypassPermissions` / `danger-full-access`，默认不弹审批直接执行）**！「官方源码」`DESIGN.md` 第 2 节、`docs/approval-levels.md`。不过它在防外部欺骗上做了一个很好的设计：给每条非本人手打的消息加上不可伪造的 `[From 谁 · 什么类型 · 权限级别]` 标签，所有外部 Webhook、应用事件默认标为 `information only`（仅作参考资料，无权批准操作或提权）。「官方源码」`server/provenance-label.ts`

### 2.5 模型与账号支持

- **复用本机已安装 Agent 及其登录**：原生支持，且是主打卖点。本机装好的 Claude Code（甚至支持在同一界面切换多个 Claude 订阅账号）、Codex（支持浏览器设备码登录）、Grok CLI、Cursor、Copilot 等直接复用各自的订阅额度，无需二次买 API。「官方文档」`apps/docs/content/docs/providers/index.mdx`、`docs/custom-engines.md`
- **自定义 API 与本地模型**：内置 `openai-compat` 等直连驱动，支持填任意第三方 Base URL 与 API Key（OpenRouter、DeepSeek、智谱、千问、MiniMax 等），并能自动发现本机运行的 Ollama / LM Studio 模型（自动把 Ollama 默认过小的 4k 上下文扩到 16k～64k）。「官方文档」`apps/docs/content/docs/providers/model-providers.mdx`

### 2.6 记忆、长期运行与外部工具连接

- **记忆**：全部存为角色工作目录下的明文 Markdown 文件（`MEMORY.md` 限前 200 行/24KB 自动注入，超限自动归档旧条目；另有主题笔记与日志），每轮自动按相关性召回最多 4 篇笔记 + 4 段历史对话，所有自动改写都记入独立账本支持一键回退。「官方文档」`docs/memory.md`
- **长期运行**：进程内调度器（基于 `croner` 库），支持日历定时、间隔、额度重置触发和 `check_back` 延时回查；前提是桌面软件开着（支持插电时在任务前 1 小时防电脑休眠，合盖仍会睡）。Webhook 单独监听 `127.0.0.1:8800`，不暴露主控制口；第三方应用事件通过 Composio 每 25 秒长轮询拉取，无需公网端口（桌面免费版走官方托管中转每天限 500 条事件；自备 Composio Key 目前反而还不支持事件监听）。「官方文档」`docs/routine-schedules.md`、`docs/composio.md`
- **连接外部工具**：一条是面向普通人的 **Composio 一键网页授权**（连邮箱、日历、Slack、GitHub 等）；另一条是 **Custom MCP**（支持粘贴命令/网址、OAuth 2.1 自动登录、自动扫描导入 Claude/Codex/Cursor 里已配好的 MCP 和技能包，并用 `OMB_MCP_RESULT_BUDGET` 限制单次返回默认不超过 8,000 字符防止撑爆上下文）。「官方文档」`docs/custom-mcp-servers.md`

### 2.7 手机与远程访问及加密情况

提供 5 种连接路径，配有独立的原生 iPhone（SwiftUI）与 Android 伴侣应用（源码不在主仓库，上架应用商店），也可直接用手机网页访问：「官方文档」`docs/phone-web-app.md`、`docs/phone-relay-server.md`、`docs/ios-companion.md`、`docs/self-hosting.md`

1. **同一 Wi-Fi 直连**：局域网明文 HTTP（`:8810`），**不加密**；为此它在检测到非加密局域网连接时，主动禁止在手机上输入密钥和保险箱密码。
2. **Tailscale 组网**：走 WireGuard 隧道，**全程加密**。
3. **Cloudflare Tunnel（`--tunnel`）**：生成临时 HTTPS 域名，**传输层 TLS 加密**（Cloudflare 边缘节点解密转发）。
4. **自有域名 + Caddy**：标准 **HTTPS 加密**。
5. **官方/自建中转（`--relay`）**：采用 **Noise `NKpsk0` 协议 + AES-GCM 端到端加密**，中转服务器只能看到密文，看不到任何聊天内容；此外手机扫码配对提交凭据时额外使用 **RFC 9180 HPKE（P-256）非对称加密**，防中间人窃听。

### 3.1 它到底是什么、给谁用、怎么用（是否必须用命令行）

- **定位**：当年商业产品 Manus 爆火但需要邀请码时，MetaGPT 团队用几小时搭出来并开源的**轻量级 Python 通用 Agent 实验框架**。「官方文档」`README.md`、「官网」`openmanus.github.io`
- **目标用户**：会写 Python 代码、想自己改提示词或接工具做实验的开发者与研究人员。
- **怎么用（是否必须用命令行）**：**必须使用命令行，且必须手动复制并编辑 `config/config.toml` 纯文本配置文件**。运行方式是在终端敲 `python main.py`、`python run_flow.py` 或 `python run_mcp.py`。官方 `main` 分支**没有正式图形界面**（仓库虽有早期实验性的 `front-end` / `desktop` 分支，但并未合入主线正式交付）。对不写代码、不用命令行的游戏制作人而言，无法直接上手使用。「官方源码」`main.py`、`config/config.example.toml`

### 3.2 完整功能清单

代码体量很小，全部能力一览无余（「官方源码」`app/`、`protocol/`）：

1. **单通用 Agent 循环（`Manus`）**：默认最多自动思考并调工具 20 步（`max_steps = 20`），自己决定何时查网页、写脚本、改文件、输出结果后结束。
2. **浏览器自动化工具**：调用 `browser-use` / Playwright / Crawl4AI 打开 Chrome 浏览器访问网页、点击按钮、填表、滚屏、抓取正文或提取内容。
3. **本机代码执行与文件编辑**：内置 `PythonExecute`（直接跑一段 Python 代码拿打印结果）、`Bash`（开终端会话跑命令）、`StrReplaceEditor`（按字符串替换修改本地文件）。
4. **多 Agent 顺序规划流程（`PlanningFlow`）**：在 `run_flow.py` 中先由大模型列一个步骤清单（`PlanningTool`），再按步骤顺序分别交给通用 `Manus` 或数据分析 `DataAnalysis` Agent 执行（官方 `README.md` 自己注明该多 Agent 版本“unstable / 不稳定”）。
5. **数据分析与图表生成（`DataAnalysis`）**：读取表格数据跑 Python 分析脚本，并借助前端图表脚本生成可视化图表文件。
6. **云端沙箱版（`SandboxManus` / Daytona）**：对接第三方云沙箱平台 Daytona，在远程容器里启动浏览器与桌面（支持 `ComputerUseTool` 坐标点击截屏及 VNC 网页预览链接）。
7. **MCP 客户端/服务端与实验性 A2A 协议**：支持连外部 stdio/SSE MCP 工具（`run_mcp.py`），支持把自己包装成简易 MCP 工具（`run_mcp_server.py`），以及 `protocol/a2a/` 下一个不支持流式输出的 Google A2A 协议演示服务。

### 3.3 Agent 组织、协作与人工介入

- **组织形态**：默认是**单个全能型通用 Agent**（`main.py`）；可选开启 `PlanningFlow` 做简单的“列计划 → 按步串行调子 Agent”，没有常驻角色列表、没有群聊讨论室、也没有并行派单防死循环。「官方源码」`app/agent/manus.py`、`app/flow/planning.py`
- **人工介入**：几乎全自动黑盒跑到底。唯一的人工介入工具是 `AskHuman`（`app/tool/ask_human.py`），总共只有 21 行代码——**只有当大模型自己主动想起来调用它时，终端才会停在 `input("Bot: ...")` 等人敲字回车**；人无法在界面上看卡片点批准，也无法在浏览器弹窗时顺滑接管再交回。「官方源码」`app/tool/ask_human.py`

### 3.4 动手范围、隔离环境与权限审批

- **动手范围**：能操控浏览器、在本机直接 `exec()` 执行任意 Python 代码、开 `/bin/bash` 跑任意系统命令、改本机任意可访问文件；在 Daytona 模式下还能模拟桌面鼠标键盘点击。「官方源码」`app/tool/python_execute.py`、`app/tool/bash.py`、`app/tool/computer_use_tool.py`
- **隔离环境**：
  - 虽然代码里有 `DockerSandbox`（`app/sandbox/core/sandbox.py`），但示例配置中 **`use_sandbox = false`（默认关闭）**！也就是说默认直接在你的宿主机系统上裸跑 Python 和命令。「官方源码」`config/config.example.toml`
  - 示例配置里浏览器参数甚至写着 `disable_security = true`（关闭浏览器同源安全策略）；Daytona 云沙箱若未配密码，VNC 远程桌面密码在源码里硬编码回退为弱口令 `123456`。「官方源码」`config/config.example.toml`、`app/daytona/`
- **权限与审批**：**完全没有权限分级，也没有任何人工审批拦截器**。模型只要输出工具调用，框架立刻直接执行。

### 3.5 模型与账号支持

- **不能使用本机已安装的 Claude Code / Codex / CodeBuddy 及其订阅登录**。「官方源码」`app/llm.py`
- **只支持填 API Key**：支持 OpenAI 兼容接口（OpenAI、DeepSeek、OpenRouter、硅基流动等）、Azure OpenAI、AWS Bedrock、Ollama 本地接口（可给视觉任务单独配一个 `llm.vision` 模型）。「官方源码」`app/llm.py`、`config/config.example.toml`

### 3.6 记忆、长期运行与外部工具连接

- **记忆**：**没有任何跨会话长期记忆，甚至没有本地数据库**！它的 `Memory` 类（`app/schema.py`）只是一个内存里的消息数组，最多留最近 100 条消息，终端窗口一关全部清空。「官方源码」`app/schema.py`
- **长期运行**：**无定时任务、无文件监控、无 Webhook 事件触发**，跑完单次命令即退出。
- **外部工具连接**：仅支持在 `config/mcp.json` 或命令行参数里配置连接 MCP 服务，无 OAuth 应用商店或密码保险箱。「官方源码」`run_mcp.py`

### 3.7 手机与远程访问

- **完全没有**：无手机应用、无手机网页适配、无局域网配对、无加密中转。实验性的 `protocol/a2a` 默认只监听明文 HTTP `:10000` 且无鉴权。

### 3.8 技术栈、代码规模、许可证、维护状态与已知问题

- **技术栈与代码规模**：Python 3.12，核心仅 **90 个 Python 文件、12,297 行代码**（外加 1 个图表辅助 TS 脚本），不到 OpenMausBot 代码量的百分之一。「官方源码」文件统计
- **许可证**：**MIT 许可证**（非常宽松）。「官方源码」`LICENSE`
- **维护状态**：虽然历史星标高达 **59,038**（因早期开源复刻热点暴涨），但**主分支自 2026-08-16 起已超 3 个月无新提交，最新正式 Release 停留在 2025-04-10 的 `v0.3.0`**，处于维护大幅放缓状态，当前仍有 **227 条未关闭 Issue**。「GitHub API」
- **已知问题与安全漏洞**：社区 Issue 直接指出了多处高危隐患且尚未合入修复——例如 `#1508` 指出 `Manus` 把不可信外部 MCP 服务返回的说明文字直接拼进最高权重的系统提示词（我们在 `app/agent/manus.py` 第 166～170 行核实确有此事！），且沙箱文件操作存在未转义命令行拼接；`#1506` 指出路径清理函数可被绕过导致目录穿越；此外大量用户反馈跑任务时容易陷入重复循环烧掉大量 API 费用。「GitHub API」「官方源码」`app/agent/manus.py`

### 3.9 安全与隐私

- **密钥保存**：所有模型 API Key、搜索服务 Key、Daytona 云平台 Key **全部明文写在 `config/config.toml` 文件里**，没有任何加密。「官方源码」`config/config.example.toml`

### 4.1 两个项目的核心区别与主参考建议

| 维度 | OpenMausBot | OpenManus | 对我们的启示 |
|---|---|---|---|
| **产品形态** | 面向普通人与团队的图形界面聊天工作台（Electron + Web + 手机端） | 面向程序员的命令行 Python 脚本框架 | 你需要的是全界面操作的工作台，OpenMausBot 形态完全吻合 |
| **账号成本** | 直接白用本机已登录的 Claude Code / Codex 等订阅，也支持自有 API | 只能填 API Key 按量扣费，不支持本机 CLI 订阅 | 与我们“第三方沿用自身登录 + 独立 Agent 自有 API”路线一致 |
| **Agent 组织** | 常驻角色名册 + 部门主理人拆活 + 群聊讨论室 + Markdown 团队导入 | 单通用 Agent 循环 + 简易不稳定串行规划 | 常驻岗位与团队协作正是制作人管项目最顺手的方式 |
| **安全与审批** | 有审批卡片与防注入来源标签，但默认 `Full access` 太激进 | 完全无审批、默认裸跑宿主机、明文存 Key | 吸收 OpenMausBot 的防注入标签，但坚持我们“默认需审批”的底线 |
| **长期与外联** | 完整分层记忆 + 日历定时/补跑 + Webhook + 500+ 应用 + 手机端加密 | 关掉窗口即失忆，无定时、无事件、无手机端 | 长期记忆、自动化与外部工具管家以 OpenMausBot 为主要参照 |
| **独特亮点** | 团队模板导入、MCP 大返回限流、语音口语化朗读、花费上限阀门 | 开放式“自己开浏览器查竞品/抓资料 + 跑脚本出图表报告” | 把 OpenManus 的“网页调研+数据报告”做成工作台里的受控工具与角色模板 |

**结论建议**：**坚定以 OpenMausBot 作为主要功能对标对象，同时只从 OpenManus 吸收“受控浏览器网页调研/操作”与“本地表格数据分析汇报”这两个具体业务能力**。原因很简单：你是游戏制作人，不用命令行，手里已经有 Claude Code、Codex、CodeBuddy 和独立模型 API，你想扩充的是“组建自己的 AI 制作班底、让它们记住项目背景、定时巡检、连办公工具、帮忙查网页资料并在手机上随时拍板”，这正是 OpenMausBot 验证过的产品方向；而 OpenManus 既没有界面、又不能用你的订阅账号、还没有安全审批，重造一套 Python 框架只会跟现有 TypeScript 工作台割裂。

### 4.3 能力取舍：按“我能用它做什么”逐项评估（不做菜单照搬）

围绕游戏制作人的真实日常工作，把所有候选能力分成**“第二阶段做”“留到第三阶段做”“明确不做”**三档：

#### 一、纳入第二阶段做的能力（高价值、本机可控、零强制付费云依赖）

| 我能用它做什么（对制作人的实际价值） | 大致实现成本 | 是否必须依赖第三方在线服务？费用、数据外发与断网/故障预案 |
|---|---|---|
| **1. 给外来的网页、通知和插件戴上“防欺骗手环”（安全基线）**：防止外部网页或通知里藏恶意指令骗 AI 删改工程或偷发密钥，限制子进程能看到的敏感环境变量。 | 中（1 个单会话步） | **否（纯本机逻辑，\$0）**。数据不出本机，断网完全可用。这是后面连工具、看网页、做自动化的强制前置条件。 |
| **2. 一眼看清今天/本月花了多少额度，设自动刹车线（监控与花费上限）**：半夜跑定时任务或让几个角色讨论时，一旦达到你设的每日/每月上限，自动停掉后台无人值守任务，但绝不拦你亲手发的消息。 | 小～中（1 个单会话步） | **否（纯本机账本汇总，\$0）**。数据不出本机。若第三方 CLI 未返回精确美元，同时支持按 Token 数设上限。 |
| **3. 在网页上一键给 AI 装工具和工作套路（能力中心：MCP + 技能包）**：粘贴一段配置或点一下就能把本地已装 Claude/Codex 里的好用插件和技能导入工作台，比如读 Excel 数值表、查设计文档；自动截断超大返回防止卡死。 | 中（拆为 2 个单会话步） | **框架本身纯本机（\$0）**。连本机工具（如读本地表格/文档）数据不出本机；若你自选连某个在线 MCP（如飞书/GitHub），仅对应查询发给该服务，对方故障时网关自动报错降级、不拖垮对话。 |
| **4. 组建常驻“AI 制作班底”并记住项目设定（常驻岗位 + L2 长期记忆 + Markdown 团队导入）**：配好“主策助理、世界观校对、数值检查员、代码审查员”等常驻岗位，它们长期记住你的游戏设定（写错还能一键撤销）；还能用一份文档把整支小队备份或分享出去。 | 中（1 个单会话步） | **否（纯本机 SQLite + Markdown，\$0）**。记忆全部存在本机数据目录，不上传任何云端。 |
| **5. 拉几个岗位进“讨论室”会审方案，或让“主理人”拆活并行干，顺手还能开侧聊**：评审新玩法时让主策、数值、技术三个角色在讨论室各提意见再由主理人汇总；做主任务时不懂的术语在右侧“侧边聊天”随手问，不弄乱主线。 | 中～大（1 个单会话步） | **否（纯本机调度，仅消耗你原有模型额度）**。内置死循环刹车（最多允许限定轮数委派），某个角色报错时主理人如实汇报人工介入。 |
| **6. 让工作台定时巡检、盯表格改动，先用便宜模型过滤杂事（快速判断 + 日常自动化 + 稍后回查）**：设“每天早上 9 点汇总昨晚提交与未过测试”“数值表保存时自动查配表冲突”，或跟 AI 说“半小时后帮我看下打包完没”；电脑休眠醒来自动按规则补跑一次，不连发轰炸。 | 中（1 个单会话步） | **否（纯本机调度，\$0）**。快速判断层优先用你已配的便宜小模型或免费本地模型（如 Ollama）；若未配小模型，降级为按固定关键词规则过滤或直接唤醒目标角色。 |

| **8. 让 AI 在受控浏览器里帮你查竞品网页，长篇报告点一下读给你听（受控网页浏览 + 语音朗读）**：吸收 OpenManus 的调研强项与 OpenMausBot 的接管设计——复用电脑自带的 Edge/Chrome 开独立隔离窗口查资料截图，遇到登录或验证码弹窗请你在真窗口点一下（工作台绝不碰验证码）；长回复自动去掉代码符号用系统语音免费朗读。 | 中（1 个单会话步） | **默认零付费依赖（\$0）**：浏览器复用本机已装 Edge/Chrome，语音默认用浏览器/Windows 原生离线语音（数据不出本机，断网可读）。可选预留自有 TTS API 接口，云语音挂掉时自动切回系统语音。 |

#### 二、留到第三阶段再做的能力（重工程或属于既有远期规划）

| 能力 | 为什么不在第二阶段做（留到第三阶段） | 外部服务与费用说明 |
|---|---|---|
| **游戏资产浏览、三维预览与媒体生成（生图/音视频）** | 这是 `phase-1.md` 原有的核心特色方向（[media-gen.md](media-gen.md) 已调研），与第二阶段“先把 Agent 团队、工具和自动化底座搭稳”正交，放第三阶段专心做好体验。 | 生图/生视频通常按量调用云 API（如豆包/通义/Fal 等）或本机显卡跑 ComfyUI（\$0 但吃显卡）。 |
| **出门在外用 4G/5G 手机连回家里电脑（外网安全访问）** | 在没做好全套网络安全审计前直接暴露公网风险极高。短期若急用，可零代码配合免费加密组网工具（如 Tailscale）；自研端到端加密中转（参考 OpenMausBot 的 Noise + HPKE 方案）留到第三阶段连同手机体验一起做。 | Tailscale 个人版免费（\$0，WireGuard 点对点加密）；若以后自建云服务器中转约 ¥30～50/月。 |
| **独立桌面安装包（Tauri）与原生手机 App** | 现在的双击启动器 + 手机自适应网页已覆盖 90% 场景，等第二阶段新增的讨论室、能力中心、监控页界面定型后再打包客户端，避免双端反复返工。 | Windows/macOS 正式代码签名证书若要消除系统拦截提示需每年付费（约 \$100～\$300/年），自用可暂不买。 |
| **本地隔离虚拟机（Docker/Podman 桌面容器）** | 对不敲命令的制作人来说，装 Docker/WSL2 排错门槛高且占数 GB 内存；第二阶段先用工作副本 + 受控浏览器解决 95% 需求，确需重度隔离执行陌生软件时第三阶段再引入一键容器。 | 纯本机免费（\$0），吃本机内存与磁盘。 |

#### 三、明确不做的能力（高风险、云锁定或偏离定位）

1. **不做“新建角色默认全盘放行（`Full access`）”**：OpenMausBot 为了省点击把默认权限设成全放行，一旦遇到提示词注入后果严重。我们坚持默认“需审批”或受控工作副本内操作。
2. **现阶段不做“让 AI 直接抢你正在用的本机鼠标和键盘（`This Computer` 宿主机键鼠接管）”**：AI 在无隔离宿主机上乱点可能误发微信/邮件、误删文件，还会跟你的手抢鼠标，Windows 上兼容性和杀毒软件误报也多，风险远大于收益。
3. **不绑死任何付费中间商 SaaS（如强制接 Composio 云中转或 Boat 云电脑）**：Composio 免费版每天限 500 条事件且把你的第三方授权托管在别人云上，Boat 云电脑按月收费（\$15～\$99/月）且工程文件全上传云端。我们统一走开放的本机标准 MCP 协议，账号只留在你自己的电脑里。
4. **不做自动破解或绕过网页验证码**：无论技术还是合规红线都严禁触碰；网页工具遇到登录框、人机验证或付款页一律暂停并弹提示由制作人亲自在窗口完成。
5. **不加任何后台遥测统计（如 PostHog）**：你的游戏企划案、数值表和对话记录 100% 留在你本机，工作台绝不往任何统计服务器发一条使用数据。
6. **不做线上会议跟会机器人、静态建站发布、企业计费白标（`enterprise/`）**：与个人游戏制作人智能工作台定位无关，徒增维护负担。

### 4.4 OpenMausBot 代码借用与参考边界分析

OpenMausBot 是 TypeScript + Node 24 + `node:sqlite` 技术栈，且除 `enterprise/` 外采用 **Apache-2.0** 开源许可证，和我们技术栈高度同源。核查源码后划分如下：

#### 1. 适合直接借用并按本仓规范裁剪的小模块（纯逻辑、耦合极低、均在 Apache-2.0 范围内）

| 对方源码文件 | 作用 | 借用方式与收益 |
|---|---|---|
| `server/provenance-label.ts` + `server/peer-provenance.ts` | 给非本人直发的消息打 `[From 谁 · 类型 · 权限]` 防伪标签，并转义正文里试图伪造标签的括号和分隔符 | 仅百余行纯字符串逻辑，零外部依赖，可直接改写进 Gateway 消息拼装层，低成本建立防提示词注入第一道防线。 |
| `server/tts/speech-text.ts` | 把含代码块、表格、长路径、链接的 Markdown 回复改写成顺畅的口语朗读文本 | 约 238 行独立模块，改成中文提示词（如“一段 TypeScript 代码”“一张图片”）后直接用于第 2.9 步语音播报。 |
| `server/bot-box/egress-gate.ts`（及 `server/browser/egress/` 地址表） | 自己先解析域名并拦截 `127.0.0.1`、局域网私有网段、链路本地与云元数据地址，防 DNS 重绑定绕过 | 约 130 行基于 Node 原生 `node:http` / `node:net` 的代理门禁，可直接用于受控浏览器与不可信工具的出站防护。 |
| 自定义 MCP 智能粘贴解析与结果字符预算（`OMB_MCP_RESULT_BUDGET` 思路） | 识别用户粘贴的是命令行、`npx` 还是 JSON 配置；对超过阈值（如 8,000 字）的工具返回做安全截断摘要 | 解析与截断纯函数可直接移植，大幅降低非技术用户配 MCP 的门槛。 |

#### 2. 只适合参考设计思路、绝不直接搬代码的模块

- **前端界面组件（`src/`）**：对方重度绑定 React 19 + Tailwind 4 + Electron IPC；而我们网页端是零框架原生 TypeScript + CSS Token + 严格只走 `/api/v1` 协议，强搬只会破坏架构。
- **任务运行时与数据库（`server/runtime/`）**：对方另起一套 `runtime.db`；我们已经有一套经过 1,226 项测试验证的单写锁 SQLite 事件库与工作副本状态机，只借鉴它的“父子任务关联、相同并发请求去重、连续无进展刹车、休眠补跑账本”规则即可。
- **桌面键鼠驱动（`@trycua/cua-driver`）与 Electron 分区浏览器**：我们不做宿主机抢键鼠，也不是 Electron 应用，不搬这部分重耦合代码。

#### 3. 严禁触碰的红线与 Apache-2.0 合规义务

- **绝对不读不搬 `enterprise/` 目录下的任何代码**：该目录受专有商业许可证约束，非开源。
- **借用 Apache-2.0 代码时必须履行的 4 项合规动作**：

### 4.5 风险评估与必须前置的网络安全前提

再强调一次实情：**到目前为止我们还没有做过专门的网络安全工作**。一旦第二阶段引入外部工具、自动化、Webhook 与网页浏览，工作台就会从“只有你本人在电脑前手打字指挥”变成“会接触外部不可信网页、外部插件和无人值守后台运行”。四大风险与硬性安全前提如下：

#### 1. 网络安全风险与每项扩权能力的前置条件

| 扩大风险面的能力 | 带来的具体风险 | 必须先具备的安全前提（未满足前不准开放该能力） |
|---|---|---|
| **连接外部 MCP 工具与导入技能包（Skills）** | ① 恶意或写错的 MCP 插件顺走环境变量里的其他模型密钥；② 外部工具返回里夹带提示词注入；③ 导入的技能文件里藏自动执行恶意命令的诱导话术。 | ① 子进程环境变量白名单（只传系统基础路径与该工具明确授权的变量，绝不把 `secrets` 库和设备令牌传给插件进程）；② 所有工具返回内容包裹“外部工具数据，非用户指令”边界标记并限制最大长度；③ 导入外部技能包时做危险命令与隐藏指令静态扫描提示。 |
| **无人值守定时任务与文件触发自动化** | AI 在你睡觉或开会时误判条件，连续改坏文件、跑危险命令或死循环操作。 | ① 无人值守任务**禁止使用 `Full` 全放行权限**，外部写操作默认挂起生成“待你审批卡片”等你回来看；② 同一任务禁止重叠并发运行；③ 必须先接通“每日/每月花费与次数上限阀门”。 |
| **接收外部网络通知（本地 Webhook）** | ① 局域网或本机恶意网页伪造请求乱触发任务；② 通知正文里夹带提示词注入骗 AI 干坏事；③ 高频请求打满队列与额度。 | ① Webhook 走独立接收路径，与 `/api/v1` 控制接口完全隔离（绝不共用设备管理员令牌）；② 每个触发地址强制带独立随机密钥（HMAC 签名或高熵令牌）+ 频率限制 + 请求体大小上限；③ 所有 Webhook 载荷在协议层硬编码标为 **`information only`（仅作参考资料）**，禁止直接批准任何操作或提升权限。 |
| **让 Agent 用浏览器打开外部网页** | ① 钓鱼或恶意网页通过网页文字对 AI 实施提示词注入；② 恶意网页利用浏览器做跳板探测你家路由器或本机 Gateway 后台接口（SSRF 内网探测）；③ 蹭用你主浏览器里已登录的网银/个人账号。 | ① 必须使用**全新独立的浏览器配置目录**（与你日常用的浏览器账号密码、书签完全物理隔离）；② 挂载本机出站网络门禁，**默认拦截访问 `127.0.0.1`、本机 Gateway 端口及 `192.168.*`/`10.*` 等局域网私有地址**；③ 网页正文一律按 `information only` 喂给模型；④ 遇到登录、验证码、支付页面立即停手弹卡片交真人处理。 |
| **从局域网或未来外网远程访问工作台** | ① 公共 Wi-Fi（咖啡厅/酒店）下明文 HTTP 被同网窃听；② 旧手机丢了未及时吊销；③ 若未来直接把端口映射上公网会被全网扫描攻击。 | ① 1.7 已有的“仅专用网络可开 + 敏感操作需电脑端弹窗确认”保持不变，且**在明文局域网连接下一律禁止新增/查看 API Key 明文**（学 OpenMausBot 的好做法）；② **第二阶段严禁直接把 Gateway 端口暴露到公网**；第三阶段若做外网访问，必须先上 TLS/HTTPS 或 Noise/WireGuard 端到端加密。 |
| **（若未来考虑）让 Agent 操控整台电脑桌面** | 误删电脑私人文件、误点聊天软件对外发消息、被屏幕上的恶意弹窗劫持。 | 第二阶段**不做**宿主机键鼠操控；未来若做，必须强制跑在独立的本地虚拟机/沙箱容器内，绝不在宿主机裸跑。 |

#### 2. 费用失控风险
- **来源**：多角色互相委派死循环、高频定时任务空转、独立 Agent 调昂贵大模型、外部 MCP 一次塞回几万字撑爆上下文。
- **对策**：① 第 2.2 步先上全工作台与单岗位每日/每月预算上限（支持按金额或按 Token 双口径，超限自动停掉无人值守任务）；② 多角色委派设硬上限（单次任务最多嵌套深度 2 层、最多委派 6 次，连续 2 次无实质进展自动熔断）；③ 快速判断层先用廉价小模型挡掉 80% 无事发生的巡检；④ MCP 单次返回超 8,000 字自动截断摘要。

#### 3. 稳定性风险
- **来源**：OpenMausBot 的前车之鉴就是功能堆太快导致 1,024 个未关 Issue 和频繁白屏崩溃；Windows 下子进程弹窗、孤儿进程残留、电脑休眠唤醒后定时器雪崩。
- **对策**：① 严守“每步一个小闭环、单会话可做完自验、离线全量测试不退步”；② 外部 MCP 子进程全部纳入现有 Windows Job Object 进程树清理并强制 `windowsHide: true`（绝不弹黑框）；③ 休眠唤醒超过 12 小时的过期定时任务只记一条“因关机/休眠已跳过”，12 小时内的只补跑最新一次且错峰间隔 15 秒启动。

#### 4. 外部依赖与断供风险
- **来源**：第三方云服务涨价、停服、国内网络连不上，或命令行 Agent 升级改了输出格式。
- **对策**：核心调度、记忆、自动化、能力中心、语音播报默认均可在纯本机完成；新增 npm 依赖前必须经过你本人同意，锁定精确版本，且只选活跃维护的 MIT / Apache-2.0 库。
