## 现象

phase-1 第 11.1 / 11.14 节要求项目目录及 git 仓库只有明确合并 / 回滚时写入，但第 11.3 / 11.6 / 11.7 节要求共享 git worktree、非 git 直接在原目录运行并快照。用户本次开工指令同时重申这些要求。

## 复现步骤

1. 对照第 11.1 条 2 与第 11.6 条 2：创建 worktree 需要在原仓库登记工作树并创建任务分支。
2. 对照第 11.14 第二条与第 11.7 条 2：shadow 的 Agent cwd 是项目目录，执行写入时已经改变原文件。

## 影响

无法同时满足完整字面约束；若直接选择一种，会改变用户文件保护承诺或默认工作区与合并行为。阻塞阶段 1 的工作区方案实现。

## 根因

规格混用了“独立文件工作副本”“共享仓库元数据”和“原目录快照恢复”，三者的写入边界不同。

## 处理方式

选项与建议完整记录在 [step-1.5](../acceptance/step-1.5.md) 的“阶段 1 前待决定”。建议 git 允许必要元数据写入、非 git 新任务使用独立副本。等待用户决定，尚未更改设计或实现。

## 验证

已完成文档交叉核对。未在本仓库或用户任何真实项目运行 worktree、合并、回滚试验。实现和临时项目验证尚未执行。
