| 关闭 | 2026-11-08 |

## 现象

原 Db.tx 的内层调用只增加深度，不建立保存点。外层捕获内层错误后正常返回时，内层错误之前的 SQL 也会提交。独立目录需要把模型、凭据引用、审计与事件一起回滚，不能沿用该行为；事件还须等最外层提交后通知。

## 复现步骤

1. 从提交 `d1a4b4b` 取项目自身 db.ts 到忽略的审查目录，在临时内存数据库复现，不操作实际数据。
2. 外层 Db.tx 中调用内层 Db.tx；内层插入 meta 测试行后抛错。
3. 外层 catch 该错误并正常返回，查询发现测试行数为 1；预期为 0。

## 影响

把多个目录操作组合为事务时，失败的操作可能留下部分记录。若在事务中即时发事件，客户端还可能看到最终回滚的变更。未据此宣称已经影响本机真实任务或凭据。

## 根因

嵌套事务未使用 SQLite SAVEPOINT；原 EventStore.append 在写入后立即通知，不等待外层提交。

## 处理方式

Db.tx 的内层使用保存点，内层回滚同时丢弃该层通知；新增 afterCommit，在最外层提交之后执行。EventStore.append 和新目录事件均按此通知，回滚时只丢弃通知与事务内记录；通知异常不逆转已提交业务。

## 验证

旧提交的隔离复现得到 rowsAfterCaughtInnerFailure=1。新测试覆盖外层回滚无事件、内层失败被捕获仍不留模型、后续正常操作可提交、既有 append 兼容，以及另一数据库连接在通知时可见新项；最终全量结果见 step-1.3。等待修复提交溯源，不提前填写哈希。

## 时间线

- 2026-11-08 修复：提交 `07edd5c`，相同内存数据库反例的插入残留从旧版 1 行变为 0 行。25 项新增目录测试及全量 350 项默认测试（3 跳过）、类型检查、构建通过，覆盖内层失败捕获、外层回滚和提交后通知；本问题改为 fixed，不代表独立 Agent 整体通过。
