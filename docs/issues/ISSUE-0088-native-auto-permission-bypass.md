## 现象

阶段 6 要求隔离任务对每个 Agent 开放四档权限，同时要求项目规则和始终禁止清单生效。但现有原生自动模式会直接运行部分工具，不发送 request_permission；Gateway 没有执行前的拦截机会。

## 复现与证据

本次只读代码核对，没有启动真实 Agent 或执行危险命令：

1. packages/adapters/src/acp/session.ts 的 applyInitial 注释明确说明 bypass / acceptEdits / auto 不会发来审批；当前通过限制模式防止这种放宽。
2. Claude / CodeBuddy 的 workspace / full 映射到 acceptEdits / bypassPermissions；Codex 对应 workspace-write / agent-full-access。见各适配器 index.ts。
3. Claude 会话元数据仍设置 allowDangerouslySkipPermissions=false；已安装依赖的 dist/session-mode.js 在 allowBypass 为 false 时不提供 bypassPermissions。这也是当前保护，不能为了显示四档直接删除。
4. Gateway 规则引擎入口是 onPermission；独立 Agent 的文件和命令可在执行前调用此入口，第三方已自行允许的工具不会经过这里。只观察 tool_call 事件后取消不能证明写入尚未发生。

## 影响

直接去掉权限档位限制，会削弱用户要求的原项目保护与始终禁止规则；工作副本路径本身不是系统沙箱。即使维持原生需审批模式，也不能声称覆盖第三方自己已允许、未上报的所有行为。

## 根因

计划将“原生自动执行”和“Gateway 对每次工具执行保留决定权”同时作为目标，但现有 ACP 接入只在 Agent 请求审批时获得决定权。
