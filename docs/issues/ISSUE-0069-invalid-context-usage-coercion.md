# ISSUE-0069：空上下文用量被强制转换成零

## 现象

ACP 的 usage_update 映射使用 Number() 转换 used、size 和 cost.amount。null、空字符串会变成真实零，负数被夹成零。

## 复现步骤

1. 离线向 UpdateMapper 输入 used: null、size: 100 的 usage_update。
2. 修复前得到 used: 0 的用量事件，无法区分未报告和真实零。

## 影响

可能把缺失的上下文或费用显示成零；真实补验没有观察到 null 输入，此问题由代码审查与离线复现发现。

## 根因

强制数值转换丢失原始类型，负数夹零掩盖无效报告。

## 处理方式

只接收上游明确报告的有限非负数值。used 或 size 无效时不发用量事件；金额无效时省略 cost，保留有效上下文。明确报告的零仍保留，不从其他字段推算。

## 验证

- 新测试覆盖 null、undefined、空串、数字字符串、负数、NaN、Infinity 和合法零。
- 临时恢复旧映射时两项新增测试失败，恢复修复后四项用量测试通过。完整检查待追加。
