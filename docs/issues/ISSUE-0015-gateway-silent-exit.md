# ISSUE-0015：Gateway 意外退出，没有留下错误信息

| 项 | 值 |
|---|---|
| 状态 | investigating |
| 类型 | bug |
| 严重程度 | 高 |
| 发现于 | 用户人工验证（2026-11-07） |
| 开启 | 2026-11-07 |
| 关闭 | |

## 现象

用户双击启动脚本，配对后点 [重新检测]。11:14:04 CodeBuddy 的探测会话关闭后，Gateway 进程退出，网页显示连接断开，终端窗口提示“AI Console 意外停止了”。用户关闭了终端窗口，错误信息没有保留下来。数据库里只有 13 条 agent.status 事件，没有任务；`agents.log` 最后一行是 `[agent:codebuddy:probe] 已关闭`。

## 复现步骤

未能复现：用独立数据目录的实例按同样操作连续 [重新检测] 6 次、[测试连接] 1 次，进程都正常。

## 影响

工作台整个停掉，所有任务中断；没有日志就无法定位。

## 根因

未查明。最可能的原因：同一时间 WorkBuddy 正在后台自动更新（11:16～11:17 安装目录被整体替换，2.115.0 → 2.165.0），更新程序结束了正在使用旧引擎的进程，进而让 Gateway 出现了未处理的错误。也可能是某个后台 Promise 被拒绝且没人处理：Node 默认会让整个进程退出。

## 处理方式

1. 新增 `packages/gateway/src/crash-log.ts`：未捕获的异常写完整堆栈到 `logs/gateway.log`，终端给出日志位置，然后收尾退出；未处理的 Promise 拒绝只记录并提示，服务继续运行。
2. 启动、已启动、正常退出、启动失败都写进 `gateway.log`，以后能从日志判断进程是怎么结束的。
3. CodeBuddy 不再使用 WorkBuddy 的内置引擎（ISSUE-0016），WorkBuddy 更新不会再影响 CodeBuddy 会话。

## 验证

- `crash-log.test.ts` 3 项：未处理拒绝不退出、未捕获异常写堆栈并只收尾一次、日志脱敏。
- 待观察：再次发生时，`gateway.log` 里应能看到原因；收到日志后补根因并关闭本单。

## 时间线

- 2026-11-07 开启：用户报告；查看日志和数据库，复现失败；加上兜底日志。
