# ISSUE-0123：历史工具审批丢失同一次调用的名称

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 中 |
| 发现于 | [1.6 阶段 7](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

Codex 首轮发起 mcp.aic-history.search，随后的审批仅显示“Codex 请求执行命令”。

## 复现步骤

1. 在新建临时 git 项目，将演示任务交给原生 Codex GPT-6 Luna，要求先搜索“北门”。
2. 核对工具开始事件、审批卡、审批结果和交接记录中成功的内部读取次数。

## 影响

用户无法从审批卡判断要批准的工具。此次没有放行，真实历史读取为零。

## 根因

原生适配器先报告命名的 MCP 工具，相关审批只附同一工具调用 ID、执行类型与状态。工作台仅用审批请求内的字段生成标题。

## 处理方式

只在同一会话、同一未结束的调用 ID 上沿用工具名称显示在审批卡。显示名称不改变权限判定。四个只读工具在 MCP 列表声明只读、非破坏性及本地范围，第三方是否免去其自身审批取决于客户端。

## 验证

真实任务 t_oFvf_Xkqe351 中有工具开始、审批到期和工具失败记录。原生消息分片明确称此次查询取消。离线 ACP 回归修复前读到泛化标题。

## 时间线

- 2026-11-18 开启。Codex 真实补验按停止条件结束，后续修复仅使用离线夹具。
- 2026-11-18 审批卡标题的缺陷已关闭。模拟 ACP 跨进程和两套主题已核对工具名称，审批权限保持原判定。真实模型成功读取另由 ISSUE-0001 跟踪。见 [本轮验收](../acceptance/step-1.6.md)。
