# ISSUE-0037：矛盾的 Responses 终态仍可能返回工具调用

| 项 | 值 |
|---|---|
| 状态 | investigating |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | [三协议传输内部验收](../acceptance/step-1.3.md) |
| 开启 | 2026-11-08 |
| 关闭 | |

## 现象

新传输组件审查时，回环 SSE 的事件类型为 response.failed / response.incomplete，但内层 response.status 伪称 completed 且含完整函数调用，driver 仍可能返回 tool_calls。新组件尚未提交或接入正式任务，没有发生真实工具执行。

## 复现步骤

1. 仅启动自建回环 HTTP 假服务，创建临时目录与内存凭据 fixture。
2. 发送 failed / incomplete 终态事件，内层返回 completed 和 read_file 函数调用。
3. 用真实 HTTP driver 接收，断言必须拒绝协议内容。
4. 修正前两项定向回归实际失败：Promise resolved tool_calls；修正后同两项通过。

## 影响

不能只相信内层状态授权工具，错误 / 未完成的外层终态同样是协议约束。错误对象与 completed 同现也不能按成功落盘。本次仅假接口，不代表任何用户供应商实际存在该行为。

## 根因

事件分支识别三种终态后都调用同一个内层解析器，没有比对外层类型与内层状态；完整 JSON 也未明确拒绝 completed 同时存在 error 的矛盾组合。

## 处理方式

三类事件的状态必须与事件后缀一致，否则整次拒绝；completed 且有非空 error 对象同样拒绝。仍需完整函数参数、已声明工具与 Gateway 审批，不能把完整 JSON 视作绕过错误终态的授权。

## 验证

两项修正前失败 / 修正后通过回归，另加 JSON completed + error 的拒绝验证；53 项新传输定向测试通过。最终全量检查及修复哈希完成后追加。

## 时间线

- 2026-11-08 开启：首次三协议组件提交前审查发现并以两项实际 HTTP 反例复现；修正后定向测试通过。正式独立任务保持关闭，无真实模型消息。
- 2026-11-08 最终源码 typecheck / test / build 均通过，默认测试 545 通过、3 项真实冒烟跳过，含两项事件矛盾与一项 JSON 错误组合回归；修复提交后补哈希并关闭，不宣称真实上游出现或修复了该行为。
