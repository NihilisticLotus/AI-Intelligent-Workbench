# ISSUE-0045：服务停止提示不明显且占位仍写重新连接

| 关闭 | |

## 现象

用户手动关闭本轮预览控制台后，Gateway 在 14:37:58 正常退出且端口释放。用户先反馈“没有出现停止提示”，进一步确认“左下角显示已停止，但没看到明显提示”。内嵌任务观察页已显示 down 文案，但为灰色普通提示，视觉强度弱于仍保留的 Claude 额度错误；同一输入框占位仍为“正在重新连接，恢复后可以继续发送”。

## 复现步骤

1. 在任务页保持既有暂停任务和未发送附件，不调用模型。
2. 关闭运行开发 Gateway 的控制台，等待网页进入 down。
3. 查看输入框上方的灰色停止提示，以及仍写“正在重新连接”的占位文字；对比更突出的旧 Agent 错误。

## 影响

服务确实停止后用户可能只注意到侧栏小字，无法迅速理解需要重新启动；停止状态和重连占位表述矛盾。此次尚不能证明原生 Chrome 在 3 秒内出现完整任务提示。

## 根因

Composer 的 offline-note 对普通断线和 down 共用灰色样式、图标和 status 语义；占位文字只按 online 判断，没有区分 down。

## 处理方式

按 ui-design 6.10 保持提示块不用描边，down 改用既有错误底色、警告图标、独立标题与 alert 语义，补齐对应占位；不改探测 / 重连策略、接口或草稿。同步 phase-1 9.4 和界面设计 v0.3.10。

## 验证

基线实际内嵌截图见 step-1.3-native-console-down.jpg；该截图不代替 Chrome 人工观察。修正后的完整检查与界面验证尚待补记，原意外退出根因继续由 ISSUE-0015 调查。
