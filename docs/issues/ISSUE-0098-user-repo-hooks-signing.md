## 现象

每条 git 命令都强制 `core.hooksPath=NUL`、`commit.gpgSign=false`，包括在用户项目里生成的合并提交和撤销提交，静默违反用户仓库的提交规则。

## 处理方式

- git 封装新增 `userCommit` 选项：只有用户项目里的最终提交（压缩合并的 commit、保留记录的 merge、撤销的 commit）按用户自己的钩子和签名设置执行，时限放宽到 5 分钟（签名可能要输入口令）。工作副本里的所有命令照旧不运行钩子、不签名。
- 任务改了提交钩子所在目录（`.husky`、`.githooks` 或 `core.hooksPath` 指向的项目内目录）时，不在用户项目里合并，返回 `manual_required`（reason `hooks`），避免运行 Agent 写的钩子。

## 验证

- 新增两项：用户自己的 pre-commit 钩子在合并时运行；任务改了 `.husky/pre-commit` 时合并被拦下、HEAD 不变。临时还原时失败。原有“检出钩子不执行”用例继续通过。
