## 现象

工作台把自定义 API 作为 Claude / Codex / CodeBuddy 的账号注入启动进程，真实补验也在尝试替换这些进程的认证。用户澄清期望第三方 Agent 使用自身设置与登录，AI Console 独立 Agent 使用工作台自己的自定义 API / 模型，新增模型保留已有配置。

## 复现步骤

1. 在当前 Agent 管理页打开某个第三方 Agent。
2. 添加“官方 API Key / 自定义地址”账号，派发使用该账号的任务。
3. 当前实现通过该适配器的环境变量和认证启动第三方引擎；没有真正独立的工作台 Agent 执行器。

## 影响

产品配置归属与用户需求不一致。子进程环境隔离或未改写全局文件，均不足以证明实现了工作台独立 Agent。旧 API 补验不能作为新需求验收通过。

## 根因

旧设计限定“不自研 Agent 和模型调用”，并将自定义 API 放入各家 Agent 的账号配置。实现沿用了这一错误的产品边界；当前只有第三方适配器与演示 Agent。

## 处理方式

按用户要求同步架构、界面设计、计划与记录（phase-1 9.15）。停止新增旧认证补验，不再更改 Claude 设置来源。第三方配置链路整改、独立执行器选型与实现、旧工作台测试配置清理均待完成。

## 验证

已核对 design.md 旧目标、phase-1 6.4、profiles 创建逻辑及适配器 buildEnv。仅文档边界已修正，代码、正式界面、原型和新的独立 Agent 均未验证。不读取第三方凭据内容，不宣称其全局设置已被修改。
