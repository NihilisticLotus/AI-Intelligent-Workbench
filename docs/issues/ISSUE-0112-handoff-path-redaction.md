# ISSUE-0112：环境配置的值与真实改动路径重合时，交接可能给出不存在的文件名

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 高 |
| 发现于 | [1.6 阶段 3](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

临时任务里的人工环境配置为 `DEBUG=1` 和 `SCENE_FILE=Town.unity`。副本实际改动 `Level1.txt`、`Town.unity` 后，交接预览把两条路径显示为 `Level***.txt`、`***`，覆盖校验仍为通过。

## 复现步骤

1. 在新建的临时任务里录入上述合成工具输出。
2. 在该任务的工作副本新增这两个普通文件。
3. 用已配对的设备调用到另一个 Agent 的预览，核对实际文件名、交接路径和校验结果。

## 影响

接手方可能尝试打开副本里不存在的文件。两个文件若被打为相同标记，校验也难以区分。

## 根因

环境文件引用值与真实密钥共用普通子串替换。覆盖校验在替换后的路径上比较，无法识别被替换的文件身份。

## 处理方式

数字碰巧出现在文件名中的情况应保留真实文件名。普通环境配置值恰好等于完整项目路径的情况涉及发送哪些数据，按计划第 12.3 节第 16 条等待用户决定，选项见验收记录。工作台密钥、常见密钥格式和环境文件原文继续打码。

## 验证

真实预览接口在临时副本复现。使用的文件、配置和消息全部为人工样例；没有真实调用。

## 时间线

- 2026-11-18 开启：在交接预览核对改动路径时发现。
- 2026-11-18 用户选择 A。新增真实预览与 stdio 查询的回归用例，旧实现因两个文件名都不正确而失败。现用任务内稳定代号，全名匹配的路径统一显示为“已隐藏路径 1”，`Level1.txt` 和本地改动列表已核对。
