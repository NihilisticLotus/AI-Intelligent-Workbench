# ISSUE-0032：旧能力表单可能写入已变更的服务范围

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | [独立目录网页验收](../acceptance/step-1.3.md) |
| 开启 | 2026-11-08 |
| 关闭 | 2026-11-08 |

## 现象

能力覆盖原请求只校验模型 revision。服务地址或凭据修改会增加 configRevision，但不会改变模型 revision。打开的旧能力表单因而可能成功把人工值绑定到变更后的新范围。

## 复现步骤

1. 在临时目录数据库创建服务与模型，记录二者初始修订。
2. 修改服务地址，保留原模型 revision。
3. 旧能力请求不带服务配置修订时可以保存；新增 expectedConfigRevision 后，同一旧配置请求必须报冲突且无记录 / 事件残留。

## 影响

旧表单认知中的路由与实际保存的能力范围不一致。未据此宣称已发生真实服务误判或真实任务影响。

## 根因

模型编辑并发与服务范围并发是不同修订；仅校验前者不足以约束人工能力适用范围。

## 处理方式

协议追加可选 expectedConfigRevision，事务内核对；正式网页始终发送，冲突保留输入并禁止覆盖，用户明确载入最新模型和服务版本后再编辑。旧调用不传保持兼容，因此不宣称所有旧客户端均受此保护。

## 验证

默认回归测试覆盖改地址后的旧修订冲突、无人工值 / 事件残留、正确新修订保存 false。浏览器两窗口实际验证地址变更后旧能力表单被拒绝、输入保留，载入最新版本后旧能力变为未知并标配置变更。提交后补充修复哈希。

## 时间线

- 2026-11-08 修复：提交 `169d676`，正式网页始终携带可选 expectedConfigRevision，事务内核对；默认回归与双窗口地址变更实操均拒绝旧能力保存且保留草稿。364 项默认测试（3 跳过）、类型检查和构建通过，状态改为 fixed；旧客户端省略该字段的兼容性保留，不扩张为独立 Agent 整体验收通过。
