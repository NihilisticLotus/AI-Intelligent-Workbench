## 现象

阶段 6 新增独立需审批用例曾未在等待时间内产生审批，单独执行随后通过。首轮全量中，既有 independent-files 三项及 independent-task-runtime 两项失败，耗时涉及 30 秒边界。

## 复现步骤

1. Windows 本机运行完整 npm test；Gateway 配置同时执行两个测试文件。
2. 核对文件宿主与独立任务用例终态和失败原因。

## 影响

阶段 6 尚不能提交为已验收，不据局部通过代替全量结果。

## 根因

尚未查明。并发启动真实离线 PowerShell 宿主可能影响时限，需要完整错误与串行对照，不凭耗时推定根因。

## 处理方式

保留失败证据；完整运行结束后串行对照。不放宽文件保护，不增加跳过，不改变真实调用预算。

## 验证

独立需审批单独重跑通过；浏览器离线独立副本自动写入成功，原目录不变。全量仍未通过。

## 时间线

- 2026-11-15 开启：阶段 6 首轮全量出现既有与新增 Windows 宿主用例失败，继续调查。
- 2026-11-15 定位：完整首轮为 720 项 Gateway 通过 / 5 项失败，全部是测试或等待时限耗尽。仅改为单 worker 对照后，五项均通过：登记副本 6.3 秒、三次宿主启动 2.8 秒、上限快照 2.8 秒、独立全自动文件 5.4 秒、项目 allow 写入 5.4 秒。没有改这些断言或产品时限。证据支持 Windows 宿主并发冷启动争用，未识别到具体系统组件；默认在 Windows 串行测试文件，其他平台保留两个 worker，待最终全量确认。
