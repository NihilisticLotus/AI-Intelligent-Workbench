## 现象

真实目录已确认 HTTP 200 / service_parse，但统一错误无法区分本地列表结构、单页上限、重复 ID 或分页分支。响应正文按安全边界未保存，不能从现有缓存确定触发哪一项。

## 复现步骤

1. 本机无认证合成接口返回 JSON，内容不符合已接入模型列表格式。
2. 正式网页点击一次获取预览并展开诊断。
3. 原诊断只能显示解析阶段与计数，缺少校验分类。不要为复现擅自访问真实服务。

## 影响

后续真实排查仍可能得到相同通用错误，难以决定下一步；不能用当前缺失的细节猜测供应商结构或放宽解析。

## 根因

解析器的多个固定本地错误统一转换为通用错误；现有有限诊断没有追加固定原因字段。本单描述诊断能力缺口，不解释智谱旧失败根因。

## 处理方式

protocol 只追加可选 parseFailure 和固定五项枚举。仅解析器主动抛出已分类错误时写入；要求解析阶段、已收到 HTTP 200 且有服务尝试。保留原通用错误、原快照和退避；不增加请求，不输出上游值、字段名或正文。网页在原折叠详情内显示中文分类；旧诊断显示未记录，不回填。

## 验证

新增 8 项回归；完整 743 项通过 / 3 项真实冒烟默认跳过，typecheck / build 通过。正式 app 17890 实际点击本机合成服务一次，显示结构不符 / HTTP 200 / 服务 1 / 公共 0 / 解析 0 页；打开真实旧服务仅查看缓存，显示未记录分类。临时服务已清理，其他独立配置、目录、模型、绑定、预算、请求及默认摘要相同。截图工具失败，保留实际页面文本证据，未伪造新截图；新增视觉截图未验证。真实供应商新分类尚未验证。
