# 调研：OpenBitFun 的界面与用量统计

> 2026-11-07 · 用户提供链接 https://github.com/GCWing/OpenBitFun · 只读查看 README、截图和前端源码（`src/web-ui/src/flow_chat/components/usage/` 等），没有安装运行
> 用户的看法：部分功能和我们重叠，界面更轻量，比较喜欢

## 它是什么

开源的 Agent 工作台（MIT，约 3.9k star，2026-02 创建，调研当天仍在提交）。Rust 写的 Agent 运行时，加上 Tauri 桌面应用，另有手机端和 CLI。

它和我们最大的区别是：**它自己就是 Agent**，自带运行时、模型配置、多 Agent 协作（“极简 / 标准 / 极致 / 创造”四种模式）。我们是**调度本机已有的 Agent**（Claude Code、Codex、CodeBuddy），不自己跑模型。所以它的运行时、模型管理、Mini App 不在我们的范围里；界面和用量统计可以借鉴。

## 重叠的功能

| 功能 | OpenBitFun | 我们 |
|---|---|---|
| 会话列表按项目分组 | 侧栏“SESSIONS”，项目文件夹下挂会话 | 侧栏按项目 / 分组（已有） |
| 任务看板 | Task Board：计划概览 + 定时任务 + 日历 | 看板（按状态）+ 自动化（定时） |
| 多设备、手机远程 | 官方中转 + 端到端加密 | 第 1.5 步局域网，外网后期 |
| 权限级别 | 输入框上方“Full access”标签 | 输入框里的权限按钮（已有） |
| token 统计 | 首页总量卡片、每轮指标、会话用量报告 | 设计里有（监控页、调用统计），原型和正式版都还没有 |
| 上下文用量 | 输入框旁的小圆环，点开是分类明细 | 设计里只有一句“上下文用量条”，没有画 |

## 界面为什么显得轻

对照它的 4 张截图：

1. **颜色少**：浅灰底、白色内容区，几乎没有彩色块；状态只用小字和小图标。我们的原型卡片背景、彩色徽标、琥珀提示比较多。
2. **对话区没有外框**：消息不放在气泡或卡片里。用户消息是右侧的浅灰胶囊，Agent 回复直接是正文。过程折叠成一行“6 exploration and execution steps”。这和我们刚做的“用时 N 秒”是同一个思路。
3. **顶栏只有标签页**：顶部是打开的会话 / 页面标签，右上角 3～4 个图标，没有标题栏按钮堆叠。
4. **输入框上方一条细信息行**：项目名 · 分支 · 运行在哪台电脑，右侧是权限标签和上下文圆环。输入框里只剩“+”、模型选择、语音、发送。
5. **侧栏极简**：搜索、首页、任务看板，然后就是会话树；底部是设备名和设置齿轮。没有多级导航、计数徽标和分组按钮。
6. **留白大，正文最宽约 1100px 居中**，字号一致，没有粗体标题堆叠。

## 用量统计怎么做（读源码）

- **上下文圆环**（`TokenUsageIndicator`）：输入框旁边一个小进度环，`当前 token / 上下文窗口`。70% 以上变黄，90% 以上变红。
- **上下文明细**（`ContextUsagePopover`）：点圆环弹出。头部“已用 N% · 约 X / 窗口大小”，下面是一条分段横条（每段一个分类，最后是“未使用”），再下面是图例列表。分类有：系统提示、工具定义、规则、技能、MCP 工具、子 Agent 定义、已压缩的对话、对话。
  - 拿不到分类明细时不编造，只显示总量；拿不到窗口大小时不显示百分比（源码注释原话：不要编造分母）。
  - 打开明细是只读的，不触发重新计算。
- **每轮指标**（`TurnUsageMetrics`）：每轮回复下面一行小字：总 token、输入、输出、缓存命中率、首字时间、输出速度。悬停看明细。
- **会话用量报告**（`SessionUsagePanel`）：右侧面板里的完整报告，可以导出 Markdown，可选隐藏路径。
- **首页**：总 token、单日最高、最长任务、连续使用天数。

## 我们能拿到什么数据

我们的数据都来自 Agent 通过 ACP 报告的内容，不能自己算：

- `usage_update`（ACP 稳定版）：`used` 当前上下文里的 token、`size` 上下文窗口大小、`cost` 累计费用（可选）。Gateway 已经记成 `session.usage` 事件，网页还没显示。
- 每轮的 `usage`（ACP 草案，`PromptResponse.usage`）：`totalTokens`、`inputTokens`、`outputTokens`、`thoughtTokens`、`cachedReadTokens`、`cachedWriteTokens`。适配器还没接，要实测哪家报告。
- **分类明细**（系统提示、工具、MCP、对话各占多少）：ACP 里没有。Claude Code 自己的 `/context` 命令能给出这些数，需要研究能否通过扩展拿到；拿不到时只显示总量和“对话以外的部分”。
- **订阅账号的额度**（本周已用 46%）：ACP 里没有，各家要单独研究（zcode-acp 有智谱的配额接口可以参考）。

所以原型里画完整的分类明细，正式版按 Agent 实际报告的内容显示，没有的写“未报告”，不用 0 冒充（design.md 23.4 已有这条规则）。

## 借鉴什么、不借鉴什么

借鉴：
- 对话区去掉外框，用户消息右侧浅灰胶囊，Agent 正文直接排。
- 输入框上方一条信息行（项目 · 分支 · 本机），右侧放权限和上下文用量；输入框里只留必要按钮。
- 上下文用量：输入框旁一个小圆环 + 点开的分类明细（样式参照用户给的 Claude 截图：标题、“N% used · 已用 / 窗口”、分段横条、带色块的分类列表、可展开的 MCP 工具和记忆文件）。
- 每轮回复下面一行用量小字，悬停看明细。
- 侧栏减负：搜索、首页、看板、会话树、底部设备和设置。
- 拿不到的数据不编造。

不借鉴：
- 自带 Agent 运行时、模型配置、多 Agent 模式（不是我们的定位）。
- 宠物、皮肤市场、Mini App。
- 顶部多标签页：我们的用户一次主要盯一个任务，侧栏切换足够；标签页会让界面更像编辑器（用户明确说过不要像编辑器）。
