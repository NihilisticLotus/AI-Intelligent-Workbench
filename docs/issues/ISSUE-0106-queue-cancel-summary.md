# ISSUE-0106：取消排队任务时被工作副本说明写入拖住

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 中 |
| 发现于 | [1.6 阶段 1 验收](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象与复现步骤

在同一临时非 git 项目派发两轮任务，保持第一个运行，取消排队的第二个。旧断言在默认轮询窗口内仍读到 queued。

## 影响

尚未运行的任务取消后不能及时显示暂停。

## 根因

取消路径即使还未取得项目运行权，也会等工作区差异刷新。该刷新和任务说明发布共享副本操作队列。

## 处理方式

尚未取得项目运行权且已取消时直接处理暂停。已运行的轮次继续按原流程核对快照和改动。

## 验证

保留原有断言，临时项目串行与旧任务原位运行两个定向用例通过。

## 时间线

- 2026-11-18 开启并定位于阶段 1 本地验收。修复后已完成上述定向复验。
- 2026-11-18 全量第二轮又发现，正常启动审批和排队任务换账号也会被同一副本的说明发布阻塞。说明文件已有独立排除规则，可与快照、差异计算并行。将同一副本的说明写入串行化，清理副本同时等待说明写入和普通副本操作。保留原有时序断言，五个涵盖排队、重启、原生配置及同名文件的定向用例通过。
- 2026-11-18 修复已推送至 main，提交 `667fa8e`。
