# ISSUE-0116：反向交接草稿的确认请求被拒绝

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 中 |
| 发现于 | [1.6 阶段 4](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

来源不能原生恢复，且开启“交接前让我确认”时，切回能生成反向交接草稿，再次提交确认却收到 HTTP 400。

## 复现步骤

1. 在临时项目用两个演示适配器完成一次交接，来源声明不能原生恢复。
2. 开启交接确认，点切回并使用服务端返回的草稿标识确认。

## 影响

同时使用反向交接和可编辑确认的用户无法完成切回。

## 根因

切回接口原先只接受文件恢复修订号，严格请求校验拒绝反向交接草稿标识。

## 处理方式

切回接口接受草稿标识与编辑内容。反向草稿绑定原交接，成功后原记录变为已切回；工作台操作不记为用户原话。

## 验证

第一次全仓测试中确认请求返回 400。接口更新后的定向测试收到 200，核对原 Agent 与两条交接记录状态均符合预期。

## 时间线

- 2026-11-18 发现并修复，随阶段 4 提交。
