## 现象

新建任务起始页复用 1.3 附件组件；文件选择、图片粘贴、推荐、派发和重复预览已实测通过，但从 Windows 文件资源管理器拖入这一入口没有取得成功证据。

## 复现步骤

1. 在本次创建的 Chrome 窗口打开开发工作台 17890 的起始页。
2. 在本次创建的文件窗口选择仓库合成图片 step-1.3-synthetic-shapes.png。
3. 拖向起始页，电脑操作工具拒绝终点超出源窗口边界；未执行文件上传，也没有发现产品错误。

## 影响

这是浏览器验收证据的缺口。phase-1 10.11 指定的八入口、带图派发、独立派发、返回保留与双主题验收均已通过。拖入处理复用已有组件，不能把其他入口的成功视为拖入已通过。

## 根因

当前原生电脑工具的 drag 要求两端都位于绑定窗口截图范围内。跨窗口路径被工具拒绝；网页是否存在拖入回归未验证。

## 处理方式

保留未验证状态，不修改系统设置、不用脚本模拟鼠标绕过工具边界。下次有支持跨窗口拖拽的验收环境时，使用同一合成图片补验；无需真实模型调用或第三方凭据。

## 验证

- 文件选择、Ctrl+V 粘贴、Ctrl+Enter 演示派发、消息图片重复预览已通过。
- 原生文件拖入：未验证。

## 时间线

- 2026-11-13 开启：记录工具限制和补验路径。本次创建的文件窗口及 Chrome 窗口随后关闭，用户原有窗口保留。
