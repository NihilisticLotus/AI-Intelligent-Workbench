# ISSUE-0053：本机代理把供应商域名解析到 198.18.x，元数据读取被网络规则拒绝

## 现象

2026-11-09 02:22:56（UTC+8），用户批准的一次智谱目录读取在正式网页上失败：“元数据域名解析到受限地址”，诊断为“读取服务目录 · HTTP 状态：未确认 · 服务请求尝试 1 次”。没有拿到任何 HTTP 响应，所以也没有根结构。

同一时间在本机用 Node 的 `dns.lookup('open.bigmodel.cn')` 只读查询：唯一的 IPv4 地址落在 **198.18.0.0/15**（RFC 2544 基准测试段）。这个网段常见于代理软件的 fake-ip 模式：代理把域名解析成假地址，再由本机代理接管连接。上次（2026-11-08 23:58）同一读取收到了 HTTP 200，说明当时的解析结果不同，本机的网络或代理设置在两次之间发生了变化（推断，未核对代理软件本身）。

## 复现步骤

1. 本机代理处于 fake-ip 或类似模式，`open.bigmodel.cn` 解析到 198.18.x。
2. 在工作台点“获取模型与能力 → 获取最新预览”（服务目录）。
3. `metadata-http.ts` 在连接前校验解析结果，198.18.0.0/15 在受限名单里，请求在建立连接前被拒绝。

## 影响

- 只要本机代理用 fake-ip，所有独立服务的模型目录读取都会被拒绝。
- 独立 Agent 的模型对话请求是否走同一套地址校验，本次没有核对（不在授权范围），需要离线查代码。
- 第三方 Agent（Claude Code、Codex、CodeBuddy）不经过这套校验，不受影响。

## 根因

元数据客户端为防止 SSRF 和 DNS 重绑定，拒绝解析到私网、回环和保留网段（包括 198.18.0.0/15）的地址，且不使用系统代理（`proxyEnv: {}`）。fake-ip 代理恰好把公网域名解析到这个保留网段。网络规则本身按设计工作；问题在于设计没有考虑本机透明代理。

## 处理方式

待定，需要用户决定，不在本轮擅自放宽：

- 方案 A：用户在代理软件里把 `open.bigmodel.cn`（或所有工作台要访问的供应商）设为直连 / 不走 fake-ip。工作台不改代码。
- 方案 B：工作台增加一个明确的设置“允许本机透明代理的 fake-ip 网段（198.18.0.0/15）”，默认关闭；打开时只放行这个网段，其他私网和回环仍然拒绝，并在诊断里标明“经本机代理”。需要设计、测试和用户确认。
- 方案 C：支持显式配置的 HTTP 代理（读系统代理设置）。改动更大，且代理本身能看到请求，需要单独评估。

在用户选择之前，诊断里的提示文字可以补一句“可能是本机代理的 fake-ip 模式”（离线可做，不改变放行规则）。

## 验证

- 正式网页实际一次读取：服务尝试 1 / 公共 0 / 已解析 0，HTTP 未确认，阶段“读取服务目录”。
- 只读核对：服务、模型、绑定、生成账本、预算、用户消息、其他目录、默认摘要全部不变；活动任务为空，独立 v2 请求仍 11。
- 本机 DNS 只读查询：198.18.0.0/15。没有查看代理软件配置，也没有修改任何网络设置。

## 时间线

- 2026-11-09 开启：用户批准的一次目录读取在连接前被网络规则拒绝；本机 DNS 只读查询显示 198.18.x。按约定不重试、不换地址、不放宽规则。
