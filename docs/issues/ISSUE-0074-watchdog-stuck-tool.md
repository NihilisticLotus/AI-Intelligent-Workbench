## 现象

ISSUE-0061 的修复让“有工具已开始未结束”时每秒重置无回应计时。如果 Agent 卡死在工具里、永远不发这个工具的结束事件，这一轮就永远不会自动停止。ACP 适配器只在回合结束时补发未结束工具的结束事件，回合不结束就补不了。1.3 的“10 分钟没有事件自动停止”（ISSUE-0022）在这种情况下失效。

## 复现步骤

1. 假 ACP 发一个 in_progress 的工具调用，然后什么都不发，等待取消。
2. 修复前：任务一直 running，不提醒、不停止。

## 根因

看门狗把“有工具在执行”当成持续有活动，没有上限。

## 处理方式

- 有工具在执行时不重置计时，也不发提醒，改用更长的上限 `noResponseToolCancelMs`（默认 60 分钟，不小于普通上限）。超过就停止这一轮，提示“工具执行 N 分钟没有任何回应，这一轮已停止”。
- 等待审批照旧不计时；工具结束事件到达后，按普通的 1 分钟提醒、10 分钟停止计时。
- 60 分钟的默认值是判断：长于常见的构建时间，又能保证卡死的 Agent 最终会停下。需要调整时改这一个参数。

## 验证

- real-agent.test.ts 新增 1 项：卡死工具在普通上限后仍运行、不提醒，到工具上限后暂停并发出 no_response 错误和 session/cancel。临时还原为旧逻辑时该项失败，恢复后通过；ISSUE-0061 原有的两项长工具用例继续通过。
