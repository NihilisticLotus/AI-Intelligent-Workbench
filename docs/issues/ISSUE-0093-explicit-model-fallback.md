## 现象

派发前缓存目录与网页明确显示 Custom GLM5.2（custom-local:glm-5.2），会话建立后提示该模型不可用、改用 default-model，并已经发送了本轮短消息。这违背本批仅授权自定义模型、不回退自带模型的约束。

## 复现步骤

1. 工作台 GET /agents 缓存含 custom-local:glm-5.2；新 TEMP 项目任务显式选中它，网页显示一致。
2. 派发后新会话目录不再含该 ID，适配器 applyInitial 发出警告并将 want.model 清空，继续 prompt。
3. 发现后立即点击停止，未允许待审批编辑；任务 paused，原目录和副本均只有基线。未重试，未发送 CodeBuddy 非 git 用例。

## 影响

模型目录过期或初始化配置失败时，可能调用用户没有选择的模型并产生未知费用；旧的提示后继续执行不能保证显式模型限制。收费批次停在 7 / 8 条（Claude 3、Codex 3、CodeBuddy 异常 1）。

## 根因

packages/adapters/src/acp/session.ts 的 applyInitial 在模型不在新会话目录时只警告并放弃选择；setConfig 失败也只警告。Gateway 随后把实际模型写回并继续发送消息。新会话刷新后的 CodeBuddy 目录实际含 custom-local:glm-5.3；此前 GLM5.2 缓存已经过时。未读取第三方配置，不能判断外部目录何时变化。

## 处理方式

待用户决定（phase-1 11.3 第 15 条：改变可见行为或保护含义的未覆盖选择先问）：

- 建议：对所有第三方明确选择的模型，若目录缺失、设置失败或实际模型不一致，在 prompt 前终止并保留原选择，提示重新选模型；用户选择“Agent 自己的默认模型”（null）时仍可使用默认值。不能把思考强度单独失败误报成模型回退，需分别覆盖测试。
- 保留现状：只停止本批 CodeBuddy，记录风险与未验证；不建议，因为后续仍可能发生非预期计费。

修复不读取第三方凭据，不改第三方配置和登录。关键离线测试应证明错误模型收到的 prompt 次数为 0，并做撤修失败、恢复通过验证。
