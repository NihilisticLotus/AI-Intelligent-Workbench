## 阶段 1 前待决定：项目保护边界（2026-11-15）

依据用户本次指令的“三、4”和 phase-1 第 11.3 条 15，涉及写用户目录和数据含义的未覆盖冲突必须记录选项后停下询问。本节未选择方案，未修改既定设计。

### 决定一：git 工作副本的仓库元数据

`git worktree add -b aic/...` 共享项目仓库，会在派发时写原仓库的 worktree 登记、任务分支等元数据；任务副本里的提交也写共享对象库。清理工作副本同样会修改登记及任务分支。虽然不修改主工作目录中的项目文件或当前分支，但不满足“点击合并 / 回滚前连 git 仓库也不写”的字面约束。

| 选项 | 结果 |
|---|---|
| G1：为任务工作副本的必要元数据写入设明确例外（建议） | 保留既定 worktree 方案；允许创建 / 清理登记、维护本任务 aic/ 分支及共享对象；主目录文件、当前分支只在明确合并 / 回滚时变更，不写其他分支、标签、配置、远端 |
| G2：原仓库也严格只读到合并 / 回滚 | 改为数据目录中的独立仓库副本，需要重订工作区、差异和合并流程；不再是当前规格的共享 worktree 方案，增加磁盘占用和实现范围 |

### 决定二：非 git 项目的直接写入

第 11.3 条 1、4 和第 11.7 节明确 shadow 以项目目录为工作树，任务直接写原文件、每轮前后快照；这不是文件隔离，且大于 50 MB 的文件无法依靠影子快照回滚。旧 inplace 任务继续直写也是同类既有例外。

| 选项 | 结果 |
|---|---|
| N1：保留非 git 直接写入和快照的明确例外 | 完全沿用既定 shadow 方案；派发页如实提示直接修改，每轮快照，超限大文件不可回滚；全局“只在合并 / 回滚时写项目”须限定为新 git 任务的主工作目录 |
| N2：非 git 新任务也在独立文件副本中运行（建议） | 遵守项目文件保护优先；需要增加显式应用结果操作及原目录变化检查，重新定义快照 / 回滚 / 大文件处理并同步规格；不是当前规定的 shadow 直写行为 |

建议 G1 + N2：允许 git 为工作副本维护必要元数据，同时保护新任务的原项目文件。若选择 N2，先补齐非 git 副本与应用结果的具体规则，不擅自决定大文件复制或覆盖策略。旧 inplace 行为按既定兼容规则保留并明确提示，不把它描述成隔离。
