# ISSUE-0110：等待审批时拒绝还原的用例依赖启动速度

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 低 |
| 发现于 | [1.6 阶段 2](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

阶段 2 第二次全量运行中，任务还在 `running`，原等待断言已经结束，后续还原保护断言没有执行。

## 复现步骤

1. 在临时 git 项目创建延迟发送的演示任务，写入三项工作副本改动。
2. 发送消息，在全量测试负载下等待演示 Agent 请求审批。

## 影响

用例可能在审批请求出现之前结束。此次失败没有发生文件还原。

## 根因

原用例用测试框架的默认短轮询窗口推断何时出现审批。Git 工作副本核对、Agent 启动和实际审批事件之间没有这个时限约定。

## 处理方式

先订阅任务事件，发送消息后等待同一任务的真实审批请求。随后仍断言状态为等待、还原接口返回 409，并逐字核对工作副本的内容。

## 验证

第二次全量运行失败在等待状态的旧断言，其余 760 项 Gateway 用例通过。修改用例后重新运行三项全量检查。

## 时间线

- 2026-11-18 开启，改用工作台对网页发布的审批事件同步测试。
- 2026-11-18 修正后 Gateway 的 761 个用例全部通过，全仓 1094 通过、3 跳过。
