# ISSUE-0034：工具明确中断后仍继续请求模型

| 项 | 值 |
|---|---|
| 状态 | investigating |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | [独立文件工具接入](../acceptance/step-1.3.md) |
| 开启 | 2026-11-08 |
| 关闭 | |

## 现象

工具 driver 正常返回 outcome=interrupted 并明确说明副作用未知时，既有循环仍把它当普通工具结果发送给模型，甚至可以进入 completed。

## 复现步骤

1. 在未修改的 `28b5a77` 循环上，以假模型先请求一次工具，再返回完成。
2. 工具正常返回 interrupted，不抛异常。
3. 新增回归要求 tool_error / failed 且只请求模型一次，实际返回 completed，断言失败。

## 影响

模型可能在用户核对之前再次提出结果未定的操作。正式独立运行时尚未开放，本次没有真实模型、用户文件或计费影响。

## 根因

循环仅对工具抛异常停止；未检查正常工具结果的 interrupted 终态。

## 处理方式

先持久化真实的中断结果，再以 tool_error 停止本轮；剩余调用补中断配对，禁止自动请求下一轮，保留人工核对入口的实现边界。

## 验证

新增默认回归在未改循环时失败，实际为 completed；修正后重新验证并在提交后追加哈希。正式网页恢复与真实服务仍未验证。

## 时间线

- 2026-11-08 开启：文件写入结果可能为副作用未知的 interrupted，接入审查复现既有循环继续请求的问题；新增默认反例失败，循环文件在反例前与 HEAD 无差异。
- 2026-11-08 补上中断结果持久化后的停机分支，待全量测试与提交溯源；不自动重放或恢复原文件。
