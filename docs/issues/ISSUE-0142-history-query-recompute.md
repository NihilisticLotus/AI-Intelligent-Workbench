# ISSUE-0142：历史查询每次调用都重新投影与打码全部事件

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | [1.6 完成后的第二次代码审查](../acceptance/step-1.6.md)（审查范围 5dc0c9c..72adaf5） |
| 开启 | 2026-11-19 |
| 关闭 | 2026-11-19 |

## 现象

aic_history 的每次调用都重新投影全部事件、读取环境附件、解密匹配的 Key 并对每条事件重新打码。长任务里单次调用可能超过 MCP 客户端 10 秒超时。

## 复现步骤

1. 在长任务上交接，让接收方连续调用 search。
2. 每次耗时随事件总量线性增长。

## 影响

接收方的历史查询变慢甚至超时，回查能力失效。

## 根因

readHistory 没有缓存。

## 处理方式

按任务缓存投影、打码器和逐条打码结果；指纹包含事件最大序号、已发送附件、保存的 Key、路径别名、独立 Agent 消息和会话密钥，任一变化即重建。最多保留 16 个任务。

## 验证

`handoff-review.test.ts`：事件不变时第二次查询不再调用 forRedaction，新增事件后重建并能查到新内容。
