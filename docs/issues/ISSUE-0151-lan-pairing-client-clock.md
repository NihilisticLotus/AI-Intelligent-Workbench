# ISSUE-0151：手机按本地时钟提前判定配对超时

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | [第 1.7 步代码审查](../acceptance/step-1.7.md) |
| 开启 | 2026-11-19 |
| 关闭 | 2026-11-19 |

## 现象

局域网配对页每秒查询请求状态。服务端回复“等待中”时，网页仍拿电脑给出的到期时间与手机本地时钟比较，过期就显示“配对确认超时”并停止查询。

## 复现步骤

1. 手机时钟比电脑快两分钟以上。
2. 在手机提交正确配对码：第一次查询后即显示超时。
3. 电脑仍弹出“有新设备请求连接”，点允许后手机已不再领取凭据。

## 影响

两台设备时钟不一致时无法配对，电脑上的允许也无效。

## 根因

`pollingOutcome` 只在服务端结果不是等待时采用服务端结果，否则按本地时钟判超时。

## 处理方式

只要拿到服务端结果就以它为准；服务端到期计时器会把请求改为超时。仅在查询失败、没有结果时才按本地时钟判超时。

## 验证

新增“手机时钟偏快但服务端仍在等待”的用例。临时撤掉修复后失败，恢复后通过。
