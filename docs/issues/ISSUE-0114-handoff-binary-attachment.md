# ISSUE-0114：交接首条消息的二进制附件可能携带命中打码规则的原文

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 高 |
| 发现于 | [1.6 阶段 4](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

临时项目里，消息正文走了交接打码，但新上传的二进制素材通过另一条路径到达了目标演示 Agent。它可以读到素材中命中常见密钥格式的人工字节。

## 复现步骤

1. 创建两个不同种类标识的演示适配器，任务使用只读权限。
2. 上传含零字节和人工标记的素材文件，计算原文件的 SHA-256 校验值。
3. 通过任务发送入口换目标并附带文件，在接收端验证能否读到人工字节。另比较替换命中字节前后的文件校验值。

## 影响

发原附件或可打开原附件的链接会暴露内容。替换包内字节会破坏素材校验值。跳过素材继续执行，与保留整条消息让用户替换素材，两种行为对按附件办事的任务有不同后果。

## 根因

正文和内嵌任务说明走交接打码；附件沿用原有的任务内身份与原始文件，独立于正文传递。

## 处理方式

当前处于阶段 4 未提交开发状态。两个候选行为、建议及适用范围已登记在验收记录。

## 验证

离线回归用例已失败在“接收方不能读到命中字节”断言。没有使用真实密钥或真实 Agent。

## 时间线

- 2026-11-18 开启。用户决定后在两个方向验证实际接收材料和原会话状态。
- 2026-11-18 用户选择 A，附件检查应在创建检查点、关闭原会话和标记发送前完成。
- 2026-11-18 已在任务发送入口验证：带人工敏感字节的素材被拒，目标启动次数为零，原会话标识、草稿正文和附件清单一致，检查点和交接表没有新增记录。替换同名干净素材后，接收端校验值与替换件一致。网页操作尚未验证。
- 2026-11-18 关闭。附件命中时保留草稿及原会话、替换后按校验值发送已通过阶段 4 全仓验收。
