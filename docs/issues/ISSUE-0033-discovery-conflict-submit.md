# ISSUE-0033：模型发现冲突后仍可重复提交旧预览

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 低 |
| 发现于 | [模型发现网页验收](../acceptance/step-1.3.md) |

| 关闭 | 2026-11-08 |

## 现象

双窗口验收时，另一窗口修改服务基础地址后，旧发现预览的导入请求被后端正确拒绝，但界面仍允许反复点击同一旧预览的导入与获取按钮。

## 复现步骤

1. 窗口甲获取本机假接口列表并勾选一项，不导入。
2. 窗口乙修改同一服务地址，配置修订增加。
3. 窗口甲导入得到 409；初版按钮仍可点，不能明确引导停止旧提交。

## 影响

多余失败请求和操作困惑。后端始终校验配置修订，未出现跨地址导入、模型新增或调用计费。

## 根因

发现弹窗只呈现错误，没有将 409 转为本地停止提交状态。

## 处理方式

409 后保留勾选、锁定获取与导入；明确提示载入最新配置和缓存，核对地址后重新获取、勾选。载入成功才清除冲突状态，不自动重试。

## 验证

默认测试验证配置变更与快照身份被拒绝、无新增条目。修正后浏览器再次双窗口操作：409 后两按钮禁用、旧勾选保留；载入最新配置显示修订 3、清空勾选且旧缓存不可导入，Esc 返回入口。提交后追加修复哈希。

## 时间线

- 2026-11-08 实现本地冲突锁定并通过同场景 GUI 回归，待提交后补充哈希改为 fixed；未涉及真实服务或付费请求。
- 2026-11-08 修复随模型发现提交 `63d84bc` 落地：冲突后锁定旧预览提交、明确载入最新配置后重新选择；407 项默认测试通过、3 项真实冒烟跳过，类型检查 / 构建和双窗口 GUI 回归通过。状态改为 fixed；独立执行器整体仍未完成。
