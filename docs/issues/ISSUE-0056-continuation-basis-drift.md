# ISSUE-0056：项目规则、人工总结或工具开关变化后，独立任务每条消息都失败

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 高 |
| 发现于 | [第 1.3 步代码审查](../acceptance/step-1.3.md)（2026-11-11，范围 0e1a3b2..80ed883） |
| 开启 | 2026-11-11 |
| 关闭 | 2026-11-11 |

## 现象

独立任务里模型用过工具或留下过思考续传资料之后，只要 AGENTS.md 被改动（用户改，或 Agent 自己用 replace_text 改）、人工总结保存在非最后一条、或把工具次数改成 0，下一条消息就在发请求前失败，提示“模型请求未能可靠完成”，此后每条都失败。

## 复现步骤

1. 用系统提示“规则甲”完成一个带续传资料的回合。
2. 用“规则乙”开始下一回合，读取上下文。旧助手消息仍带续传资料；modelWire 校验 prefix 不一致，抛 request。

## 影响

任务卡死，只能换模型或新建任务。智谱 Responses 每次工具调用都会留下续传资料，本仓库的 AGENTS.md 又经常改，实际很容易碰到。

## 根因

续传资料在生成时绑定了绑定、系统提示（含项目规则正文）、人工总结和工具声明（model-wire.ts 的 scope / prefix）。conversation.context() 只按绑定判断是否保留（ISSUE-0044 的修法），没有考虑另外三项。

## 处理方式

context() 增加三项判断：该消息所在回合的系统提示与当前回合相同、工具开关（工具次数是否大于 0）相同、且消息产生于当前人工总结保存之后。任何一项不符只移除本次输入里的专用资料，保留可移植原文；原始记录不改写，modelWire 的校验不放宽。

已知范围：工具声明本身随版本变化（升级后描述不同）没有逐回合指纹，仍会被 modelWire 拒绝；9.28 已约定不改旧版本声明。

## 验证

- independent-conversation.test.ts 新增 2 项（规则变化 / 工具开关 / 改回原样；中间位置总结前后）。临时还原修复后两项均失败，恢复后通过。
