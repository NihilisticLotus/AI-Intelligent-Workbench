# ISSUE-0113：私有索引仍会把副本内容写进原项目的 Git 对象库

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 高 |
| 发现于 | [1.6 阶段 4](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

在新建的临时 git 项目里，任务分支 HEAD、Agent 暂存区与原项目工作目录都没有变化，但原项目可以按私有检查点引用读到仅存在于工作副本中的人工环境文件。另在一个全新的临时项目验证了预览接口：预览前原项目没有对应的 Git 对象，预览返回 200 后该对象存在。

## 复现步骤

1. 创建临时 git 项目和工作副本，在副本新增未被项目忽略的人工 `.env.local`。
2. 用独立的索引写树并创建 `refs/aic/checkpoints/<任务ID>/1`。比较任务分支和原暂存树，在原项目查询该引用的文件。
3. 在另一个临时项目只发送交接预览请求，比较调用前后的对象存在性。

## 影响

即使没有把副本合并回项目，原项目的 Git 对象库也可能持有原本只在副本里的内容。所有复现均使用新建临时目录和人工数据。

## 根因

工作树与原项目共享 Git 对象库。`GIT_INDEX_FILE` 隔离暂存区，写树和暂存新内容仍会写对象。

## 处理方式

只读的交接预览、改动列表、文件补丁使用工作台临时对象目录；原项目已有的对象只供读取，比较结束后清理临时对象。真正需要将来恢复的交接检查点还涉及环境文件内容的保留边界，选项已记录在验收文档。

## 验证

回归用例在旧预览器下失败。临时对象目录接入后，改动与还原的 14 个用例通过，包括清单与补丁仍可查看、原项目没有生成副本环境文件的对象。
