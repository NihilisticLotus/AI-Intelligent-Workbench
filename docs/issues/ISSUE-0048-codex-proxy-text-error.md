## 现象

原生 Codex 同会话 Luna 回复 OK，切换 gpt-5.5 成功后，第二条固定短消息返回 CC Switch 代理的 HTTP 400 / ChatGPT 账号不支持模型正文。任务却显示待验收，未发 error，也未记录上次失败。

## 复现步骤

1. 已授权的只读合成任务先选真实目录中的 gpt-6-luna，发固定 OK 消息。
2. 从实际列表切换 gpt-5.5，最多再发一条相同消息。
3. 观察自动 Compact conversation 和代理拒绝正文、任务待验收、菜单缺少失败标记。不要为复现擅自重发收费消息。

## 影响

上游明确不支持模型时会被误当成功；工作台不能提示暂停或为实际账号标记模型失败。

## 根因

已查明工作台漏检机制：现有短正文模式要求已知前缀，未包含代理的固定封套；回合中任何 tool_start 都会阻止正文检测，Codex 自带 think / Compact conversation 自动压缩也触发该条件。真实事件有一条该 think，没有项目执行 / 读写工具或审批。未读取代理配置或凭据；本单不调查或改变其模型权限、路由与认证。

## 处理方式

完整识别固定 Codex 代理模型不支持封套，模型前后及当前配置相同、HTTP 400、短单段正文；仅该规则允许无目标的已知 Compact conversation。其他工具或其类型 / 标题 / 目标变化仍阻止识别；原有模式仍零工具。复用暂停、原文保留、实际账号失败标记。同步 phase-1 9.6 和设计 v0.4.23，不自动重试或回写历史。

## 验证

定向适配器及 Gateway 假 ACP 集成通过，正式构建网页在隔离 17891 / 独立数据目录显示暂停、原文及上次失败，零真实模型调用。全量与提交哈希随后追加。修复后真实供应商复验未验证；本轮异常即停，未执行智谱目录。
