## 处理方式

**2026-11-09 定位后待用户决定**：智谱 Responses 带工具调用时返回的 reasoning 项没有 encrypted_content，而工作台为了下一轮能原样续传思考，要求必须有。可选做法：

- A：按智谱文档的格式续传：保存 reasoning 的明文 `reasoning_text`，下一轮作为思维链输入回传。只对确认支持这种格式的服务启用（需要按服务记录续传方式），其他服务保持现有严格规则。
- B：带工具调用时，reasoning 缺少可续传内容就丢弃这项思考，只回传工具调用和结果；思考只显示、不续传。实现简单，但下一轮模型看不到自己上一步的思考，可能影响多步工具任务的质量。
- C：维持现状，Coding Plan 服务上的独立 Agent 只能不带工具使用。

建议 A：和官方文档一致、不丢上下文，代价是续传方式要按服务区分并补测试。

开单时的处理：

- 按约定已停止整轮，不重试、不换服务或协议、不放宽解析。
- 离线可做：给 protocol 失败加固定分类诊断（例如“未知输出项类型”“reasoning 缺少 encrypted_content”“事件状态不一致”），只记分类不记正文，和目录根结构诊断同样的做法。有了分类，再用 Coding Plan 额度复现一次，就能知道是哪一条校验没过。
