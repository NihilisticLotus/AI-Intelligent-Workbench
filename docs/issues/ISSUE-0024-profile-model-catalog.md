# ISSUE-0024：切换账号仍显示另一账号的模型

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 高 |
| 发现于 | [第 1.3 步真实补验](../acceptance/step-1.3.md) |
| 开启 | 2026-11-08 |
| 关闭 | 2026-11-08 |

## 现象

新建任务从 Codex 订阅账号切到第三方 API 账号，仍显示订阅账号的模型与旧选择。发送前发现并停止，没有因此发送错误模型的消息。

## 复现步骤

1. 新建任务选择 Codex 订阅账号与一个原生模型。
2. 切到只有手填模型的自定义地址账号。
3. 查看模型子菜单与当前模型。

## 影响

可能向第三方接口发送不支持的模型，也会误报模型能力。

## 根因

Agent 摘要只有默认账号的模型目录；网页切账号时没有重算目录和选择。服务端还会让其他账号缓存覆盖当前账号的手填目录。持久化模型解析会丢弃新增的 vision 字段。

## 处理方式

为账号摘要追加可选模型目录、能力和来源；自定义地址优先使用自身手填目录，不借用其他账号缓存。新建任务切账号后选择该账号可用的模型与强度；会话内仍以实时配置为准。模型持久化沿用协议校验并保留 vision。

## 验证

协议、Gateway 和网页回归测试通过。浏览器从订阅账号切到测试 API 账号后，模型自动变成手填的 glm-5.3-flash，子菜单只显示此模型，旧强度消失。证据：`assets/step-1.3-profile-models.png`。
