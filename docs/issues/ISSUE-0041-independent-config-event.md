# ISSUE-0041：独立任务换模型后输入框沿用旧会话配置

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |
| 发现于 | step-1.3 浏览器图片换模型补验 |
| 开启 | 2026-11-08 |
| 关闭 | 2026-11-08 |

## 现象

通过推荐按钮打开独立配置，选择已知支持图片的模型并应用后，任务配置已保存，输入框仍显示旧模型不支持图片的提示并阻止发送。

## 复现步骤

1. 独立任务完成一轮，上传合成图片，当前模型明确不支持图片。
2. 点击推荐的支持图片模型，核对独立配置并应用。
3. 输入框仍从上一轮 session.started 推导旧模型，直到下一轮启动；预检又阻止下一轮启动。

## 影响

用户不能在界面完成图片模型切换后的首次发送。已保存的选择和预算未丢失，没有因本次受阻发送产生模型请求。

## 根因

应用独立配置只发布 task.updated，而输入框优先读取会话事件中的模型；缺少既有 session.config 通知。

## 处理方式

明确应用配置成功后追加 session.config，立即同步当前模型、思考强度和权限。复用既有协议，不改变第三方 Agent 行为。加入 Gateway 配置事件断言和网页会话推导回归。

## 验证

最终测试与浏览器重验追加到 [1.3 验收](../acceptance/step-1.3.md)；真实供应商视觉能力未验证。
