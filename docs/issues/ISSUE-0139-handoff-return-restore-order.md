## 现象

returnHandoff 在原生恢复和反向交接之前就把工作副本恢复到检查点。原生恢复出错，或反向交接后来失败时，任务仍留在接收方，文件却已被改回交接前。

## 复现步骤

1. 交接后接收方改文件，勾选“恢复检查点”切回。
2. 让原生恢复抛出非“不可恢复”的错误，或让反向交接的首轮失败。

## 影响

接收方的改动在没有切换成功的情况下被撤销，用户没有得到提示。

## 根因

恢复检查点与会话切换不在同一个提交点上。

## 处理方式

先只核对恢复清单修订；原生恢复在新会话启动后才恢复文件，恢复失败就关闭新会话、接回接收方。反向交接把恢复放进 prompt 的新会话启动之后，交接未完成时按反向交接自己（恢复前）的检查点还原，并在对话里说明。网页确认流程第二次请求也带上恢复修订。

## 验证

`handoff-review.test.ts` 三例：原生恢复失败、反向交接首轮失败时文件保持切回前；反向交接完成时文件恢复。临时还原修复后前两例失败。
