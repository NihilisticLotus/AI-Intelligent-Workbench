# ISSUE-0028：API 账号删除时的目录与凭据清理规则冲突

| 项 | 值 |
|---|---|
| 状态 | investigating |
| 类型 | 验收未通过 |
| 严重程度 | 高 |
| 发现于 | [第 1.3 步真实补验](../acceptance/step-1.3.md) |
| 开启 | 2026-11-08 |
| 关闭 | |

## 现象

phase-1 §9.11 要求删除测试账号后清掉 DPAPI 密钥和账号目录，§6.4.1 则明确保留独立目录以免误删历史。Codex 采用计划允许的 API 认证后备方案后，独立目录还会包含 Codex 自己的凭据。

## 复现步骤

1. 对照上述两条计划规则。
2. 创建并成功使用 Codex API 账号。
3. 当前删除实现只清工作台 secrets，保留整个独立目录；本次尚未执行删除。

## 影响

不能将工作台 DPAPI 密钥删除等同于 Agent 凭据全部清理，也不能直接声称完成 §9.11 第 3 项。

## 根因

目录保留与真实补验要求不一致，后备认证新增的 Agent 凭据清理尚未落实。

## 处理方式

已向用户说明两个可选行为：清理凭据并保留会话历史，或删除整个 API 账号独立目录。等待决定后修正第 9 节、代码与验收；不读取凭据内容，不修改历史记录。

## 验证

删除、Agent 凭据清理和目录最终行为均未验证。测试账号暂留供后续补验，未冒充已经清理。

## 时间线

- 2026-11-08 开启：真实 API 认证成功后检查删除要求，发现计划冲突，暂停删除并向用户提出具体取舍。
- 2026-11-08 用户澄清工作台独立 Agent 与第三方认证分别管理，后续以 phase-1 9.15 / ISSUE-0029 为准。当前三项工作台测试配置尚未删除，清理仅针对工作台自有数据，不读取或更改第三方凭据；不能把新的产品边界当作旧目录清理已经完成。
- 2026-11-08 第三方边界整改时发现旧删除接口会把引用任务的 profileId 清空，存在转用本机认证的风险；已在清理方案落地前阻止第三方旧配置删除。界面只读显示停用状态和密钥保留说明，自动测试确认删除请求不解密或删除旧密钥。具体清理与恢复规则尚未实现，状态不关闭。
