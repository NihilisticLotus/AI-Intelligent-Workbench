# ISSUE-0125：连续交接后原生切回，较早分隔条缺少切回按钮

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | bug |
| 严重程度 | 中 |

| 关闭 | 2026-11-18 |

## 现象

从第三段会话原生切回第二段后，网页不能继续切回第一段。

## 复现步骤

1. 同一任务先后交接两次，再从最后一次交接原生切回。
2. 展开第一次交接。后端允许继续切回，网页按最后一条交接事件隐藏按钮。

## 影响

一次交接后切回可用，连续切回在第二次操作时缺少入口。

## 根因

原生恢复不会产生新的交接事件。后端读取最后一条仍处于已发送状态的记录，网页一直使用最后收到的交接事件。

## 处理方式

分隔条读取 Gateway 对当前交接记录的判断。

## 验证

见时间线和本轮验收。

## 时间线

- 2026-11-18 开启，收尾检查发现前后端判定不一致。
- 2026-11-18 修复。新建离线任务连续交接两次，旧实现没有传回当前记录标志，回归失败；修复后两个原生恢复及三次接口状态核对通过。17890 的日间与夜间各操作两次切回，独立 Agent 先原生恢复，然后回到演示 Agent。见 [阶段 7 验收](../acceptance/step-1.6.md)。
