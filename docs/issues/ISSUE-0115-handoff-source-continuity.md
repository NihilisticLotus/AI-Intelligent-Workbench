# ISSUE-0115：不能原生恢复的来源会话在交接失败后丢失运行状态

| 项 | 值 |
|---|---|
| 状态 | fixed |
| 类型 | 验收未通过 |
| 严重程度 | 高 |
| 发现于 | [1.6 阶段 4](../acceptance/step-1.6.md) |
| 开启 | 2026-11-18 |
| 关闭 | 2026-11-18 |

## 现象

目标首轮失败后，任务显示原 Agent，历史消息也在。原 Agent 再次收到用户消息时，把它当成新会话的第一轮。

## 复现步骤

1. 在临时项目用两个演示适配器，来源沿用内置演示 Agent 的原生恢复能力，记录每个连接上的回合数。
2. 向来源发送一轮，再向目标发送交接；目标首轮直接返回失败。
3. 确认交接记录已标失败、任务恢复为原 Agent，再向来源发送“继续上一轮”。比较来源两次接收消息时的回合数。

## 影响

用户仍能查看会话历史，却不能接着使用进程内的原状态。没有发生真实模型调用。

## 根因

第 12.9 节要求在目标启动前结束原进程，同时要求任一步失败时原会话保持可用。对于明确不支持原生恢复的来源，原进程结束就无法保留这部分状态。任务表改回原 Agent 无法恢复它。

## 处理方式

针对不支持原生恢复且原会话仍在线的来源，临时保留空闲进程或在下次发送时用交接材料重新建立会话，两者影响不同。详见验收记录。

## 验证

默认离线回归用例失败。实际回合计数为 1、1，续用同一会话的预期为 1、2。已验证能原生恢复的演示来源按指定会话标识成功切回。

## 时间线

- 2026-11-18 开启，已记录等待用户决定。
- 2026-11-18 用户选定 A：无原生恢复能力时保留空闲来源，待目标首轮结果再释放或接回。
- 2026-11-18 关闭。目标失败后原会话回合为 1、2 且连接未关闭；成功后来源仅关闭一次。定向用例和阶段 4 全仓验收均通过。
